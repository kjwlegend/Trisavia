# 行为卡与设计覆盖

用于复杂新行为或跨模块扩展时补遗漏；小修改只查受影响项。不是要求每个行为都拥有货币、图片、NPC 或模型。

## 行为卡模板

| 字段 | 应交付的内容 |
| --- | --- |
| 居民意图／结果 | 一句自然语言；结束时什么事实改变，结果下一步如何使用 |
| 稳定 ID／版本／范围 | 逻辑动作与当前是否启用；不要用可改文案作主键 |
| 地点／执行者 | 场所层级、区域、接近点／station、参与者、是否远程可执行 |
| 前置条件 | 当前权限、工具、材料、钱、体力、关系、名额、开放状态 |
| 输入与授权 | 明确目标／数量／实例或合法输出引用、最高成本、期限；谁决定 |
| 时间／过程 | UTC 或明确世界时钟；开始、有效在场、结束、持续／瞬时；是否随机 |
| 资源账 | 何时预留／扣除／释放、确定或随机收益、重试是否可能多发 |
| 正常结果 | 来源事实、资产／关系／状态变动、空结果／部分完成 |
| 异常与取消 | 主动取消、系统失败、撤权、超时、重启、缺资源、双方冲突 |
| 规划衔接 | 单动作／有限计划；身体占用、远程等待、下一步是否需要判断 |
| 机器入口 | 实际能力发现、输入／输出、当前选项、错误、同次回执查询 |
| 可见性 | 本人、主人、其他居民、NPC、平台的字段级许可 |
| 表现资源 | 地图／站位、图标、物品图、动画、音效、文案及 fallback |
| 日志／反馈 | 哪个业务节点入日记，哪部分只在当前卡；声明与事实分开 |
| 验收／所有者 | 正常完整路径和针对风险的失败路径，原 WS 与交付者 |

不适用项写清原因。例如听免费街头演出可以没有物品奖励，不要为填满“产出”一栏发一枚毫无用途的代币。

## 跨模块检查

| 维度 | 容易遗漏的实质问题 |
| --- | --- |
| 行为组合 | 上一步的结果是否真能作为下一步合法输入？工具／钱从哪里开始获得？ |
| NPC | 若有服务职责，离岗后服务是否可用、如何准确描述？是否共用资源规则？ |
| 地图 | 图上有门不等于有室内；付费活动是否真可达？钓位／座位是否堵唯一通道？ |
| 物品 | 定义与实例分开了吗？被预留的物能否又卖一次？鱼／食品／券是否混同？ |
| 美术 | 是否有稳定映射、真实图片／动画产物、比例与遮挡合同？是否把规格误报为资产完成？ |
| 经济 | 奖励是否新发行？谁支付？价格变更如何影响已有授权？随机期望是否写成保证收益？ |
| 时间 | 离线后是否错误补演过去活动？旧活动能否恢复？客户端时钟是否能刷工时？ |
| 并发 | 两人抢最后席位、同物同时卖送、完成与取消竞争，分别由谁裁决？ |
| 计划 | 是否有无限循环／自动扩预算？等待另一人是否锁死身体？已完成效果取消时是否被抹掉？ |
| 反馈 | 正常无收获是否误记故障？受理是否误记完成？评价是否冒充理解或同意？ |
| 日志 | 同一结果是否多来源重复？先筛选权限还是先截 10 条？新主人能否看到旧私密历史？ |
| 发现／UI | 人类可见和 Agent 可执行是否同一版本？无效按钮、未知结果、失联和跨角色切换是否准确？ |
| 交付 | 是设计、素材、源码、本地运行还是公网已发布？责任／授权／依赖有没有混写？ |

## 用一个不同活动检查方法是否可复用

可选走读“参加一场街头演出”，不要照抄钓鱼参数：

- 意图：获得一段共同娱乐经历；场所为广场演出区，固定节目有真实可用音频或文字内容。
- 音频需明确来源和可播放许可；听众不开声音也有可读状态。不是必须调用生成模型。
- 如需门票，先定义售票／入场／退款与演出取消；免费版可完全没有钱包改动。
- 外部 Agent 可提交“到场并停留到演出结束”的有界计划，主办方取消／席位满有清楚结果。
- 不因同场而成为好友，不因播放完成认定听众喜欢或理解音乐；主观评价另有作者。
- 日志只记有根据的参加／中止；主人和他人公开范围沿原授权；不把 NPC 观众人数写成真实用户投票。
- 技术／美术需实际场所、节目时间、表演者表现、入场／进行中／取消／结果状态；没有新物品也不强加物品图。

这个走读用来检查遗漏，不预先批准开发演出功能。真正需求不同就换例子，保留行为优先的方法。
