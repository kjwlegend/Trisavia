# M1 主人登录与备份恢复修订

日期：2026-10-16。本批 A 基准为 `f6804c1bb0bbd195dff0a54455422f87bf79a3ad`，在 `codex/m1-owner-experience` / `m1-integration` 隔离实现。本文为作者交付事实，独立代码审查、设计完整复验及正式部署另记录结果；未因已有 M1 或域名 PASS 推定本批通过。B 城镇首页继续在独立 worktree 实施，不在本批范围。

## 用户能完成的流程

默认只显示编号与密码登录，忘记密码后直接选择登录备份；网页检查文件来源、实际能力及所属主人，再引导设置新密码、下载新备份、确认保存和提交。首次设置同样分开设置密码与保存备份。已登录进入「我的 Agent」，管理记录、运行访问及邀请收进「管理与安全」。

旧下载文件可能同时含过时的首次设置记录、过期网页登录会话和仍有效的独立恢复材料。页面先读取原操作结果；结果不能读回时，只读确认独立恢复权限，再继续同一主人的找回流程。恢复权限不由 Agent 身份文件、初始交接或公开编号替代。文件只有有效管理会话时，明确说明不能重设密码，并让人主动选择继续管理。

原 IP 与域名仍共用同一服务和身份。文件的 `origin` 必须精确匹配：域名页选到原 IP 备份时，不发送认证请求，显示固定原入口；不修改文件来源或转发秘密。原 IP 找回成功后，可使用原管理编号和新密码登录域名。生产用户文件及真实账号未用于本批作者测试。

## 安全与接入实现

- 新增 `GET /v1/owner/recovery`，复用现有 `owner_recovery` 的状态、代次和实例校验，只返回实际 `ownerId` 与可用状态。不创建会话、不消费证明、不改密码，真正恢复仍在提交事务内重新校验。
- 选择文件时先在浏览器判断格式、大小、来源、完整命令键和能力。读回认证结果或核对恢复能力时，均检查实际主人与文件编号一致。旧文件本身不修改；必要的旧进度另保留在当前标签页私密存储。
- 对首次明确拒绝的登录，释放当前表单并提示编号或密码错误。未知请求结果继续保留原操作号、scope、action 和已预存下一代证明，先自动查结果；需要时只沿用同次请求。刷新后不保存明文密码，要求重新输入；恢复备份可携带可选 `sourceRecoveryToken` 继续尚未完成的原请求，兼容既有文件。
- 结果未知时可下载进度文件、明确确认保存后退出；普通退出只清当前网页会话，不退出世界或撤销 Agent。存储及下载材料始终是私密能力，不进入 URL、公开资料或测试附件。
- 官网复制提示词与 Agent 说明统一为标准 HTTPS API 优先。Node 24 只用于可选 TypeScript 参考客户端；HTTP 宿主仍须安全随机生成、可靠保存和复读秘密、私密交付及原操作续接。参考客户端 `status` 会续接待提交写入，严格只读检查应使用 `GET /v1/agent/self`。
