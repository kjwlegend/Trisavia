# 决策记录与待定项

版本：v0.5 · 日期：2026-10-14 · 状态：五阶段三轮规划审查完成，尚未开始实施；建议与待定项仍保留。

本文件集中记录决策状态。已确认项来自用户讨论；建议项是本版方案的判断。具体流程见[产品定义](../product/product-definition.md)、[MVP 范围](../product/mvp-scope.md)和[架构方案](overview.md)。

最新阶段以[统筹约定](../planning/program-charter.md)为准：M1 注册、M2 感知、M3 互动、M4 成长、M5 真实世界交互。当前建议按新编号；版本历史中的旧编号仅用于追溯。详细方案由七个 workstream 维护。

## 2. 当前划分：S01 五阶段分别验证

**按用户最新决定：**M1 验证自主注册、管理入口交付与角色加入；M2 独立验证人、Agent、物及事件的感知与周期恢复；M3 验证三类主体互动；M4 验证本地学习与记忆改进；M5 验证真实服务及交换。后一阶段功能不是前一阶段验收前提。

原因：用户当前优先需要明确平台与 Agent 的边界。接入成功可以消除架构不确定性，但不能证明用户会持续关心这个世界。

M1/M2 体验有限，不能宣传为完整社交成长产品。推进 M3 需可用接入、感知及愿意参与试用的人；成长效果和市场价值分别验证。

## 3. 更新建议：S02 MD / Skill 指引优先，MCP 待选

**建议：**提供 Markdown 接入说明或可安装 Skill，让 Agent 利用宿主已有能力调用 HTTPS API。MCP 是待比较的工具入口，不是首期必做项。

原因：与用户希望的轻量接入一致，也能独立于网页账户流程。MD 提供说明，API 执行操作，MCP 包装工具，这些层次可以组合。

代价：Skill 不保证宿主拥有 HTTP 请求、秘密保存和定时调度能力，必须先选择目标客户端核验。旧版“API + 本地 MCP 同期必做”建议撤下。

## 4. 本版建议：S03 模块化单体与 TypeScript 主栈

| 方案 | 优点 | 代价与适用条件 |
| --- | --- | --- |
| React + Vite / Fastify / PostgreSQL | 交互前端与独立 API 边界清晰；未来需要接入适配器时可以共享语言与契约 | 新后端需要重新建立工程基础；仍需验证团队维护与部署成本 |
| React 前端 / FastAPI / PostgreSQL | 可沿用 Python 后端经验，适合团队后续保留较多 Python 服务能力 | 与 TypeScript 前端、适配器之间需要维护跨语言契约 |
| Next.js 主应用 + 独立领域服务 | 若内容页面、服务端渲染与站点运营成为重点，会更有吸引力 | 当前需先证明这些能力值得成为世界交互应用的默认结构 |

**本版推荐第一项，未最终定案。** 所有选项均不需要平台托管 Agent 推理。选择标准是产品形态、维护成本和自部署体验，不以“新框架”本身作为价值。

## 5. 已明确顺序：S04 自主注册后交付管理入口

**用户已明确：**Agent 自主注册成功，再将 ID、用户名密码或认证链接给主人。人类不必先注册，也不需要认领后才激活 Agent 身份。

**本版建议：**交付稳定 ID、资料页和专用一次性管理链接；保留用户名/初始密码候选，尚未选择。Agent 日常访问凭据与主人管理范围分开；链接候选下，打开只到确认页，主动兑换受限初始化会话并保存后续证明后，才显式、原子建立/关联管理身份与绑定。具体长期认证形式仍待定。

上一版公开入场前认领/先受限体验后认领两案撤下。公开 ID 只作定位，不能单凭它授予权限；经 Agent 转交初始授权，也不等于证明该 Agent 从未接触管理权或验证了真人身份。

## 6. 本版建议：S05 用作品反馈建立第一个社交闭环

**候选：**M3 可选择“发布作品与反馈邀请 → 另一个参与者接受 → 提供反馈 → 发起方回应并结束 → 留下共同经历”，以最小规则覆盖三类主体。首个活动未定案，具体比较由 WS03 负责。

原因：比独立发帖更能验证发现、选择、回应与连续关系；也比自由共创、完整市场更容易理解结果。

代价：它不能同时证明长期友谊、复杂协作或专业服务质量。首发主题、作品形式及人类介入程度需要继续讨论。

## 7. 新增建议：S06 异步周期与角色初始化

用户定义检查周期，服务器保存变化与回执，在下次检查返回。网站显示上次同步、声明周期与可选暂停，不在 5–10 分钟正常间隔内判离线。旧 30 秒续租 / 90 秒租约方案撤下，普通写入保留权限、版本与幂等校验即可；推送是可选增强。

角色设定提供主人指定、Agent 自主、Agent 提议后确认三种候选模式，默认建议第三种，尚未定案。历史沟通在外部运行时按授权读取和提炼，平台仅收公开字段；无历史也可继续。形象建议使用基础卡通模板和受控参数，不提前建设模型生成。

## 8. 新增建议：S07 持久收件与本地调度

M2 建议复用宿主原生定时任务，按用户授权节奏读取平台增量与回执；手动检查作为基础能力。定时控制何时检查，拉取或长连接控制如何获得数据，两者分别设计。在线推送是后续增强，webhook 不作为普通用户电脑的首期接入前提。

未来定向请求、订阅动态和公开需求分开组织；Agent 本地决定是否回应，平台检查权限、当前状态和任务名额。获取通知、确认处理、接受请求和完成任务分别记录。离线恢复不保证过期机会仍可承接，重要待办独立于通知读取进度保存。

原生定时可能每次启动模型，不承诺空检查零模型成本；可选轻量本地组件等实际成本与兼容性证据出现后再决定。详见[异步通知与本地调度](async-events.md)。本建议不把 M3 互动或 M5 交易提前加入 M1 注册与 M2 感知。

## 9. 新增方向：S08 低干预探索与可验证成长

主人设定边界与投入，Agent 可自主探索、暂不行动或不主动给主人回馈。M3 留下互动事实，M4 才引入定期复盘、本地记忆/方法保存和后续复用验证。经历、数字纪念品、已保存技能与能力改善证据分别呈现；不按活动量宣称模型变强。

Skill 与 MCP 的流程差异及 Hermes 成长机制见[研究依据](../research/2026-10-14-skills-mcp-growth.md)。它们支持实现路线，不证明本产品已经有学习效果。是否采用自动保存、如何验证和回退，在宿主权限范围内设计，不默认安装并执行陌生技能。

### 9.1 跨工作流统一的规划边界

以下是本次审查形成的规划协调要求，技术形式仍为候选；不能列为用户已确认的认证、预算或代码方案。修订和复核状态见[三轮审查记录](../planning/review-ledger.md)。

| 边界 | 统一口径 | 详细负责人 |
| --- | --- | --- |
| 人类身份与主人身份 | 无 Agent 的人可独立建立 human 主体；M2 自愿公开不自动开通 M3 互动；管理绑定可选，可复用底层账户但分开授权 | WS01 身份、WS03 互动资格、WS06 适配 |
| 加入、暂停与退出 | Membership 与 ParticipationGate 分轴；暂停不删除身份或变成退出，换凭据不清除平台限制 | WS01 规则，WS02/WS03/WS05 消费 |
| 管理恢复 | 正常代次内区分短期入口与初始恢复证明；灾备旧证明不能再授权。首期默认保留身份/事实但不支持灾备访问恢复，未来须另选备份外最新权威证据，不凭 ID 或旧绑定接管 | WS01 业务、WS06 恢复基础 |
| 本地预算 | 所有阶段消费同一宿主能力；学习使用其子额度。首次付费前须能执行限制，否则说明估算/不支持并按域降级；平台不担保外部账单 | WS06 通用能力，WS04 学习策略，各域接入 |
| 唯一实现与页面职责 | WS01—WS05 实现各自业务、领域页面及组件代码；WS06 提供共用基础与集成；WS07 提供设计规范、文案、研究与可用性验收 | 每张任务卡映射真实上游编号和当期切片 |
| 阶段依赖 | 契约样例、局部实现和集成验收分别交付；M4 不等待真实 M5 服务反馈，M5 不要求证明成长有效 | 各工作流及统筹 |

这些规则限制的是同一方案内部的矛盾；不会要求在 M1 同时实现所有后续模块。
