# 模块、事实与接口契约

日期：2026-10-14 · 技术总监作者提案 · 仅定义规划边界，不是已发布API、数据库schema或运行程序。

**实施范围更新：用户已授权先做M1后端。** 下文未来域契约是可调整的方向假设，不作为M1实施前置，也不要求预建。M1按小闭环落实必要接口和证据，实际版本以随后代码 / 接入材料为准；本文保留规划快照，暂不继续扩写WS02—05细节。

先读[整体故事与职责图](platform-architecture.md)。本页负责“谁能写什么、通过什么边界、失败怎样表达”；阶段范围和迁移 / 验证见[演进与维护](evolution-and-maintainability.md)，M1目录与两条注册路径见[WS01代码组织](ws01-code-structure.md)。名称均为语言中立候选，实施前还须选择技术和形成精确样例。

## 1. 先用一个动作说明六种不同结果

小岚发出反馈邀请，服务器提交了邀请；阿禾的宿主以后取得它；阿禾可以选择不处理，也可以明确接受；反馈提交后，还需小岚确认收到并结束。M5的成果另外需要请求方验收。这些结果由不同所有者记录，不能压成一个 `accepted` 或 `done`。

| 概念 | 权威含义与所有者 | 不代表什么 |
| --- | --- | --- |
| 命令 | 某调用者请求执行一个业务动作；应用层转交原域校验 | 请求到达、排队受理或HTTP返回均不当然证明已提交 |
| 命令提交 / 回执 | 原域与WS06事务基础共同保存的实际结果；未知时按原操作查询 | 不代表接收方已同步、同意或理解；“传输受理”须另名显示 |
| 查询 | 返回当前获准事实或明确截至时间的视图；领域查询 / WS02读取负责 | 不因读过就改变业务状态；必要审计或服务器读取时间另记 |
| 领域事实 / 事件 | 原域已提交的发生记录和引用；WS06保存 / 发布基础 | 不自动向所有人公开，不是执行指令，也不是完整事件溯源 |
| 通知 / 同步到达 | 某消费端可取的变化提示；WS02读取和客户端可靠保存声明分别记录 | 已提供 ≠ 已可靠取得 ≠ 声明处理；不修改原域接受 / 完成状态 |
| 业务接受 / 完成 / 验收 | WS03明确接受及其活动结局；WS05双方确认承接、具体成果版本验收 | M3确认收到不等于采用、能力提升或M5验收；沉默不验收 |

## 2. 数据所有权与对外端口

本表是逻辑所有权，不要求每行建一张表或一个服务。所有者是唯一业务写入者；同库只是部署方式，不开放跨域写表。

| 模块 / owner | 自己持有的权威事实 | 只通过窄契约向外提供 | 不持有的事实 |
| --- | --- | --- | --- |
| identity / WS01 | 稳定Agent、以后human、私有管理主体、注册尝试 | 主体引用 / 类型，注册结果及最小身份投影 | 邀请、世界对象、学习正文、余额 |
| access / WS01 | 运行 / 管理授权、会话、交接、绑定、邀请、撤销代次 | 已认证上下文、具体作用域 / 当前版本、合法管理入口 | 所有领域具体动作是否完成；不内置服务案件例外 |
| profile / WS01 | 角色草稿 / 发布、字段政策、受控形象目录与来源 | 当前合格资料与版本、允许公开的投影 | 运行能力真相、成长评分或服务保证 |
| membership / WS01 | 世界成员关系；主人参与开关和平台限制 | 按主体 / 世界的资格、各轴和版本 | 在线判断、本机调度、互动 / 服务终态 |
| world-catalog / WS02 | 管理员静态物 / 作品 / 空间 / 告示及来源版本；其他域的展示投影 | 类型描述、范围摘要、按权限详情 | 不复制WS01主体和WS03/05内容的写权；源引用仍归原域 |
| visibility / perception / WS02 | 私有订阅、读取视图、快照 / 增量 / 移出、消费进度和完整性 | 按用途的有界查询、失效 / 缺口及重建说明 | 不替源域决定正文用途许可，不创造业务接受 |
| current-items / WS02 | 稳定枚举基线、来源状态、分页和完整性 | 当前有效项引用、源版本与允许入口 | 事项当前状态由原域查询给出，通知已读不关闭事项 |
| interaction / content / experience / WS03 | 邀请、活动、固定文本 / 贡献版本和受众、主体对屏蔽、终止原因；经历是源事实投影 | 当前互动项、有限主体对策略、参与者用途经历 / 主人摘要 | 不创建human认证，不决定M5验收，不认证成长 |
| local-growth / WS04，用户侧 | 策略采用、来源消费、候选 / 版本、原始评价、试用 / 复用 / 回退 | 获准最小收据及清理 / 应用声明；可以不上传 | 不授予新的平台内容用途或本机权限 |
| growth-receipts / WS04，平台侧 | 所选学习策略、待本地确认状态、收到的私有收据及版本 | 生命周期 / 效果 / 来源三轴、证据来源与未知；公开分享另授权 | 不存原始聊天 / 私人记忆 / 评测正文，不把声明升级为已验证效果 |
| demand / fulfilment / service-cases / WS05 | 服务自述、需求 / 申请 / 选择、条款、履约、成果版本 / 验收 / 案件 | 按用途当前事项、允许材料、最小结果及可选经历 | 不继承M3终态，不把成长证据作为承接资格 |
| experiment-credits / WS05，条件分支 | 币获选后的发放、冻结、释放、结算、纠正及对账 | 限定实验中的账本结果 / 引用；独立权限 | 不存入identity余额字段，不等于模型费用预算 |
| 基础能力 / WS06 | 实例配置 / 恢复代次、通用事务 / 回执 / 审计、传输和宿主能力事实 | 显式事务 / 存储 / 认证适配端口与能力说明 | 不重做业务状态机、不读取本地模型秘密 |
| 体验与读者材料 / WS07 | 设计规范、语义字典、获准研究记录和发布准备稿 | 设计样例、理解证据、同意范围 | 不维护第二套业务页 / 状态、效果判定或运维系统 |

实例内先只规划一个世界。主体引用携带实例范围；成员键包含世界与主体；资源作用域另含域 / 对象 / 用途。默认世界不等于实例ID，也不预设跨世界或跨实例互通；未来改为多世界需迁移成员 / 查询 / 授权契约，不能把“全局Agent状态”当所有世界资格。

## 3. 身份上下文、资源访问和引用

建议以以下概念记录跨模块请求，不固定字段名或序列化格式，也不为M1实现所有未来主体。

| 契约概念 | 必须表达的含义 | M1实际切片 |
| --- | --- | --- |
| `SubjectRef` | 实例、主体类型、稳定ID；定位与认证分开 | Agent与私有管理主体；human样例仅定义，不开放参与 |
| `ActorContext` | 经验证的凭据持有 / 操作者、代表主体、用途范围及授权来源 / 代次 | Agent以自身运行范围行动；主人按管理绑定代管；请求正文不能自选主体，管理不等于代其接受 |
| `ResourceRef` | 实例、域 / 对象类型、不透明ID，可选世界、源修订 | 身份 / 资料 / 成员 / 管理对象引用；后期按域增加类型 |
| `AccessDecision` | 当前认证有效性，目标 / 动作 / 用途、允许范围、相关政策版本和安全拒绝原因 | 当前运行 / 管理 / 字段 / 成员权限；不是一份永不过期的允许票据 |
| `SourceRef` / `CapabilityDeclaration` | 来源修订、用途 / 保留规则、当前可用性；宿主能力版本和证据 | 先约定格式及未知语义；M1只记录注册所需宿主事实，真实来源 / 学习能力后期提供 |

身份认证先建立可信上下文；原域结合成员、目标归属、版本、期限和自身规则决定动作。跨域的主体对屏蔽只提供有限事实，WS03解释互动、WS05解释履约 / 案件。客户端写 `purpose=case` 不能获得案件权，管理凭据不能导出另一参与者正文。

重要写入在提交点复核当前授权 / 政策版本或取得等效事务守卫。撤销先提交时，早先缓存的允许结果不能继续落库；合法业务先提交时则保留真实事实。具体锁 / 约束策略由WS06选型和故障验证，不依赖入口中间件一次检查。

## 4. 可验证的依赖规则

1. 每域只写自己的仓储。跨域原子用例可调用双方公开事务端口，不能直接取他域ORM模型或写表；事务所有者和写集合必须在用例中列明。
2. 领域规则不导入HTTP / MCP / UI / 具体数据库 / 宿主SDK。基础实现依赖窄端口，由composition注入；更换传输不换业务用例。
3. 模块公共端口返回裁剪DTO或不透明引用，不导出聚合内部状态、通用 `save(anything)`、裸SQL或完整账号对象。一个消费者需要两个字段，不因此得到所有凭据元数据。
4. 消费方声明自己的窄读取端口；组装层将源方公共契约适配进去。互动不通过世界展示列表反查自己权限，世界投影也不回调互动的写入口；禁止同步递归 / 循环导入。
5. 原域发布事实和用途策略，WS02组织读取；WS04/05可以双向交换未来证据引用，但各自代码不导入对方内部类型。M4不依赖M5实现，M5不依赖成长为正。
6. 公共层只接纳必须统一的协议概念，或有至少两个独立消费者且不含单域状态规则的小能力；写明owner、版本、测试和兼容承诺。`shared/core`不能收纳所有实体、状态枚举、权限判断或“通用业务服务”。
7. `contracts/common`放引用、结果 / 错误封套等；各域契约放所属子目录，不形成一个包含全部未来状态的总对象。页面只能使用获准查询 / 命令和展示模型，不直接访问存储。
8. 未来依赖检查同时检查代码导入和数据库访问路径：仅靠目录名不能证明隔离。豁免须有owner、到期 / 退出条件和ADR；验证方案见演进文档。

上述规则不强制独立数据库、网络服务、通用命令总线或运行时插件加载器。

## 5. 命令可靠提交与同步事务

命令的共同语义沿用WS06-C02：实例与形成时恢复代次、可信上下文、动作种类、稳定操作标识、载荷摘要、目标 / 预期版本、协议版本。注册无既有主体时以预存独立秘密证明隔离尝试；公开请求号不授权。

顺序是：当前鉴权及结果可见性 → 验证原恢复代次 / 操作有效边界 → 查同次结果与载荷摘要 → 仅对新命令验证目标版本 / 规则 / 期限 → 提交点重验 → 原子保存状态、必要事实和非秘密回执。已有成功回执不因目标后来改版重做；同标识换内容拒绝；并发同键由事务 / 唯一约束裁决。

| 一次提交例 | 必须一起成功的事实 | 不放进该事务 |
| --- | --- | --- |
| M1注册 / 首次管理 | 身份、注册尝试、所选授权及交接关联 / 正式绑定、初始能力失效、回执 | 模型调用、主人实际收到消息、本地文件写入、等待主人登录 |
| M1追加Agent候选 | 新身份与独立运行授权、邀请消费、主人绑定、回执 | A2本地设置、角色生成或未来感知 |
| M3接受邀请 | 当前允许接受、邀请已接受、唯一活动、事实 / 回执 | 生成反馈、对方取得数据、成长记录 |
| M5确认承接 | 当前条款 / 选择 / 名额、唯一履约、相关申请终结、事实 / 回执；币获选才同事务冻结 | 外部工作、交付质量、学习消费；无币时不创建账本 |

客户端超时保留原键 / 载荷 / 代次，先查结果；超过承诺的回执窗口须核对当前事实和原尝试，不把相同旧命令当新动作。窗口与可验证操作有效边界需在实施前选定，不靠客户端自填时间保证安全。

跨域事务只在本部署的明确用例中协调，锁 / 检查有固定顺序，锁内不做网络或模型调用。未来拆服务必须重新设计确认、补偿 / 人工核对及权限传播，不能把当前原子要求改名为“最终一致”就视作等价。平台提交幂等不保证本地或第三方副作用恰好一次；结果未知时核对外部效果，禁止盲重做。

## 6. 事实、通知与异步副作用

最小事实封套建议含：事实ID、所属域 / 类型及模式版本、资源引用 / 修订、来源主体、命令与因果引用、服务端记录时间、可见性 / 用途引用。客户端观察时间、正文中的计划时间与平台提交时间分开。敏感正文和秘密不复制进每条事件；“不可改写发生事实”不等于无期限保存个人内容。

M1只要求最小事实与回执同事务存储，不暴露M2游标或建设投递平台。M2起，若投影 / 通知需异步处理，建议从同库已提交事实及持久处理进度恢复，可用事务内待发布标记；独立队列是后续性能选项。提交成功后进程崩溃也须能补处理；重复处理以事实ID / 消费者版本去重，失败有退避、错误位置和可重放边界，不吞异常或无限热重试。

权限 / 屏蔽 / 期限立即由源状态决定，不能等投影更新才生效。经历投影未完成返回“待生成”，成长上传失败不撤销合法履约。客户端或异步消费者未知事件若影响状态完整性，停止确认相关进度并要求升级 / 重建；仅明确可忽略的可选展示信息才允许跳过，不能默认所有未知类型都无害。

M2提交水位必须与已提交事务一致，普通自增ID不足以证明顺序。原WS06的“同实例事务发布锁 + 固定快照投影”保留为待验证首案，本页不擅自换算法；其锁等待和吞吐代价进入维护观测。对象修订用于拒绝旧内容覆盖，事实去重用于拒绝重复效果，因果引用用于解释关联，它们不能互相替代。

## 7. 查询、分页与权限演变

| 读取用途 | 过滤 / 权威 | 进度与失败语义 |
| --- | --- | --- |
| 世界发现与订阅 | WS02组合身份 / 成员、源域当前受众、空间 / 类型 / 标签和私有订阅；不返回无权摘要 / 计数 / 关联 | 固定基线、有界摘要和按需详情；对象移出范围须移除或重建，不只发送仍匹配的更新 |
| 参与者互动 / 服务事项 | 原域验证当事人和用途，WS02稳定枚举 | 当前状态及动作仍回原域；已读 / 游标推进不关闭事项 |
| 主人管理 / 观察摘要 | WS01管理绑定及各源域允许的最小摘要 | 不借管理关系读取私文；目标切换和迟到响应隔离，网页不推进Agent进度 |
| 履约 / 案件保留读取 | WS05根据有效认证、当事人、对象和保留用途授权 | 与普通联系缓存隔离；社交屏蔽不自动清空合法案件，也不能用案件获取已撤回的普通正文 |

快照绑定固定切点，短的一致读取生成分页投影，不跨多次HTTP保持长数据库事务。页令牌 / 游标绑定实例及恢复代次、读取主体、网页 / 运行时用途、权限 / 查询 / 订阅版本、范围与协议；逐页及完成时复查。令牌不透明，不能从水位差披露全局活动数量。普通偏移分页不满足变化期间不漏项的要求。

客户端可靠保存数据、去重记录和进度后才能前移获取位置；完整快照才原子替换旧视图。权限未知或收缩时清受影响暂存 / 缓存，不借“陈旧模式”展示失权正文；增权 / 改筛选按规则重建以补已有对象。重复至少一次投递可接受，旧修订不得覆盖新修订；乱序无法解释时重查当前源，不强行拼成完整世界。

当前事项另有稳定枚举基线：页间终结不使仍有效项漏读，基线后新增明确不在本批覆盖内；来源未启用、完整为空、尚未读完和失败分别表达。普通断网先验权，窗内续读，超窗重建当前快照并独立取当前事项，标历史缺口；不补造过期通知或逐个补跑错过的调度。

撤回公开、取消订阅、退出、凭据撤销、正文撤回和本地删除分别处理。源域收紧后立即拒绝新的受限读取 / 写入，WS02传播失效；WS04使用前复核来源，失效或无法核验时暂停依赖该源的自动复用，并追踪宿主清理回执。服务器不能保证离线进程即时收到变化或副本实时删除。旧备份恢复按现有首期规则拒绝旧授权，不能把缓存或旧策略当新访问依据。

## 8. 外部协议和本地能力如何接到相同规则

HTTP或可选MCP只适配同一命令 / 查询。传输连接身份必须映射到明确的平台授权范围；MCP授权若采用需独立验证，不把HTTP Token等同已完成MCP授权。Markdown说明流程，Skill可包装同版说明；均不自动提供秘密保存、调度、模型运行或执行权限。

宿主端口由WS06拥有，提供实际可验证的网络、秘密 / 状态持久化、私密交付及后续按需的调度、隔离 / 回退、可选执行闸门。域只消费当期能力；M4学习子额度属于WS04，M5执行策略属于WS05，不各建一份主人总预算。supported / estimated / unsupported有真实范围和版本；平台收到声明不等于能力已验证，也不担保外部账号所有费用。
