### R3-P01 · P2 · M2 总览仍允许缩成一种物对象，并用测试人物替代阶段人类入口

- **状态：verified。**
- **位置：**`docs/product/mvp-scope.md` §3「最小范围与流程」第 59 行及「验收场景与证据」第 65 行；`docs/planning/roadmap.md` §2 M2 行第 20 行、§5「M2：再让它按自己的节奏感知」。对照 WS02 `plan.md` §1 第 11、15—17 行、§8「六类对象首读」及「M2 人公开、成员多轴与历史」；关联 WS01-T09@M2、WS02-T01—T04/T09/T10、WS07-T03。
- **冲突：**MVP 总览说物可以仅选作品、资源或场所中的一种，并允许四类对象各用真实或标明的测试样本完成该项验收。最新 WS02 则规划人、Agent、物品、作品、空间、事件六类投影，集成验收须有真实 human 身份及主动公开出口；WS07-T03 也以六类和人类主动公开为验收输入。四类上位分类本身没有问题，缺少其与六类最小投影的映射，以及测试样本和真实入口验收的区别，才造成范围差异。
- **具体反例：**执行者按总览只登记一件静态作品、两个 Agent、一张标注测试的人物卡与一条事件，就能声称满足“四类对象各有样本”；但仍未实现空间/物品投影，也未验证无 Agent 的 human 创建、主动公开与撤回，无法满足 WS02/WS07 的阶段退出条件。
- **修改归属：**统筹修改 MVP 总览及路线图；WS02/WS07 只需确认镜像文字，不要求扩展已有工作流。
- **建议修订：**保留“人、Agent、物及事件”的用户层分类，明确本轮提案在感知目录中展开为六类最小投影；区分局部契约/演示可用测试样本与 M2 集成须走真实 human 主动公开路径。继续标注具体目录范围为提案，不冒充用户已选定实现。
- **复核验收：**仅阅读总览的执行者也会列出与 WS02 §8 相同的最小对象覆盖；测试人物不被记为真实 human 入口验证；M1 仍不等待 M2 的人类公开流程。
- **定点复核证据：**`mvp-scope.md` §3 第 59 行已明确四类上位分类展开为六类最小投影，关联 WS01-T09@M2 的独立 human 与主动公开/撤回，并注明 M1 不等待；第 65 行把测试样本限定于局部契约/演示，集成明确要求真实 human 创建、公开及撤回。`roadmap.md` §2 第 20 行和 §5 第 63 行已镜像对象范围及真实入口要求。相邻周期/恢复条款未将测试数据升级为真实验收，也未把 M2 前置给 M1；原反例已被排除。

### R3-P02 · P2 · 产品定义的 M3 示例仍引入第三方讨论

- **状态：verified。**
- **位置：**`docs/product/product-definition.md` §5「从加入到成长的体验」M3 段第 103 行。对照 WS03 `plan.md` §1 第 10、15—18 行、§3 私文受众及 §5 正常路径；关联 WS03-T02/T04/T08、WS07-T04。

- **修改归属：**统筹修改产品定义；WS03/WS07 的双主体方案无需改变。

### R3-P03 · P2 · M4 总览把版本记录放在试用之后

- **状态：verified。**
- **位置：**`docs/product/mvp-scope.md` §5「最小范围与流程」第 98 行。对照 WS04 `plan.md` §2 第 31—38 行、§4 正常路径、WS04-T05/T06/T07/T08；关联 WS07-T05。
- **冲突：**总览给出“形成候选 → 试用或请求许可 → 记录本地版本 → 验证”的显式顺序。详细方案要求先保存不被自动加载的候选版本、前版和恢复点，再冻结协议并隔离试用；初评合格也只进入限定延迟试用，之后才能判定可复用。总览目前把保存和试用的先后写反。
- **具体反例：**使用总览编排最小流程时，先让宿主加载一个尚未登记版本的候选，试用崩溃后才进入“记录版本”步骤。这次使用的方法版本及恢复点未留下确定证据，无法按 WS04-T05/T06 验收；若把该次试用直接当日常复用，还会遗漏初评与延迟验证的边界。
- **修改归属：**统筹修改 MVP 总览；WS04/WS07 保持其现有安全顺序。
- **建议修订：**至少写成“来源/授权核对 → 候选及前版保存、可恢复 → 冻结协议并隔离试用/初评 → 合格者限定延迟试用后判断复用，负结果停用恢复”。可压缩文字，但不能把版本建立放到试用之后。
- **复核验收：**从总览按箭头执行时，第一次试用前已有候选身份、版本及恢复依据；初评结果不直接成为可复用；无改善/退步可以不进入正式复用并完成流程验收。
- **定点复核证据：**`mvp-scope.md` §5 第 98 行现按来源/用途/授权核对、惰性候选/前版/恢复点保存、协议冻结与隔离初评、限定延迟试用后判断复用排序，另明确负结果停用恢复、初评不等于可复用。第 96 行允许无新内容不总结，第 102—107 行仍区分拒绝、负结果、权限与版本证据；没有相邻条文要求先启用后留版本或强制正式复用。原反例已被排除。

## 4. 阶段独立性与价值判断

五阶段详细方案在产品层面能分别定义最小结果：M1 自身身份与交接；M2 可见事实与真实周期恢复；M3 一次双主体反馈及合法负结局；M4 本地保存/验证/恢复，效果允许为零；M5 一类无偿服务及异议收口。WS03、WS04、WS05 的局部验收与平台集成、体验复核分开，M4 不等待真实 M5，M5-A 不等待积分。未发现必须先建设完整市场、关系图谱、训练平台或常驻客户端才能完成前阶段的产品前置。

娱乐/观察、方法积累、具体任务改善和服务价值分别设证据口径。WS07 不以心跳、自动消息或币流水代替人类回访与真实需求；WS04 比较世界反馈与同一 Agent 本地复盘；WS05 比较自有 Agent/已有工具，并允许不采用、不值得外包或停止实验。上述是可执行的未来验证设计，当前没有足够数据可以宣布其中任一价值成立。

低干预方向保留：主人预授权范围内无需逐次指挥，Agent 可以拒绝、不行动、无产物或不上传；主人看最小真实事实，不因观察要求反向强制上传本地正文。开源许可证、宿主和认证形式仍是明确的未来选择，未发现将它们包装为用户已定案的新增问题。
