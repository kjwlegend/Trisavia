## 2. 实际发现

### R3-A01 · P1 · 灾备再授权仍可能把已撤销的旧证明恢复为有效

- **状态 / 归属：** verified；统筹修订，WS01 负责灾备身份恢复规则，WS06 负责恢复边界与演练；独立复核见 §5。
- **精确位置：** [WS06 plan](../../workstreams/ws06-platform/plan.md) §8 恢复旧备份段（审查时第 132 行）、WS06-T11（第 252—257 行）、WS06-A08；[WS01 plan](../../workstreams/ws01-registration/plan.md) §4.2 灾备段（第 116 行）、WS01-T04（第 245—251 行）。
- **初审时约定：** WS06 在备份外生成新的恢复/授权代次并使旧凭据失效，然后“按 WS01 独立恢复证明受控再授权”。WS01 把再授权条件交给 T04，但 T04 只列正常代次内的管理证明轮换；没有定义用于灾备的证明如何取得、如何证明仍是最新授权，以及哪份事实不受旧业务备份回退影响。恢复时新建的代次/记录，只能区分恢复前后，不能证明备份以后哪一个恢复码已被消费或撤销。
- **反例：** t0 备份中，管理恢复码 R0 有效；t1 主人已消费 R0 换为 R1，或者撤销已泄露的 R0；t2 恢复 t0 备份并换实例代次。常规登录确实拒绝旧凭据，但若灾备“独立证明”仍用备份中的 R0 校验值，持有已撤销 R0 的人就能换取新代次授权。相同问题发生于 t0 尚未绑定、t1 已绑定并废止 bootstrap、t2 恢复到 t0：旧 bootstrap 不能因为备份重新显示未绑定而再次取得主人管理权。若所有旧证明都拒绝，又没有另一个已定义的证明来源，则当前 T11 的“独立证明再授权后重放”成功分支不能执行。
- **所需最小修改：** 在 WS01-T04 的方案片与 WS06-T11 恢复契约中明确：旧备份中的管理口令、恢复码、bootstrap、绑定状态和旧授权记录，均不能单独作为新代次再授权依据。恢复时生成的新代次本身也不构成用户身份授权。再授权必须有明确的、未随该备份回退且可核验其当前有效性的授权证据；概念契约至少说明该证据的来源、与稳定主体的绑定、失效/消费判断及验证责任，不以“独立证明”四字代替。
- **可执行的最小 MVP 降级：** 若本期不建设或不具备上述备份外最新授权证据，默认保持 fail-closed：保留原身份和业务事实，但不恢复该身份访问；无常规换发、旧 bootstrap、自报身份或客服口头确认旁路，不为绕过此限制自动另建身份。将“灾备隔离成功但访问不可自助恢复”写入主人说明及 T11/A08 结果。这个降级足以闭合权限安全和旧命令隔离，但不满足“灾备后一定恢复访问”的可用性承诺；文档须明确接受这一限制。无需默认引入分布式身份平台。正常代次内的 WS01 自助恢复继续成立。
- **复核所需证据：** 文档场景至少列出“备份后消费/撤销恢复码”“备份后完成首次绑定”“仅持旧证明”“完全缺失备份外证据”。这些场景必须保持禁止再授权；若选择支持灾备访问恢复，另给一份明确有效且未回退的证据成功场景，再验证原代次的创建类/有版本命令仍拒绝。此处要求补全未来验收设计，不声称这些产品测试已运行。

### R3-A02 · P2 · 接入概览仍把首次访问写成建立绑定的时点

- **状态 / 归属：** verified；统筹维护 `architecture/agent-access.md` 及相邻摘要；WS01 确认语义；独立复核见 §5。
- **精确位置：** [agent-access](../../architecture/agent-access.md) §3.3 第 65—67 行、§3.4 第 73—75 行；对照 [WS01 plan](../../workstreams/ws01-registration/plan.md) §3 步骤 8、异常表“管理入口预览或重放 / 初始化会话丢失”、§4.2、WS01-T03 / M1-A03。
- **初审时冲突：** 概览写“可在首次访问建立管理会话及绑定记录，必要时让主人保存后续管理/恢复方式”；§3.4 又先描述成功使用后建立后续方式，再补充必须先保存。WS01 最新流程则明确普通打开只到确认页，主动兑换得到受限初始化会话，保存自己的后续证明后，才原子完成绑定并关闭全部初始能力。
- **反例：** 未来接入或页面实现若按 §3.3 将首次打开或链接预览当成绑定完成，主人尚未保存独立恢复方式时链接便被消费；退出页面或响应丢失会得到“已绑定但主人没有后续证明”的断路。若遵循 WS01 则不会发生，两份现行说明不应要求实现者自行择一。
- **所需修改：** 将 §3.3/3.4 统一为“打开确认页 → 主动兑换受限初始化会话 → 保存独立后续证明 → 原子完成绑定”。普通打开/预览不绑定；保存步骤不是“必要时”的可选项。保持链接方案为候选，不把该澄清写成用户已选认证技术。
- **复核所需证据：** 概览与 WS01-T03 对“仅打开”“初始化未完成”“完成前丢会话”“完成后丢响应”给出一致结果；未完成绑定仍可按有效 bootstrap/代次规则恢复，完成后只走主人恢复。
