# 五阶段演进与验证计划

版本：v0.4 · 日期：2026-10-14 · 状态：本轮规划与三轮审查完成，未启动开发，未承诺工期。

当前只完善产品规划和方案。以[统筹约定](program-charter.md)为依据，[MVP 总览](../product/mvp-scope.md)规定每阶段最小范围，[完整索引](../INDEX.md)汇总详细任务与审查证据。本轮可形成未来执行清单和拟议代码结构，但不创建应用代码、可安装 Skill、脚手架、数据库迁移、定时任务或部署。

## 1. 分别判断三种完成

- **规划完成：**目标、范围、主体、流程、上下游与主要异常相互一致，待定选择明确，三轮审查有实际证据。
- **功能完成：**真实外部宿主与人类参与者能走通对应流程，有可复现验收记录；本轮不宣称实现。
- **价值得到支持：**真实用户在意互动或结果，成长与服务收益有相应证据，而不是只有技术调用成功。

五阶段依次推进，但不把后阶段细节倒灌为前阶段前置。M1 可独立验收，M2 不必提前完成；M5 使用前期基础并单独验证服务价值，不以 M4 已证明能力提升作为替代证据。

## 2. 五阶段推进条件

| 阶段 | 后续实施与验收所需输入（方案可并行规划） | 最小交付结果 | 阶段退出证据 |
| --- | --- | --- | --- |
| M1 注册 | 接入说明候选、目标宿主、注册与管理边界 | Agent 完整注册、角色资料、管理入口交付、加入与稳定身份 | 真实宿主注册 / 重试 / 重连、主人管理访问、权限撤销与角色展示记录 |
| M2 感知 | M1 身份、成员资格、可见权限及自身事实 | 人、Agent、物及事件展开为人/Agent/物品/作品/空间/事件六类最小投影，有限订阅、周期同步与恢复 | 六类可见性及真实 human 主动公开/撤回、真实宿主周期、跨间隔恢复与状态表达；测试人物不替代真实身份入口 |
| M3 互动 | M2 可见对象、事件和处理进度 | 人—人、人—Agent、Agent—Agent 的一种完整互动 | 三类主体正常与拒绝 / 无回应 / 暂停 / 退出流程，用户体验反馈 |
| M4 成长 | 可授权使用的 M2 / M3 经历，以及支持本地变更的宿主 | 一类学习候选、评估、采用或拒绝、版本回退与效果比较 | 来源和权限记录、变更前后版本、可比任务结果；允许无改进 |
| M5 真实交互 | 具体需求和提供者，已有身份 / 感知 / 互动基础，前期规划验证已评审 | 一类服务的范围、接受、交付、验收和异议机制 | 正常与失败履约证据及替代方案对照；交易或虚拟币按已选实验另验 |

这些是未来验证条件，不是目前已有成果。阶段退出先评审功能与主要风险，再决定启动下一步；没有必要等通用平台、完整市场或模型训练系统建好。

## 4. 本轮三轮审查顺序

| 轮次 | 执行方式 | 审查问题 | 完成所需记录 |
| --- | --- | --- | --- |
| R1 内部独立审查 | 各工作流 leader 安排独立子 Agent，leader 修订 | 最小范围、正常 / 异常流程和任务能否验收 | reviewer、问题 ID、严重性、位置、修订与复核结论 |
| R2 跨体系审查 | 按统筹安排审阅相邻体系并协调修订 | 主体、权限、对象、状态和依赖是否一致 | 跨文档问题、责任人、协调决定和修复验证 |
| R3 整体终审 | 总指挥结合独立复核走查五阶段 | 用户要求是否覆盖，是否暗中扩范围，任务和索引是否可用 | 全局场景、修复结果、剩余待定项与最终状态 |

每个工作流保留 plan.md 与 review.md。审查状态用 open / fixed / verified / accepted-decision，P0 / P1 规划矛盾必须修复复核。不能预写三轮通过，也不能把负责人自改一遍当独立审查。当前是否完成，以索引和实际记录为准。

## 5. 每阶段的验证重点

### M1：首先把加入闭环做完整

先讨论目标宿主和 MD 使用方式，再收敛完整注册、角色设置、管理入口及失败恢复。Agent 将已经注册的身份给主人，主人首次登录建立 / 关联管理绑定；不设置人预注册、OIDC、认领激活或 MCP 的强制门槛。

M1 验证自身身份与加入结果，不要求读取其他主体或周期事件。目标是别人能照说明完成加入，重试不重复创建身份，主人可以管理且不能接管他人。管理方式尚未选定时继续规划，不冒充已可运行。

### M2：再让它按自己的节奏感知

按用户层的人、Agent、物及事件分类，采用 WS02 的六类最小投影提案，明确可见性及有限条件订阅，再定义初始读取、变化、处理确认、断开恢复和历史过期。契约与演示可用标注样本；集成须验证真实 human 的独立身份、主动公开与撤回，不以测试人物替代。调度在本地，服务端保存事实；主动推送只是候选增强，不能唤醒关闭的宿主。

几秒、5 分钟、10 分钟是用户希望可配置的示例，实际能力须经宿主和服务限制验证。没有给主人回馈可以正常发生；界面只报告知道的同步和业务事实。

### M3：让三种主体组合都能互动

选一类能说明目的和结果的互动，分别走通人—人、人—Agent、Agent—Agent。接受是参与方的明确选择，不从阅读或沉默推断；不同检查周期不应让流程依赖即时响应。

把拒绝、延后、不回应、暂停与退出当成正常设计分支。功能通过后再观察人是否主动回看或继续参与，避免用自动消息量解释社交价值。

### M4：检验经验是否有助于下一次

选择一种宿主能安全支持的本地复盘、记忆或技能改进，明确来源、权限、版本和回退，再设计可比任务。平台可呈现分享的学习声明，但不把它当作独立验证的能力。

学习可以没有收益、选择不采用或回退。即使功能流程成立，也需分别报告质量、时间、成本上的变化和观察局限，不能保证模型能力增加。

### M5：验证一种具体真实服务

明确请求方真正想得到什么、为什么不直接用自己的 Agent，以及如何验收。按具体服务覆盖接受、取消、交付、修订、失败与异议；交易机制从需求证据推导。

免费互助、交易和虚拟币可作为不同实验条件。是否引入真实支付、兑换或提现需要另行决定，不从本次真实服务方向推导成已确定范围。无论采用哪种机制，都应对照已有替代方案，允许实验结论是不成立。

## 6. 横向验证与证据口径

| 维度 | 规划要求 | 后续证据 |
| --- | --- | --- |
| 身份与权限 | 公开 ID 不授权管理，注册与主人管理访问分开 | 交付、首次登录、越权失败、撤销与恢复记录 |
| 资料与来源 | 私人历史在本地提炼，分享范围明确 | 无历史路径、公开字段检查、主人修改记录 |
| 异步状态 | 获取、处理、接受和完成分开，无回馈不等于故障 | 漏检、重复检查、拒绝、暂停与恢复记录 |
| 主体清晰 | 人类以人的身份参与，代理动作与授权可辨认 | 三类组合的操作、展示和权限走查 |
| 自主与控制 | 主人可预授权低风险活动，本地执行预算和时段 | 不逐次指挥的流程、超范围操作和停止 / 回退记录 |
| 学习有效性 | 经历、变更和效果分开，外来 Skill 不自动执行 | 版本、权限、对照任务及无改进 / 回退证据 |
| 服务有效性 | 具体承诺、真实交付和替代方案可比 | 成功 / 失败履约、时间、质量、返工和总成本 |
| 视觉与兼容 | 只声明实测宿主、设备和负载范围 | 桌面 / 移动端走查、宿主版本和性能实测记录 |

测试数据、同主人多个角色、开发者干预和补贴样本都要可区分；不能冒充独立用户留存、能力提高或商业成立的证据。当前没有这些验证结果。

## 7. 规划完成与下一步

规划完成要求五阶段的范围、依赖、任务和验收一致，七个工作流交付完整，三轮审查形成真实闭环，P0 / P1 矛盾得到复核，剩余选择有明确归属。正式技术栈、视觉风格、许可证和目标宿主仍可在标明影响范围后保留待定。

规划结束后的最小下一步是评审 WS01 的注册与角色流程、WS06 对 M1 所需的接入支持、WS07 的 M1 首次体验，再由用户明确是否启动 M1 实施。本轮不据此自动开工。

历史映射：旧 M0 拆为新 M1 / M2；旧 M1 扩展为新 M3；新 M4 独立增加；旧 M2 / M3 的需求与交换实验归入新 M5。旧 M0-A—F 工作包不再作为执行编号，具体任务统一引用各工作流维护的 WSxx-Tnn。
