## 0. 2026-10-19 桌面实施增量（本轮优先）

### 0.2 背包：网格与宽松详情

- 顶部标题“背包”，演示进入仍由用户主动选择；进入后常显“示例物品”，不把示例挂成当前账号的真实资产。保留现有示例内容与可用筛选；分类显示“全部／作品／虚拟道具”，只是当前演示内容的分组，不新增真实物品模型、持有、容量、余额、领取、交易或使用能力。
- 内容左右分栏：右详情 **288px**，间隔 **24px**，左侧占剩余宽；960px 窗口内左侧约 608px。左栏筛选／现有搜索保持在网格上方，高至少 44px，与网格间隔 16px；不挤占右详情。两种目标视口均保持左右布局。
- 网格 **6 列**、列／行间距 **12px**。每格上部为居中 **64×64px** 图槽，插图最大 **40×40px**、完整适配；下方隔 8px 为独立的两行名称区（40px 高）。选中边框和底色不改变格子尺寸，不用厚边框、发光或强阴影。名称过长省略，聚焦／悬停可看完整名称，右详情始终给完整名。
- 右栏顺序：插图与完整名称 → “作品／虚拟道具” → 当前示例说明 → 有依据的作者／来源与时间 → 已有可用动作。字段缺失不补猜测，长说明在详情内滚动；“查看作品”仅在当前示例确有可读正文时出现，不摆一排禁用操作。作品预览在同一背包窗口内切换，明确返回原格子与网格滚动位置。
- 首次无保存记录时选中当前筛选内第一件；有有效保存记录时按 0.4 恢复原筛选、选择与滚动。切换分类保留仍可见的选择，否则选择新结果首件并同步详情。无结果写“没有找到符合条件的物品”，给“清除筛选”；不保留不属于结果的旧详情。不因点击、滚动或切换格子改变 Agent 或世界镜头。

### 0.3 信箱：完整列表与附加详情窗

保留 **“私人通知／世界动态”** 两个标签。前者为演示收件主体的私人通知，后者为公开公告的阅读列表；“世界动态”是信箱标签，不是 HUD 世界入口的静态面板。读者与收件主体用自然称谓说明，不把示例阅读者冒认为当前登录用户。

| 区域／动作 | 行为与反馈 |
| --- | --- |
| 列表 | 880px 窗口中只展示完整宽度的列表，取消右侧正文预览。标题、示例说明、标签、筛选在上；行至少 72px 高，左右内边距 16px，行内间隔 12px。标题／安全摘要占弹性宽，时间列 88px 且日期时间不挤成逐字换行，尾部操作为两枚 44px 命中区线框图标、间隔 8px（共 96px），悬停／聚焦显名；标题最多两行。详情内使用文字操作按钮。 |
| 筛选与阅读态 | 两个标签分别保存筛选与滚动；“全部／未读／已读”可选，私人通知保留现有“待处理”入口。未读有可见“未读”文字／圆点及较重标题，已读用“已读”文字，不能只靠颜色。待处理由原示例事项决定，读信或删除列表项不完成事项；不新增全局未读红点或真实计数。 |
| 打开详情 | 点击行正文或键盘 Enter／Space，打开一张居中的 680px 附加详情窗，列表保留挂载与原滚动。正文顺序为标题、来源／时间、读者与收件主体、正文、可用的相关内容；无引用不画来源按钮。有引用时在这张详情内切换来源阅读并提供返回，不再套窗。 |
| 已读／未读 | 列表尾部和详情操作区可“标为已读／标为未读”，操作常可见且有可访问名称。每次从列表成功打开正文时标已读一次，手动标为未读后不因重绘立即覆盖；仅列表曝光、加载中、读取失败或不可读不自动标记。手动标记是本读者的整理操作，不证明读完、理解或 Agent 收到／保存。按钮点击不触发行打开。 |
| 返回 | 关闭／Esc 只关闭详情，回原标签、筛选、列表滚动与触发行焦点。已读筛选变化或删除令原行消失时，保留原滚动并按剩余范围钳制，焦点给原位置下一行、无下一行则上一行、无行则列表标题，不跳回顶部或改筛选。 |
| 空／异常 | 完整为空写“这里还没有通知”；筛选为空写“没有符合条件的通知”，可回“全部”。详情失败写“暂时打不开这条内容”，提供“重试”和关闭；原列表与筛选不丢失，不把失败当没有内容。 |

**删除是从本读者列表移除。**列表及详情都可删除，提示“仅从你的列表移除”；不删除公告原文、来源对象或其他读者的条目，不撤回消息、不解除待处理、不向发送者回执。行内删除不顺带打开或标已读；详情内删除后关闭该详情并回原列表。

采用 **10 秒撤销**代替不可逆确认：提示“已从演示信箱移除 · 撤销”，信箱打开时放在窗口内预留的底部反馈行（至少 44px），不覆盖列表；返回世界或其他模块后移至横栏右侧 16px、同垂直中心的临时反馈位（宽不超过 360px），不挤动横栏、不挡窗口或左下身份栏。连续删除在当前 10 秒内合并为一组并从最后一次删除重新计时，提示“已移除 N 条示例通知 · 撤销”；撤销恢复本组条目的原阅读态与排序位置，不重置当前筛选／滚动。返回世界时撤销仍可用；隐藏结果立即保存，撤销同时更新保存记录。待撤销条目标记、原阅读态与实际到期时间随当前隔离范围保存，刷新后仅续接剩余时间，不重新计满 10 秒；核实原主体并再次进入演示后才恢复提示。到期只结束撤销入口，隐藏结果继续保留，不删除服务端内容。

### 0.4 演示隔离与返回动态世界

- 背包／信箱继续主动进入演示，不为访客、登录成功或切换 Agent 自动填入示例。信箱常显“示例信箱 · 阅读标记保存在此浏览器”，成功提示也明确是演示；刷新不自动打开模块或详情，用户再次进入后恢复原上下文，不显示假的真实通知或资产。
- **正常刷新必须保持。**使用独立的浏览器持久存储命名空间（如 `connet.ai:m2-demo-ui:v1`），保存演示已读／未读、隐藏条目、待撤销组，以及背包分类／搜索／选中物品／网格与详情位置、信箱当前标签／各标签筛选／选中条目／列表与正文位置。正文位置只有用户再次主动打开同一条目时恢复；恢复选择或滚动本身不触发已读、不自动开详情。数据改变时移除已不存在的演示条目引用，滚动按当前范围钳制，不用刷新清空正常记录。
- **隔离范围固定为：**演示命名空间＋`location.origin`（含端口）＋实际运行实例＋经验证主人稳定标识＋当前经授权选中 Agent＋来源／示例收件主体；条目标记再按条目区分，私人与公开来源不混用。主人和实例只能取已验证的现有控制器／服务结果；必要时由作者提供无凭据的安全 UI 投影，不用显示名、URL 参数、旧缓存或本稿写死的实例值代替。无 Agent 的已登录主体使用该主人的独立“未选 Agent”范围，不回退到另一位 Agent。
- **访客另域：**使用“访客演示”命名空间＋origin＋实际实例＋持久的本浏览器访客演示标识＋来源／示例收件主体，与任何主人／Agent 范围互不迁入；该标识只分隔本浏览器的访客示例，不代表真实人类身份。登录／退出不自动把两域合并。
- **先清可见旧上下文，再恢复新范围。**退出、身份失效、主人／Agent／实例／来源切换时，立即收起旧详情并清除可见旧列表、计数、选中引用和撤销提示；旧范围的保存记录保留，不能带给新范围。确认当前身份与选中 Agent 仍获授权后，才读取匹配范围；重登同一主人、重新选中同一 Agent 可恢复其记录。启动／验证未完成不预显缓存，也不把缺少身份值当成访客或通用默认键。
- **存储失败有明确降级。**仅存示例标记和界面位置，不存密码、邮箱、token、私密入口、恢复资料或真实消息正文，不修改现有私密存储、真实业务 API／DB 或 Agent 进度。读取记录先校验版本、字段与当前范围；异常记录只忽略本命名空间对应项，不清理其他存储。浏览器拒绝读写或容量不足时保留本页状态，并在演示区自然提示“此浏览器暂时无法保存演示记录，本次更改只保留在当前页面”；这是异常降级，不能把正常刷新丢失设计成默认行为。演示记录不迁入未来真实信箱。
- **HUD“世界”直接关闭背包、信箱、其附加详情／来源阅读及其他可收起内容窗，返回持续动态、可交互的世界画布，不创建世界卡片、概览窗或占位窗。**无窗时点击保持在世界；返回保留镜头、缩放、当前 Agent 与漫游进度。底部 HUD 的 active 状态回“世界”，键盘焦点回世界按钮。
- 移除原世界面板中编造的“演示动态”列表／更新，不补造真实事件。画布动画、自有 Agent 视觉漫游、随动光圈、hover／焦点显名和列表／地图选择同步保留；开关内容窗不主动暂停场景。既有用户暂停／系统减少动态偏好仍按 M1 规则，不新增静态世界展示模式，也不由“世界”按钮强行恢复或重置用户偏好。
- 视觉移动不代表真实 Agent 决策、在线、到访或新事件；未来真实感知接入此动态世界，本轮不做感知后端。M1 未提交编辑／进行中账号任务沿原收起与续接保护，返回世界不强制丢弃、退出登录或取消业务；不重做 M1 权限和流程。

### 0.5 原画布控件保留可达

依据当前 `index.html`、`hud/features/world.js` 与 `hud/scene-renderer.js` 的源码盘点：旧世界窗的“演示动态”一行实际含暂停／播放按钮，另有缩放、全景、探索、重置、场所列表和接入锚点。**移除旧面板／编造动态内容时不得一并删除这些有效操作。**此为只读源码盘点，未冒称本轮浏览器验证。

| 现有操作 | 取消世界面板后的具体位置与行为 |
| --- | --- |
| 缩小／比例／放大、全景 | 世界画布右上轻量工具区：距右 24px、上缘 `max(88px, 顶栏下缘 + 16px)`，宽 360px、高 56px；顺序为“−／比例／＋／全景／场所／更多”。内边距 6px、按钮命中高 44px、间隔 4px，沿用共同表面和图标。比例为只读百分比；缩放范围、步长、全景 `fit` 语义沿用原实现，只改镜头，不改动画或 Agent。 |
| 探索地图／退出探索、返回初始视角 | 放入“更多”的轻量工具菜单，单列每项至少 44px，不做世界信息卡。保持原状态条件：非全景模式才出现探索切换，全景模式才出现“返回初始视角”；探索中的原右下“退出探索”按钮继续保留。初始视角重置只重置镜头／探索，不重置 Agent、身份或演示阅读记录。 |
| 暂停／播放画布动画 | 同一“更多”菜单中显示“暂停动画／播放动画”，按原实际暂停态更新；操作只影响客户端画布，保留系统减少动态与原性能降级，不声称暂停／唤醒 Agent。原“静止展示”模式式文案改为简短事实“画布动画已暂停”或“已按系统设置减少动画”；不恢复静态世界概览或虚构动态流。 |
| 场所列表 | 工具区“场所”打开并聚焦原 `#world-place-directory` 可折叠目录，继续使用原场所说明／返回地图路径；保留原目录文字入口，不复制一份列表塞进世界窗。场所说明不表示真实到访或互动。 |
| 了解与接入 | “更多”保留原“了解与接入”链接，仍到 `#world-entry`；原顶部“接入 Agent”等入口保持，不新增接入流程、不自动登录／发码。 |
| 键盘与异常 | 画布聚焦后保留方向键平移、＋／− 缩放、Home 全景、Ctrl／⌘＋滚轮；输入框和阅读窗不被这些快捷键抢占。地图未就绪时，仅依赖画布的操作按原规则不可用；场所列表、接入说明和原“重试地图”仍可达，失败不伪装无内容。 |

工具区只在世界画布为当前阅读面时显示；打开背包、信箱、M1 账号／管理或场所说明时隐藏，点击 HUD“世界”按原任务保护收起内容后恢复工具区，不开世界窗。“更多”只承载上述工具，打开不暂停动画、不抢镜头；再次点击、Esc 或选择动作关闭并归还焦点，不与附加详情叠开。左下当前 Agent／定位、底部横栏、右下退出探索及临时撤销提示保持互不重叠，必要时按实际矩形避让。两种目标桌面尺寸均按此位置核对，不另增常驻大说明卡。

| 刷新保持与隔离 | 关闭重开／正常刷新后保持已读、隐藏、分类／筛选／选中及滚动；退出再重登同一主体恢复原范围，换主人／Agent／实例／来源或访客不继承。验证前不露旧内容；存储受限有自然降级提示，真实库／私密存储／Agent 进度不写入。 |
| 返回世界 | 从背包、作品预览、信箱、详情／来源阅读返回动态画布；无静态世界窗或编造动态列表，镜头／自有角色／选择联动及 M1 任务保护保持，撤销仍可达。 |
| 画布工具续接 | 两种尺寸用鼠标与键盘操作缩放、全景、探索／退出、原条件下重置、暂停／播放、原场所目录与接入锚点；取消旧窗后无操作丢失，无工具／HUD／内容重叠，不暂停或伪称启动 Agent。 |

上述为本轮设计核对项，作者实现验证、专门独立代码审查、独立普通用户桌面闭环与后续设计复核各留各自证据。本次只交两份设计正文，未操作服务／账号／DB，未制作新图或运行候选验收。

## 1. 用户首先要得到什么

人进入世界，应能回答“这里是什么、我能看什么、刚才读到了什么、现在可以做什么”。Agent 则按本地主人许可取得同一来源下的有界结构化信息，按需读取详情；不会通过操控角色或读取网页像素感知世界。人和 Agent 权限／用途不同，看到的内容可以不同。

| 用户目标 | 首选入口与结果 | 依赖的事实 |
| --- | --- | --- |
| 找一个人、Agent、作品或场所 | 目录分类／已支持查找 → 同一对象详情；地图是另一入口 | 可发现范围、对象来源、当前可读字段 |
| 看公告和活动 | 目录“动态”或告示牌 → 公告／活动／变化记录 | 作者／发布来源、时间含义、当前说明 |
| 看发给我的内容 | 信箱 → 明确收件对象 → 来信／提醒详情 | 当前阅读者、收件对象和正文／摘要权限 |
| 看仍需处理的事 | 信箱“待处理” → 原业务当前允许的入口 | 当前事项独立来源；不从未读数推算 |
| 了解自己的 Agent 近况 | 我的 Agent → 显式选择对象 → 近期记录／下一步 | 网站访问记录与 Agent 报告各自的时间和范围 |
| 改变获准的阅读范围 | 我的 Agent → 阅读范围 → 保存结果 | 谁可改哪些条件，保存结果与后续采用／更新证据 |
| 隔几天回来继续看 | 打开原入口 → 更新当前内容，必要时说明历史缺失 | 当前权限、阅读范围和可恢复区间 |

首屏给结果、当前情况和下一步；必要错误、未开放、未确认及演示信息保留可读说明。Agent 的内部思考、评估表、模型评分、提示词链和工程状态机不进入产品阅读页面。技术依据只在本合同及实施交接中维护。

## 2. 熟悉的入口与信息层级

沿用 [内容体验稿](ws02-perception-experience.md) 的四个逻辑目的地：**世界、目录、信箱、我的 Agent**，它们不等同“个人／背包／信箱／世界”四枚 HUD 图标的业务分类。实际外壳以第 0 节及 M1 共同合同为准：底部横栏、居中窗口，“世界”返回动态画布；2026-10-17 [紧凑桌面效果提案](visuals/m2-desktop-hud-2026-10-17/README.md)保留为历史，不再以其右侧竖栏、左展窄窗或信箱双栏实施。文字菜单保持可发现和键盘可达。M1 账户／主人管理保持原入口，查看对象不会切换登录身份或私有收件对象；真实业务范围仍由各所有者提供。

目录建议分类为“人、Agent、物品、场所、动态”；“作品”是物品下的筛选。“动态”是用户入口名，内部对应公告、活动与变化记录，不替业务决定新的类型模型。分类／名称是本轮设计提案，实际启用以来源为准。

- 桌面：固定导航与页面标题；地图／列表为主区，普通详情在同一阅读区切换，信箱按第 0 节使用保留列表的一张附加详情，不无限叠窗。核心动作不依赖悬停、拖拽或找隐藏建筑。
- 手机：保持四个入口可达，地图、目录和详情单列显示；返回保留来源页面、筛选与位置。进入私有信箱不要求先在地图找到邮箱。
- 详情先给名称／类型、主要内容和当前说明，再给来源／时间、实际可用动作；完整编号等识别信息按需查看。
- 未接入的能力不给假按钮或一排禁用操作。确实需要解释下一步时，在相关位置写“此类消息尚未开放”等短说明。
- 未知总数不展示精确数字；阅读标记与待处理分别标名，既不相加，也不借红点制造义务。

以下页面是信息结构，未指定 URL、前端框架、API 字段或新的视觉引擎。

## 3. 最小页面／阅读面合同

### P01 世界

**用户目标：**看懂小镇是什么，并找到可查看的内容。

**显示内容：**复用 M1 小镇环境；真实内容与虚构演示就近分开标注。页首说明当前模式与浏览范围；真实对象只显示已获准摘要。未提供实际位置的对象仍可从目录找到，不强放进酒馆。地图资料位置、角色装饰、到访事实分开。

**控件与反馈：**HUD“世界”按第 0 节关闭内容窗并返回动态画布，不打开静态概览。既有画布缩放、定位和减少动态遵循共同规则，不在本轮新增世界控制面板；未来有获准来源时，目录与已绑定地标／对象指向同一详情。点击不产生到访、签到或唤醒 Agent；装饰物不伪装可点。

**状态：**演示显示持续可见的“虚构演示”；真实内容读取中／部分显示／失败／无获准内容按第 5 节处理。没有权限显示某对象时，图标、标签、计数和关系均不露出。不能把“环境里有酒馆”写成“有居民正在喝酒”。

**依赖：**D1、D4；E01/E02/E06。环境素材已交不表示 M2 数据绑定已存在；本轮不改 M1 地图素材／代码。

### P02 目录

**用户目标：**不用操作地图也能找到内容。

**显示内容：**清楚的类别、当前范围、已支持筛选、结果列表与加载反馈。物品中的作品用同一条对象记录；不重复加总。列表行只显示获准名称、类型、安全摘要及有用的时间／说明。

**控件与反馈：**类别选择、已支持的场所／标签筛选、“清除筛选”“加载更多”、打开详情。精确编号查找、按名称搜索是否提供，由 E02 明确；未提供前不画可输入但无结果能力的全局搜索。筛选只改此列表，不替 Agent 保存偏好。

**状态：**未读完写“已显示部分内容”；成功且完整为空才写“当前范围内暂无内容”。更改范围后重新加载，不把旧列表当新范围完整结果。失败不覆盖成空列表。

**依赖：**D1；E01/E02。与 P01 共用事实，采用有界页，不为地图先取全世界。

### P03 对象详情（地图、目录及获准引用共用）

**用户目标：**知道这是什么、内容是什么、目前能做什么。

**显示内容：**名称／主体类型、主要内容、当前说明、来源／更新时间。下表只在字段实际可读时出现；没有字段不显示猜测或虚构值。

| 对象 | 首屏重点 | 仅在成立时显示 |
| --- | --- | --- |
| 人／Agent | 类型、名字、公开简介；必要时查看编号 | 获准公开字段；不显示私有主人账号或控制关系 |
| 物品／作品 | 类型、正文或可读内容、作者声明／发布来源 | 展示场所、持有关系分别有源；作者声明不当版权认证 |
| 场所 | 名称、用途、当前可看内容 | 有源位置／声明时间，获准管理说明；不从建筑推导权利或在场 |
| 公告 | 作者／发布来源、正文、发布时间／更正说明 | 可独立原创；不强制有“原事件” |
| 活动 | 计划时间、地点说明、当前状态与来源 | 取消／改期／真实发生证据；计划时间已过仍可能结果未知 |
| 变化记录 | 哪项事实在何时改变 | 获准查看当前来源的入口；历史不替代当前业务结果 |

**控件与反馈：**返回原入口、获准时“查看场所／相关内容”；确有可展示位置时才有“在地图查看”。M2 不出现发私信、报名、购买、领取、接受或交易动作。外链由用户显式打开，正文不执行脚本或取得本地工具授权。

**状态：**详情比列表晚失权时立即移除受影响内容，不通过旧缩略图／标题兜底。活动过去了只改时间提示，不自动写已完成；到期后仍准阅读的历史可以保留。

**依赖：**E01/E02/E03；D4 影响位置说明。物品资产关系受 D3 限制。

### P04 信箱

**用户目标：**分清发给谁、我还没看什么、现在还有什么需要处理。

**显示内容：**本轮演示的“私人通知／世界动态”、整行列表与附加详情以第 0 节为准。以下真实业务规划要求页首“我的信箱”或“发给小岚 · 获准查看的通知摘要”，明确登录阅读者与收件对象；私人来信／提醒与待处理分别筛选，公开公告保持公开来源的阅读列表，不伪造私人投递。

**控件与反馈：**本轮只开放第 0 节的隔离演示已读／未读／移除。真实收件对象选择、阅读标记与列表删除仍需业务来源支持；切换清掉上一个对象的私有内容／计数并重新读取。列表打开自身信件或提醒详情；“待处理”仅列原域当前允许的继续入口。人类已看标记只影响本人获准视图，不给发送者广播，不修改 Agent 进度。

**状态：**无权限时不泄漏任何信件存在／数量；来源未启用写“此类消息尚未开放”；未取得全部待处理项时不报“全部处理完毕”。不把主人管理绑定当全量私信阅读权。

**依赖：**D2；E01/E03。人类独立收件、主人可看哪些 Agent 摘要均需合法身份／来源，M1 登录本身不证明可读。

### P05 来信／提醒详情

**用户目标：**读懂这份内容，知道是否有下一步。

**显示内容：**获准标题、作者或产生业务、投递来源、时间、安全正文／摘要和当前说明；原创信可以没有任何外部引用。派生提醒有获准引用时才显示相关来源。收到一条内容不等于已接受其诉求。

**控件与反馈：**本轮演示按第 0 节执行，关闭附加详情返回原列表。真实业务支持且有权限时才记录本人已看范围；打开正文如会产生真实阅读标记，应由 E03 先明确范围／版本，不能沿用演示内存代替。列表曝光不算阅读；有引用且可读时“查看相关内容”，没有引用就不画“查看原事件”。

**状态：**提醒到期时仍获准的历史正文可读，失效动作移除；内容撤回／读者失权则按当前权限裁剪。只允许保留最小提示时写“这条内容已不可查看”；连存在性也不可透露则从列表移除，不留透露身份的墓碑。

**依赖：**E03。原创来信样例可用于说明关系，不能借样例开放 M3 发信／回复／接受。

### P06 我的 Agent

**用户目标：**了解自己的哪一个 Agent 最近有何可确认更新，下一步去哪看。

**显示内容：**明确 Agent 名字／编号、最近访问时间、最近获准的结果或报告、尚未确认的必要说明；可进入“阅读范围”和已有接入帮助。“记录说明”按需展开，用人话区分网站记录和 Agent 报告，不展示内部思考或评估过程。

**控件与反馈：**Agent 选择器、“查看已有内容”“阅读范围”“接入帮助”；“刷新页面”只更新网页，不让人误以为已启动 Agent 检查。M1 主人管理链接保持原权限，不在本页重做账户／恢复流程。

**状态：**没有记录写“还没有世界访问记录”；只有旧记录给具体时间与“此后暂未收到更新”。不给准确在线／离线灯，不从旧暂停报告推导现在仍暂停。切换不继承别的 Agent 的计数、筛选、报告或时间。

**依赖：**E01/E04/E07。平台提供数据不等于 Agent 已保存；未收到声明不等于它已失败或没看过。

### P07 阅读范围

**用户目标：**知道当前设置属于谁，并调整业务允许的阅读条件。

**显示内容：**返回 P06、当前 Agent、已保存条件和修改权限；只出现来源已支持的空间／类型／标签等选项。目录临时筛选不会写入这里；设置不扩大权限或向被关注者发送消息。

**控件与反馈：**有修改权限才出现“保存”“取消”，变更未保存时离开给明确选择；只读范围不画可编辑假控件。保存期间保留输入，失败允许重试并保留上次已确认结果；并发冲突提示重新查看最新设置。

**状态：**“阅读范围已保存”只表示保存成功；尚未取得新范围的完整结果时写“新范围的内容还未全部更新”。是否已被本地 Agent 取得／采用只有获准证据才说，没有则不承诺立即生效或已读完。

**依赖：**E05/E07。谁能改、结果如何确认由 WS01/WS02 给出；没有可写来源时可先完成只读设计，不替业务增加写接口或网站排程。

## 4. 最小用户旅程

| 旅程 | 连续路径与完成结果 | 必须保留的分支 |
| --- | --- | --- |
| J01 首次进入 | P01 识别真实／演示 → P02 浏览获准范围 → P03 读内容 → 返回原位置 | D1 未决时只画带条件的访客分支；无真实权限不伪造“登录后必能看全世界” |
| J02 找作品和场所 | P02 物品→作品／P01 展台 → 同一 P03 → 获准时看场所或定位 | 没有地图位置仍可读作品；展示位置不等于持有，点酒馆不登记到访 |
| J03 看公告和活动 | 动态／告示牌 → 公告或活动 P03 → 返回 | 原创公告无引用可独立读；计划时间已过但结果未知、取消及改期分别表达 |
| J04 看信与待处理 | P04 确认主体 → P05 看获准内容 → 返回 P04；待处理另查原域 | 我已看过但仍待处理／旧信未读但事项已解决；不把一次阅读当接受 |
| J05 主人管理两个 Agent | P06 选 A 看近况 → 选 B 重读 → 显式进入 B 获准摘要 | 不借 Agent 凭据冒充收件人；A 的内容／计数不会短暂显示为 B，普通对象详情不切换主体 |
| J06 隔几天回来 | 当前权限有效 → 更新所选范围 → 看缺口说明及当前事项 | 未读完／暂时失败／无持久保存／旧授权失效分别说明；不补演离线生活，不补跑每次定时 |
| J07 调整范围或遇到内容变化 | P07 保存获准条件 → 查看新范围结果；对象失权时清理所有当前入口 | 保存与更新完成分开；取消关注不是删除对象，失权不以返回位置或缓存恢复正文 |

## 5. 状态与普通用户文案

本表是需设计的覆盖集，不是在界面展示一张状态机；实际文案按页面对象填入可理解名称。成功反馈放在操作附近，重要错误保留可发现说明，不只用短暂浮层或颜色。

| 实际情况 | 给人看的结果／当前状态 | 下一步与边界 |
| --- | --- | --- |
| S01 正在首次读取 | “正在加载作品……” | 保留类别和返回，避免假装空列表 |
| S02 成功、完整、为空 | “当前范围内暂无作品” | 清除已有筛选或看其他类别；只针对当前范围 |
| S03 部分结果 | “已显示部分内容，还有内容未加载” | “加载更多”；不报精确全量总数或完成 |
| S04 读取失败 | “暂时无法更新，请重试” | 有仍获授权旧内容时保留并标上次更新时间 |
| S05 首次无访问记录 | “小岚还没有世界访问记录” | 查看接入帮助，不写离线或故障 |
| S06 较久没有更新 | “最近访问：10 月 15 日 10:20，此后暂未收到更新” | 看已有内容／帮助；没有观察依据不自行判逾期 |
| S07 内容是否已保存未确认 | “这次新增内容是否已保存，暂未确认” | 可展开记录说明，不显示 Agent 思考／推理阶段 |
| S08 历史超出可补范围 | “已更新当前内容；部分较早记录无法补看” | 看当前对象和当前事项，不称完整还原历史 |
| S09 来源未启用 | “此类消息尚未开放” | 返回已可用内容，不写“没有来信” |
| S10 活动时间已过、无发生结果 | “计划时间已过，结果尚未确认” | 有权时看活动说明，不自动标已完成 |
| S11 提醒到期／活动取消 | “提醒已到期”／“活动已取消” | 移除无效动作，仍有历史阅读权时正文可读 |
| S12 事项已解决、旧信仍在 | “这条事项已处理”或原域获准结果 | 旧信可按权读，不继续制造待办；读信本身不解决事项 |
| S13 内容撤回／阅读失权 | “这条内容已不可查看”或不再返回该记录 | 仅在存在性可透露时说明；隐藏相应标题、图像、计数与旧引用 |
| S14 范围发生变化 | “范围已更改，正在更新内容” | 受影响旧页不当完整结果，不混入新范围；无权内容立即清理 |
| S15 设置保存失败／版本冲突 | “未能保存，已保留你的修改”／“设置已变化，请查看最新内容” | 仅在输入确已保留时说保留，允许重试或重新确认 |
| S16 设置已保存，结果未更新完整 | “阅读范围已保存，新范围的内容还未全部更新” | 查看已取得的获准内容，不推断 Agent 已采用 |
| S17 身份不再可用 | 人类登录：“登录已失效，请重新登录”；Agent 记录：“小岚暂时无法访问世界，请查看接入帮助” | 只在明确失败且可披露时说明；隐藏私有内容，沿已支持的 M1 路径，不凭公开编号恢复权限 |

所有真实／演示／未开放／未确认说明靠近相关内容。错误原因只有来源明确且允许披露时给出，不猜电脑关机、余额不足或 Agent 意愿。

## 6. 同一事实的两种表达

下表的结构化项只约定需要的语义，由 WS02／技术负责人决定实际 schema、路径、分页和错误结构；不把本合同做成第二套协议。

| 同源事实 | Agent 有界结构化表达需要什么 | 人的页面显示什么 |
| --- | --- | --- |
| 所选范围的对象／版本 | 主体／用途、范围、稳定引用、来源、时间、续读与完整性 | P01/P02 的获准对象和“部分显示”；详情看到同一当前可读内容 |
| 作品／持有／资产 | 作品为物品子类；展示、作者与持有关系分别有源 | P03 看作品；没有持有源不生成背包，没有余额源不填零 |
| 空间 | 用途、资料位置、位置声明／时间、权利分别提供 | 场所介绍；仅有布局坐标不写“正在这里”或“拥有土地” |
| 原创信与派生提醒 | 原创内容自身标识／正文／受众；提醒的来源引用另判权 | P05 先读自身内容，有获准引用才跳转，不强制“查看原事件” |
| 当前事项 | 原域当前结果、允许入口及完整性独立枚举 | P04 待处理；与我看过的来信分别表达，不将两者相加 |
| 网页已看和 Agent 保存 | 阅读者／用途／内容版本和各自进度互相独立 | 我看过摘要不说 Agent 已保存；Agent 保存不说主人看过正文 |
| 最近访问及报告 | 网站请求／提供数据记录，与客户端实际声明分别有时间／覆盖范围 | P06 近期结果＋“小岚报告”／“暂未确认”；记录说明不变成思考过程 |
| 失权／离线恢复 | 服务端后续拒绝无权数据，客户端获知后清理；恢复当前视图及缺口 | 不继续展示无权标题／图像；说明当前可看内容与缺失历史，不承诺抹除外部副本 |

## 10. 可执行的后续验收场景（全部待运行）

独立普通用户模拟统一遵循[普通用户模拟验收标准](../../../validation/user-simulation/acceptance-standard.md)。本节只提供 M2 的任务与内容预期，结果判定、发现分级、证据记录、隐私保护、报告和回归规则均引用该标准，不另设一份标准。体验稿的认知题只作补充核对，不向模拟者预先提供答案、源码或隐藏入口来指导过关。

共享标准中已登记的 M1／B 版本、端口和合成身份边界仅适用于其原执行范围，不自动成为 M2 测试资源或通过证据。M2 须待总指挥确认候选版本、隔离入口和可测范围后安排；当前只有设计文档，未开展本节任何普通用户模拟。

| 场景 | 应看到的结果 |
| --- | --- |
| 首次访客与已授权成员 | 模式／范围易懂；真实内容按 D1，演示始终标明，不强制碰建筑才能进入目录 |
| 地图与目录找同一作品 | 同一名称／内容／版本，作品位于物品下；无位置仍能阅读，不推导持有或可购买 |
| 同名居民与私人主人关系 | 能用允许的编号区分；公开作者资料不露出私有控制关系 |
| 活动改期、取消和计划时间经过 | 各有当前说明；结果未确认不写已完成，不提供报名或自动参与 |
| 原创无引用来信与派生提醒 | 前者直接读自身正文；后者在获准时查看来源，不强制造一个世界事件 |
| 信已看但问题仍在／问题已解决但信未读 | 待处理依原域结果，阅读标记不关闭或创造事项 |
| 主人已看摘要、Agent 没有新保存报告 | Agent 下次仍可按自己的进度获取；主人未见正文不标正文已读 |
| 主人管理 A、B 两个 Agent | 切换不串旧计数／信件／设置；管理权不变成全部私信权限，普通详情不会切收件主体 |
| 新访问记录、旧保存／暂停报告并存 | 分清记录和报告的范围／时间；不显示在线、思考中或必然已暂停 |
| 来源未启用、成功为空、部分、失败 | 四种状态可辨；无假精确计数或“全部处理完毕” |
| 长离线与超窗 | 当前可读内容可恢复，较早历史缺失有说明，不补演行动或补跑全部定时 |
| 到期后仍准阅读／内容撤回失权 | 前者有权历史仍可读；后者清理标题、图片、计数和引用，存在性按权处理 |
| 改筛选、标签移出／重入、重试和重叠响应 | 当前范围可信，不混页、不重复内容、不让旧内容覆盖新结果 |
| 保存阅读范围的失败／冲突／部分更新 | 输入与已确认结果不混淆；保存不等于 Agent 已采用或新范围已完整读取 |
| 手机与仅键盘操作 | 找作品→看详情→返回→打开信箱；焦点可见，来源位置保留，失权内容不恢复 |
| 外部正文请求执行命令或索取秘密 | 只作为内容阅读，不自动执行、打开外链、安装 Skill 或授予工具权限 |

实际记录与报告按共享标准执行，代码测试、视觉复用、真实宿主和普通用户结果保持各自证据范围。独立普通用户模拟 thread `01a14069-5861-7162-a129-a7be0f7926b5` 只向总指挥报告，本会话不自行给它派单，也不把未测的 M2 写成通过。

## 11. 视觉与交互复用约束

沿用 [完整地图合同](../../ws07-experience-launch/design/world-town-scene-contract.md)和 [world-town-kit](../../../design/world-town-kit/README.md)的淡雅生活小镇基础，不开展新十风格比较、不生成 M2 专属建筑／资产、不实现第二套地图渲染。素材的图形、位置和人物动作本身不携带真实业务事实；DOM 文案、点击区域、可见摘要及权限由数据绑定承担。

地图载入／绘制的选择由技术总监在既有世界呈现评估中决定，经统筹交接。M2 提供局部范围、对象引用和可读状态，不能要求引擎预拉全世界、靠人物自动寻路触发业务或靠装饰补造真实行为。

采用搜索／分类／列表／详情等通用发现习惯，参考 [Steam 官方搜索页](https://store.steampowered.com/search/)，不复制它的商业功能或视觉皮肤。标签分区与弹窗的键盘行为参考 [W3C Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) 和 [W3C Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：保持可见焦点，模态内焦点受控、Escape 关闭后回到合理触发位置；全页详情／非模态侧栏不锁住背景焦点。导航跨页链接与页内标签分清，点击导航不依赖鼠标悬停。

本轮先核对第 0 节的桌面 1440×900、1280×800；其余桌面及手机 390/320 保留为后续要求，未测不记通过。正文不随地图缩小；操作命中区至少 44px，减少动态不丢信息，地图之外的文字路径完整；不构成容量／性能承诺。
