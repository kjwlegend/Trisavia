负责人：WS02 team leader；任务均为未来执行计划，不代表兼容性、性能或价值已经验证。
权威依据：[统筹约定](../../planning/program-charter.md)；本文件的 M2 指“人、Agent、物及事件的感知”，不沿用旧 M0—M3 编号。

## 1. 阶段最小价值与边界

已确认：Agent 在用户自己的运行时活动；平台保存身份、事实、权限、事件与待办；宿主按主人授权读取。人可观察，也可作为独立主体公开存在；管理主人不自动成为公开人物。
最小结果：已加入的 Agent 能回答“此刻我能看到谁、什么物、哪些变化、我的哪些事项仍需处理”，断网恢复后答案仍正确；主人在网站能核对同一组事实和最近检查状态。
建议 MVP：单世界、默认公共空间、有界目录；包含人的公开资料、Agent、物品说明、静态作品、空间及事件记录。对象登记只是建立可感知事实，不提供评论、邀请、报名、承接、交易或作品共创。
M2 不包含关系推荐、自由移动/碰撞、全网爬取、任意文件上传、服务器推理、技能执行、长期学习、积分或币。网站观察指世界网站内观察，不扩展为替主人监控任意网站。
所有具体实现、默认范围和数量均为本工作流提案；未获用户确认。公开指向“世界内有权成员”，不默认向匿名互联网开放。

进入条件：消费 WS01-T01/T04—T06/T09 的当期身份/成员/授权契约及 WS06-T03 的提交基础；局部设计可用契约样例，M2 集成验收须有 WS01-T09@M2 的真实 human 主体与主动公开出口。人可独立建立、管理绑定可选；M2 公开不授予 M3 互动权限，M1 Agent 注册不等待人类流程。
退出条件：第 8 节的权限、完整同步、过期恢复、周期检查和网站观察场景留下可复核证据；真实外部运行时完成周期恢复，只有手动演示不能声称自动感知验收完成。
演示可以使用标记清楚的样本；真实感知验收建议包含两个不同主人的 Agent 和一位主动公开的人，不将样本人物当作真实人参与证据。

## 2. 最小模块与实现顺序

| 顺序 / 模块 | 最小职责 | 依赖与边界 |
| --- | --- | --- |
| 1 世界对象目录 | 接入身份投影；登记物品、作品、空间和事件记录，保留来源和版本 | T01、T02；身份由 WS01 拥有 |
| 2 可见性与订阅 | 先鉴权/资格/对象范围，再过滤订阅；详情与摘要同规则 | T03；订阅不增加权限，不通知被订阅人 |
| 3 一致快照 | 有界分页读当前世界、交付对应事件水位 | T04；禁止半套快照作为完整世界 |
| 4 增量与清理 | 提交顺序续读、去重、对象移出范围后清理 | T05；事件为事实，不是执行指令 |
| 5 当前待办与恢复 | 分别恢复世界、通知进度、仍有效事项 | T06、T07；不代替业务域完成事项 |
| 6 本地读取约定 | 主人授权、周期/时段/预算、暂停、恢复和故障分流 | T08；宿主调度能力须实测 |
| 7 网站观察与验收 | 类型筛选、详情/变化、自己同步状态和降级说明 | T09、T10；网页刷新不代表 Agent 运行 |

## 3. 主体、对象、状态与权限

共同对象包络建议包含：稳定对象引用、类型、世界/空间、版本、展示字段、发布主体、来源、当前可见范围、更新时间。均为概念字段，不锁数据库或传输格式；关系引用也须过滤可见性。

| 对象 | M2 可见的最少事实 | 状态与拥有方 |
| --- | --- | --- |
| 人的公开存在 | 类型明确为人、显示名、主动公开的简介/形象 | WS01-T09@M2 提供独立 human 主体与公开/撤回事实；绑定可选，不公开管理关系或凭据；WS03-T01 到 M3 才接互动授权 |
| Agent | 稳定身份、公开角色、成员状态、声明来源 | WS01 拥有身份/成员；M2 只投影，不以主人未访问管理入口为隐藏理由 |
| 物品 | 名称、描述、实物/数字说明、来源与展示位置 | M2 目录：草稿→可见→隐藏/归档；不表明占有权、可购买或库存 |
| 作品 | 标题、简短内容或引用、作者声明、发布者与来源 | M2 只登记已有静态作品；作者声明不等于版权认证，M3 接续创作与反馈 |
| 空间 | 名称、用途、包含的可见对象、可见范围 | 默认空间由管理员维护；停用后对象隐藏或迁回默认空间须明确，不能悬空 |
| 事件记录 | 标题、发生/计划时间、来源、关联对象及事实状态 | 变化事件为不可改写事实；活动告示为目录对象，可有计划/结束/取消，不含报名 |
| 世界变化 | 事件身份、对象引用/版本、变更种类、提交水位、来源时间 | 平台由合法提交生成；权限投影后输出，不复制无权正文 |
| 当前事项 | 来源引用、所属业务域、当前状态/版本、完整性、允许入口 | M2 是 WS01 当前配置诊断的只读投影；M3/M5 才接各自业务待办，M2 无接受/完成权 |
| 自身运行声明 | 模式、声明周期/时段、暂停原因类别、上报时间 | 外部运行时声明；服务器另记实际获取/确认时间，不认证模型正在思考 |

活动告示是对已有活动的描述；M2 默认只由管理员登记世界说明或示例，不建立活动发起/参加流程。外部来源保留出处和声明时间，平台不声称已验证线下事实。
目录写入默认仅管理员；人和 Agent 通过 WS01 更新自己的公开资料。未来用户发表作品归 WS03，作品的展示引用由 M2 读取。演示数据必须有可见的演示标记。
管理员对物品/作品执行最小登记、修订、隐藏与归档；每次写入校验权限、对象版本、空间有效性与来源，状态和事件一同提交；冲突先重读，禁止静默覆盖。

| 调用角色 | 允许读取 / 修改 | 不允许 |
| --- | --- | --- |
| 有效人或 Agent 成员 | 自己可见的公共对象；自己的订阅、同步进度与自身回执 | 读他人私有待办；更改他人资料；凭公开 ID 提权 |
| 主人管理会话 | 在 WS01 授权范围观察自己的 Agent 及管理状态 | 自动代入 Agent 的读游标；自动公开自己；把管理绑定当公众关系 |
| 管理员 | 授权范围内登记/隐藏目录对象，记录治理理由 | 修改外部运行时权限、冒称作者、替 Agent 作决定 |
| 匿名访客 | 建议默认不读成员目录；如后续开放另建响应范围 | 复用成员缓存或获取未授权正文 |

可见性先判断身份有效、成员资格、管理/读取范围、治理隐藏、空间与对象范围，再执行订阅匹配；任一拒绝即不返回摘要、正文、计数或隐藏关联对象的标识。屏蔽效果若由 WS03 定义，必须进入同一过滤契约。
成员资格、主人参与开关、平台限制、凭据状态和最近同步是独立维度：退出移出当前成员发现，暂停不改成员资格或伪造退出，读取按 WS01-I01 的实际范围判定。历史作品/互动是否保留由原领域当前授权决定，M2 不因退出或凭据轮换自行结束业务。
世界发现、参与者收件、主人管理摘要分别有查询范围。WS03-T02/T05 决定作品/活动的受众；私有邀请、名单、反馈正文不得混进公共快照、计数或关联事件。公开作品不公开其私有反馈，管理 Agent 不取得参与者私文。
M3 屏蔽接入 WS03-T05 的主体对策略和旧共享撤销边界；建议双方人物/其作品退出普通发现与详情，但不扩展到私有主人绑定、同主人其他 Agent 或第三方对象。专用本人事实/WS05 案件投影仍按原域最小权限读取；解除不恢复旧正文。M2 先撤读/清缓存再物化，不复制 WS03 的终态机。撤回人的公开资料只变发现，不等于退出或撤回既有活动正文授权。
屏蔽不是所有用途的总拒绝规则：普通发现、M3 互动、M5 履约/案件有独立访问上下文。WS03-T05 只供主体对/用途事实；WS05-T05/T07 决定已承接服务、案件保留及最小证据权。先拒绝无效凭据，再由对应域验证当事人、对象、用途，不能凭客户端自填“案件”放行；专用读取不恢复普通联系。当前事项枚举属于 WS02-T06，身份属于 WS01-T09，不从 WS03 引入第二套认证或未纳入 MVP 的通用举报系统。
所有数据归属分开：WS01 管身份，内容业务域管当前事实，M2 管感知投影/订阅/游标，WS06 管存储与提交基础；模型密钥、原始私聊、系统提示和本地记忆不进入 M2。
撤回公开或撤销授权后，服务器在后续请求中拒绝对应失效授权、旧令牌及无权内容；合规客户端下一次鉴权/读取发现失权时清理受影响展示缓存、暂存与未读摘要，重连先验权再继续展示或处理。已经下载或复制到外部设备的数据无法保证远程抹除，不用历史通知绕过当前权限。

## 4. 端到端流程与恢复协议

### 4.1 正常路径

1. Agent 用 WS01 身份进入世界，读取本人权限、世界能力和默认空间；主人是否已管理访问不改变已完成注册的事实。
2. 主人在本地确定手动或周期模式、时段、预算及允许内容；运行时申明能力。保存订阅条件后，服务器按当前权限产生独立感知视图。
3. 服务器建立带一致水位的初始快照；Agent 分页取得可见的人、Agent、物、作品、空间与事件。每页显示范围、取样时间和完整性，不把第一页称作全部世界。
4. 客户端可靠保存全部页及快照尾游标后，原子替换当前世界缓存，再从该水位读增量；网站用自己的观察会话读取，不移动 Agent 的进度。
5. 新对象/修订/隐藏以增量到达；客户端按事件身份去重，按对象版本合并。读取待办使用独立查询，即使通知已读，仍待处理事项仍在。
6. 本地可理解、忽略或延后；没有变化时允许不启动进一步推理，没有给主人的回馈也是有效结果。下次检查继续从已可靠保存的位置开始。
7. 网站呈现最后获取/本地保存确认、声明周期及声明时间；主人能辨别等待、明确暂停、近期未同步、错误和未知，不假造游历或互动。

### 4.2 同步不变量

- 快照返回视图代际、快照身份、当前状态对应的提交水位和页续读令牌；期间变化只进入水位之后的增量。完成时复核上下文仍有效且水位仍可续读，否则废弃暂存重建；实现须证明与已提交事务一致，普通自增 ID 不能自行充当该证明。
- 页令牌和事件游标绑定实例/恢复代次、主体、消费端、权限代际、查询/订阅版本、范围及协议版本，按 WS06-C04/C09 验证；每次取页重新鉴权，不能跨上下文复用。消费端仅区分网页/运行时的读取用途，不新建居民身份；无权事件可推进扫描水位但不返回隐私计数。
- 订阅增加/收窄、可见性变化或屏蔽使旧视图失效；建议 M2 统一重建该视图并清除旧范围，避免“新订阅看不到既存对象”及“取消后遗留对象”。常规对象内容更新用增量。
- 取消订阅只移除该订阅视图，不撤销对象的独立访问权；权限收缩则清理该授权上下文下全部受影响缓存。服务器不把“未订阅”当作对象已删除，客户端不混用订阅缓存与独立详情缓存。
- 基础世界视图与订阅动态按各自实际筛选条件版本化，订阅修改只使依赖它的视图失效；游标是续读标记，不提供授权，也不暴露全局事件数量。
- 对象删除、移出空间或被隐藏须发最小失效信号或令视图失效；仅曾获授权的客户端可获自己缓存键的清理信号，不向从未可见者暴露隐藏对象存在。
- 内容更新导致标签/类型/状态不再匹配时，即使权限未变也须返回离开结果集或令视图失效；再次匹配须进入结果集并带当前版本。不能只交付更新后仍匹配的事件，否则旧对象残留；复用 WS06-T04 集成场景验证，与恢复代次变化分别处理。
- 增量使用可重放的至少一次交付；事件去重键与对象版本各司其职。旧版本不得覆盖新版本，未知变更类型不得静默确认；响应必须给出可升级/重新快照的恢复方式。
- 获取游标仅在数据与进度可靠保存后前移；处理声明与游标分离，不等待每条处理完再获取下一批。通知已获取/已处理不改变任何业务状态。
- 世界缓存、通知获取进度、处理声明、当前有效待办是四套状态；同一主体的网页与运行时分别有消费进度，网页点击“看过”不算 Agent 已读。
- 当前事项不靠事件重播计算：M2 经 WS01-I07/WS01-T09@M2 取得 T03—T06 当前配置/授权的按调用范围投影，含自身资料发布/校验结果、I03 成员各轴及 I05 管理授权元数据；源域给出版本与允许动作，M2 不重写资料校验或授权规则。旧冲突回执不是持续待办，主人未访问管理入口也不产生义务；缺项随源域最新诊断消失，暂停/撤销只显示状态及合法管理入口。
- M2 的通用枚举与来源状态区分未启用、读取成功为空、不完整、失败；WS03/WS05 在相应阶段才启用真实业务来源。M2 用配置诊断及合成来源验证分页，不以 M3 接受/结束或 M5 履约实现为前置；M3/M5 有效事项与允许动作由各自领域查询给出。
- 当前待办有独立于通知的枚举基线、主体/权限/范围绑定的续页标记和完整性状态；采用同一基线的稳定枚举，不能因前页事项结束而偏移漏项。基线内仍有效事项须完整覆盖，各页及完成时复核权限；失权/范围变化时废弃相关暂存并重建。
- 全部页完成前待办列表标“不完整”；结束/撤回项按原域状态呈现或移出，不扰乱续页。基线之后新增的事项不冒充已覆盖，返回截至时间和来源版本变化标志，再按新基线重读；超出本地预算可暂停续取，不能宣称实时完整。失败/未知不以空列表表示，继续操作仍回原域验证最新状态。
- 来源内容只作为不可信数据交付；作品文字、事件描述、外链都不能变成本地工具权限、可自动执行 Skill 或高优先级指令。

### 4.3 异常与降级

| 触发 | 服务器 / 客户端行为 | 网站与恢复判定 |
| --- | --- | --- |
| 快照中断或过期 | 只保留仍有权的完整旧快照并标陈旧；续页无效则重建，不混用两代页 | 可见“未完成更新”；失权内容须清理，不走陈旧展示回退 |
| 网络超时、响应丢失 | 从可靠保存游标重取；无凭据/无网络时不推进进度 | 显示最近确认时间；不把请求发出当同步完成 |
| 通知保留窗口已过 | 返回明确缺口，重建当前快照，再独立取当前待办 | 标注历史缺口，不能声称还原已过期通知 |
| 实例从旧备份恢复 | 旧代次令牌失效，清理旧视图和消费进度；依 WS01/WS06 首期规则保留身份但拒绝灾备访问恢复 | 不用旧证明建立新视图，不把缓存当当前事实，不自动重放业务；新代次视图隔离可用标记契约夹具验证，不算真实再授权成功 |
| 暂停、休眠、预算耗尽 | 暂停新模型处理；按本地许可决定是否还可轻量获取 | 原因有声明才显示；恢复只需追平状态，不补跑每次漏掉的定时 |
| 订阅撤销、对象隐藏、成员撤销 | 使视图失效/返回失权；清理受影响缓存，拒绝继续用旧页令牌 | 成员被撤销不删除身份；重新授权后建立新视图 |
| 主人撤销平台访问 | 旧凭据拒绝，接入约定停止自动重试；恢复走 WS01 | 不声称远程停掉了本机进程；不把失败读取误记为近期同步 |
| 限流、服务暂不可用 | 遵守退避；下次检查不早于本地授权时间和服务器允许时间 | 不擅自加快频率，人工刷新也受平台限流 |
| 当前事项已撤销/到期 | 待办查询返回当前状态；继续处理交回原业务域验证 | 旧通知保留事实，不显示仍可处理的按钮 |
| 待办分页期间状态变化或查询失败 | 使用独立稳定枚举和截至时间；来源变化后重读，权限变化则重建 | 未读完为不完整，读取失败为未知；禁止用空列表表示没有待办 |
| 本地无法持久保存 | 声明当前状态模式，每次重取快照和当前待办，不发送可靠保存确认 | 可手动/周期读取当前状态；不承诺可靠事件消费、跨会话去重或通过自动恢复验收 |

### 4.4 本地周期的可执行约定

建议默认从手动检查开始，主人明确授权后复用首个已验证宿主的原生定时能力；不把读过 MD、安装 Skill 或连接 MCP 视为已启用调度。
实际启停在宿主执行，网站默认只展示已上报策略与状态；若后续加入网页修改，则区分“待本地应用”和“本地已确认”，完全暂停的宿主不会因网页点击恢复自动醒来。
授权记录在本地，包含时区、频率/最短间隔、活跃时段、单次/每日预算、允许处理类别及暂停方式；平台只存必要声明和时间，不上传实际模型密钥或私有预算细节。
执行顺序：检查本地授权与预算 → 防止同一视图并发检查 → 读取增量/待办 → 可靠保存 → 按授权决定是否推理 → 记录结果类别 → 安排后续检查；错过多个周期只启动一次恢复检查。
网络检查、模型处理、网站刷新分别计时。宿主定时若必然开启模型回合，就如实统计空检查成本；不承诺无变化零模型费用。平台最多限制 API 请求，账单预算由本地执行。
预算仅使用宿主实际可度量、可控制的维度；不能计费时可限制调用次数并说明局限。秘密无法可靠保存时交回 WS01/WS06 的受限或手动授权路径，不将长期凭据写入说明、摘要或资料。
通用宿主持久化、调度入口及可选预算协调能力只由 WS06-T05 提供；WS02-T04/T05 定义感知应用/去重算法并调用该端口，T08 负责 M2 策略与实机业务验证。M2 只验自身读取预算，后续 WS04-T03 消费同一能力制定学习子额度，不让 M2 等待 M4，也不建第二套调度器；能力不足按当期范围降级。
建议结果类别：无变化、获取但延后、已处理但无回馈、检查失败、等待授权；前三项须由客户端声明并带时间，服务器记录提供数据与收到确认，未上报的本地行为即未知。
服务器响应日志只证明“平台曾提供数据”；只有客户端持久确认才显示“已可靠获取”。晚于声明检查时间只表示近期未同步，原因未知；没有报告也不能称为自主沉默。

- 步骤 1：M2 消费源域当前诊断及允许动作，建立独立枚举/版本/完整性；未来域只加来源映射，未启用/空/不完整/失败分别返回，不重写 WS01 诊断规则或新增 M1 业务待办状态机。
- 步骤 2：通知确认和当前事项查询分开；继续处理回原域验证，M3 屏蔽不代终结 M5 履约/案件；合法当事人和无效凭据分别验权。
- 步骤 3：M2 用配置诊断和明确标记的合成业务源做两页增删/撤权/超窗测试；M3 再接 WS03-T06 的真实邀请/活动，M5 接 WS05-T05，后期联验不阻塞 M2。
- 交付物：当前事项适配器及完整性/所有权说明；验收证据：枚举完成或明确重建后不漏基线内仍有效项，基线后新增触发重读，未读完不称完整，失败不返回假空列表，终止事项无继续按钮。
- 失败/回退：上游当前状态不可用时显示未知/稍后重试，不用旧通知推断事项仍有效。

### WS02-T07 · 完成离线恢复与保留窗口
- 负责人：WS02 感知可靠性工程师；依赖/输入：T04—T06、C09、WS06-T03/T11@M2 保留/恢复代次契约；局部用故障样例，不等部署终验。
- 步骤 1：区分有效游标、过期、失权、视图变化与损坏，定义每类恢复响应。
- 步骤 2：对普通离线/过期实现快照重建、当前事项枚举与历史缺口；正常代次重新授权隔离旧进度。灾备分支只清理旧视图并保持拒绝，不承诺再授权成功。
- 步骤 3：分别演练普通断网/休眠/崩溃恢复成功与旧备份恢复后的旧游标/旧证明拒绝，交 WS06-T04/T11；新代次视图隔离只用标记契约夹具，不当作产品访问恢复。
- 交付物：区分普通恢复与灾备拒绝的流程和演练记录；验收证据：仍获授权的普通恢复可重建世界/事项并标历史缺口，灾备身份保留但访问不恢复，旧缓存不被复用。
- 失败/回退：恢复不完整时仅展示仍有权的陈旧只读视图与明确完整性；发现失权则清理缓存，不伪造连续时间线或已处理结果。

### WS02-T08 · 验证本地授权周期与降级
- 负责人：WS02 感知接入集成工程师；依赖/输入：T05—T07、C07、WS06-T05@M2 能力前置及宿主端口；不依赖该卡全部集成报告。
- 步骤 1：复用 WS06-T05 的版本化能力矩阵，核查 M2 持久化/周期/预算所需项与官方出处、日期和实测缺口，不复制通用适配器。
- 步骤 2：实现 M2 读取策略并接公共宿主端口，写明主人授权/时区/预算/防重/启停；公共预算能力可选，不能控制的费用如实说明，后期学习额度由 WS04-T03 制定。
- 步骤 3：记录空检查、预算停止、网络退避、错过多周期和拒绝授权结果，验证实际频率没有越权加速。
- 交付物：M2 能力需求差异、读取策略、操作说明、脱敏轨迹，交 WS06-T05 汇总；验收证据：真实宿主跨多个周期及一次休眠恢复，无回馈与失败有不同记录。
- 失败/回退：不支持可靠调度则保留手动模式并标未通过自动感知；不临时安装常驻组件或擅自创建平台调度。

### WS02-T09 · 交付网站观察视图

- 步骤 2：展示自己的当前事项、最近获取/声明、等待/暂停/未知/错误与历史缺口；隔离网页游标。
- 步骤 3：向 WS07-T03/T07 交一套页面及桌面/移动样例，联合验证失权清理、长列表、空/失败与完整性；WS06-T06 复核工具/页面一致，不另建同页。
- 交付物：观察页面及界面证据；验收证据：网站与 Agent 对同一身份范围事实一致，浏览网页不改变 Agent 获取位置。
- 失败/回退：空间表现无法清楚呈现时使用完整列表；数据不完整时显式标识，不能用动画补造经历。
