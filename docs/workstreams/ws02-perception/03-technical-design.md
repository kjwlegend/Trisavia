## 2. 完整读取必须满足的技术条件

- 来源目录能枚举全部当前可披露且已启用来源；每个 source 拥有稳定 ref、type/schema、当前权限、稳定快照、水位与后续变化、详情／大内容分段及停用策略。只写一个 types 列表不构成可遍历的内容源。
- 快照页冻结同一来源集合及每源连续应用水位；投影内容和水位同提交。不可变页集或稳定来源 token 由技术总监评估，不能仅取最大 eventId 或在活表上 offset 翻页冒称完整。
- 一页或响应预算受限不缩小产品范围；续页明确到末页，按需详情能读完允许内容。概览计数不替代枚举，快照切点完整不等于所有正文／源端现在均完整。
- 首期全域视图不做部分来源 checkpoint 合并；任一启用源失败则该视图不前移。其他通道独立处理；未启用源不冒充成功空集或列入已完成覆盖。
- 快照完成后至 changes 之间有连续覆盖；仅分页会话过期时废弃本批暂存，changes 从最后可靠保存且仍有效的同通道 checkpoint 重读。只有 checkpoint 超窗才重建当前受权视图并报历史缺口；snapshot／discovery／current-items 分别重启自身枚举，后两者不推进数据通道断点。新来源上线使 sourceSetVersion 改变，重建纳入该源既有对象，不能只接以后事件。

## 3. 权限与可靠进度

每页／详情／内容续页／计数／引用重验当前身份、用途和权限。scope 省略默认全域而非扩大权限；consumerId、游标、公开 ID 和输入用途都不授权。绑定主人只能看当前明确获准的管理摘要，不能读取 Agent 全部私信。

对象、事件去重依据与最终 checkpoint 同次可靠保存；同一视图串行消费，迟回响应不覆盖新版本。快照未完保留旧完整视图和暂存；无可靠持久化时降级为当前状态读取。网页／Agent／用途及 world／inventory／inbox 各自进度独立。源撤回／失权及时隐藏无权标题、计数、引用和缓存；到期仍可历史阅读与失权不同。

token 服务端绑定实例／恢复代次、实际主体／消费端／用途、权限／来源／范围／协议及切点；pageToken 和 checkpoint 分工明确。单纯旧签名有效或缓存 TTL 未到，不能绕过当前判权。旧备份恢复不复活旧授权；普通离线与灾备拒绝分开。

人类本人列表状态由单独受权查询读取，合法无记录才返回版本 0；隐藏标记不从源枚举中排除对象，失权／不存在不返回旧标记或默认态。写入先判当前权限与原操作回执，再检查预期状态版本；同键同载荷回原结果，冲突后查询并重新决定。状态与结果原子保存，与 Agent 消费断点隔离；内容版本和状态版本分开，完整合同及两页冲突／丢响应轨迹只见接口合同 §7。

## 4. 模块发现与本轮界面

最小来源／schema／说明目录是本合同的读取前置，可复用未来 WS06 机器目录；不要求先实现完整模块安装机制。新业务自己维护公开合同和 source adapter，WS02 通用读取器不按模块名分支；不懂关键语义就报不支持，不自动下载代码或 Skill。

本轮背包、信箱的状态只在明确演示模式下验证，不能污染真实身份进度。世界 HUD 回动态画布、关闭内容窗；去掉编造事件列表，保持原世界动画／Agent 视觉呈现。不写渲染器重构、真实在场、自动行动或服务器外部调度。
