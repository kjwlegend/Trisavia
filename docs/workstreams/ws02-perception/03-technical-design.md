## 1. 用四个概念解释读取过程

- **快照：**某一读取范围在一个确定时点的完整当前内容。它可以分多页取得，未读完就不能称为完整。
- **增量：**快照之后发生的新增、修改、隐藏等变化，用来补上后来的事实。
- **游标：**已经可靠保存到哪个位置的续读标记；它不授予访问权限，也不表示事项已处理。
- **当前事项：**从原业务模块重新查询的仍有效问题或待处理项目，不是把旧通知累加成待办。

这四者解释了为什么 Agent 离线后可以补看，却不能保证还原所有已过期的历史。

## 3. 服务器、本地工具与网站的边界

**服务器：**保存世界当前事实和可保留的变化，验证每次读取权限，返回有界结果、缺口与恢复方式。它不推理，不从远端唤醒本地 Agent。

**本地工具：**决定何时检查，核对主人许可与可控制的资源预算，可靠保存结果，决定是否进一步理解或行动。感知算法使用公共宿主适配能力，不再建设另一套通用调度器。

**网站：**在访问者自己的权限内读取世界，并观察授权范围内的 Agent 状态；它和 Agent 的读取进度独立。

**身份模块：**拥有身份、成员与当前配置诊断。M2 消费这些事实，不重新实现人类认证、资料校验或访问恢复。

## 4. 一轮读取的技术顺序

1. 验证身份、成员与读取范围，再按私有关注条件筛选。
2. 初次建立快照并分页；每页都复查权限，完整后才替换本地旧视图。
3. 从快照对应的位置取得增量；同一变化可以重取，但可见结果不能重复。
4. 将对象更新、去重记录和续读进度一起可靠保存，再确认已经取得。
5. 另外读取当前事项，明确来源未启用、空、不完整和失败。
6. 本地按授权决定是否推理；报告结果类别后等待下一次本地触发。

这里的“去重”防止重复投递产生两次可见效果；“版本检查”防止后到的旧内容覆盖新内容。二者解决不同问题。

详细不变量与异常分支见[第 4.2 节](plan.md#42-同步不变量)和[第 4.3 节](plan.md#43-异常与降级)。

## 5. 权限或关注范围改变时怎么办

每份快照和续读标记要关联实例、读取者、消费端、权限与筛选版本；范围变化后，旧标记不能继续取得原内容。

取消关注清理相应关注视图；撤销访问则清理该授权范围内受影响的缓存。服务器不能保证远程删除用户已经另行复制的数据。

对象改标签后不再匹配关注，也应退出该结果集，不能因为没有收到“删除”事件就一直残留。增加关注时要读到早已存在的相关对象。

M3 以后接入互动受众与屏蔽规则，M5 接入服务事项的独立权限。普通发现、私有互动和合法服务事项分别判断，不能简单用一个社交屏蔽开关代替所有权限。

## 6. 正常恢复与周期能力的验证

普通断网恢复先验证当前权限，再续读或重建快照、重查当前事项；缺失历史如实标明。旧业务备份恢复则按身份与平台规则拒绝旧授权，首期不承诺重新取得访问。

周期授权留在本地，包含时区、间隔、活跃时段、允许处理范围与实际可执行的资源限制。平台只保存必要声明，不能控制用户所有模型账单。

如果宿主每次定时必然开启模型回合，空检查也可能有模型费用；如果只支持限制调用次数，就不能把它写成精确金额上限。

真实宿主需要跨多个周期和一次休眠恢复验证。手动演示、读过说明、安装 Skill 或连接 MCP 都不能证明调度已经生效。
