# WS02 核心模块与依赖评估

日期：2026-10-19 · 技术总监 · 评估稿 v0.2。

**Agent 应能完整遍历当前有权读取的整个世界，并在之后可靠取得变化。**总览帮助理解世界，统一目录与同一详情负责读取，完整快照分页负责遍历，增量与恢复负责续读。附近、搜索结果或若干演示条目只是阅读视图，不能替代完整感知能力。

本轮分为两项：WS02 完整规划真实感知接口，技术总监评估最小结构与依赖；现有网页演示背包、信箱与返回动态世界的 HUD 获准实施。**真实 M2 后端、真实消息／资产写入及通用模块运行机制不在本轮实施范围。**WS02 保有业务和接口原件，WS07 负责 M2 内容设计，WS06 负责共享架构／世界引擎评估；本文不代写这些原件。

## 2. 最小结构与依赖

下面是逻辑职责，沿用当前 Fastify、应用服务、存储端口和来源适配的组织方式；不要求拆进程或增加一套通用框架。

| 职责 | 输出与依赖 | 边界 |
| --- | --- | --- |
| 当前阅读上下文 | 经 WS01 验证的主体、用途、当前权限及范围版本 | owner 管理权不自动成为 Agent 私信读取权；公开 ID 不是授权 |
| 世界总览与可发现来源 | 当前允许发现的类别、来源、覆盖情况、更新水位及下一步入口 | 未知／失败不能写成零；聚合计数也须判权 |
| 统一目录与同一详情 | 稳定引用、合法摘要、来源版本、按需详情 | 来源拥有正文与业务事实；目录不授予持有、产权或执行权 |
| 完整快照遍历 | 当前授权世界各来源的固定读取边界、有限分页和完成条件 | 搜索／附近视图不充当全部；单页不是完整世界 |
| 增量与离线恢复 | 各来源进入、修改、移出、重入及缺口／重建语义 | 分页位置与增量断点分开；失权后不能继续显示旧缓存 |
| 信箱与当前事项 | 合法投递的内容；原业务当前可处理事项 | 看过不等于接受或完成，提醒不维护第二套订单状态 |
| 背包读取 | 各合法持有来源的投影、详情及自己的续读进度 | 目录可见不证明拥有；无持有源不造真实库存 |
| 客户端保存与观察 | 各消费者保存点、平台事实与客户端声明 | 人类网页、Agent、消息、背包和不同用途的进度不互相推进 |

建议依赖顺序为：**权威身份／当前权限 → 来源与总览 → 统一目录／详情 → 完整快照 → 增量／恢复**。信箱、背包分别接合法来源及自己的进度；将来模块发现复用具名来源／能力声明入口，不成为读取既有世界的前置。具体端点、字段、错误名和业务范围由 WS02 原件定案，本文只提出可实施约束。

## 3. 完整读取需要满足的约束

### 3.1 总览、目录与详情

总览应说明本次覆盖哪些获准来源、各来源可读／滞后／失败／未启用状态，以及如何继续遍历。不能从总览摘要推断正文已经读取。目录与地图引用同一对象；地图动画、显示坐标和自有 Agent 漫游不产生真实行为、在线或空间权利。

列表、计数、缩略图、关联与详情都在服务端按当前用途判权，不能先下载全世界再在客户端隐藏。已知 ID 的公开资料访问和目录发现是不同入口，不能为了新目录顺手改变 WS01 现有公开资料语义。外部正文、附件与模块说明均按数据处理，不是系统指令或工具授权。

### 3.2 完整快照及来源扩展

完整遍历不要求一次返回所有内容。每次遍历固定当前主体、用途、权限／范围及各来源读取边界，使用有界页逐步走完；每页重新验证权限。必须有可判定的来源完成和整体覆盖状态，不能因预算耗尽、某页为空或一个来源结束而宣称整个世界读完。

首期按 WS02 选择采用整视图末页 checkpoint：world 视图保留各来源固定水位及状态，但不把它们当作可独立提交的断点。任一 world 来源失败，本次 world 不提交新 checkpoint，仍从原有效点恢复；信箱、背包等独立通道可各自继续。只有本视图所有必要来源／页面已完整取得并可靠保存，才提交该视图的新 checkpoint。遍历期间新增／变更内容与后续增量的交接须无静默缺口；若源不支持一致快照，就明确其一致性限制与重扫规则，不能假称某一瞬间的完整世界。

首期建议采用服务端持久读取会话与不可变摘要页集，而不是对活表反复 offset 分页。各来源适配器须给出可连续覆盖的投影／切点；页集与其来源水位一致固定，外部读取不长期占用数据库事务。这里只固定获准摘要及稳定引用／版本，不复制全部大正文；详情仍按当前权限按需读取。来源尚不能给出稳定切点时就报告该来源不可完成，不靠最大事件号拼出快照。页集大小、构建预算、保留期及过期重建在真实来源规模明确后实测，不先承诺无限快照。

未来来源增加或退出时，要能发现目录版本变化和新来源的初始快照要求。模块声明只公开经批准、当前可发现的能力及可解析的版本化 schema／使用说明，不能靠客户端猜路径；发现不等于允许调用写动作。采用 WS06 的具名声明边界，不先建设任意插件执行器。

### 3.3 增量、进度与离线恢复

完整快照的分页位置与完成后增量断点不是同一概念。进度绑定实例、主体、用途、权限／范围、视图的来源集合及必要版本；客户端只有将该视图全部必要页面数据和对应进度可靠保存后才推进末页确认点。重试、响应丢失和重叠批次不能吞内容；移出某视图不等于原对象全局删除。

超出保留窗口时重建当前状态并说明历史缺口，不假称已补齐离线期间全部经历。权限或范围变化使旧续页不可继续时，要给出明确重建路径；已撤权私密内容先失效，不等待后台副本慢慢刷新。当前事项仍回原业务查询，不能只依赖历史提醒。

续页和断点首期建议使用服务端保存绑定信息的随机不透明引用，分别记录类型与有效期，复用现有实例／恢复代次检查；不在客户端塞入可修改的授权字段。它们不是凭据，每次仍验证当前主体／用途／权限与来源集合。旧引用过期或灾备代次不符时按 WS02 错误合同重建；实现时另设窄读取仓储，不混入 M1 业务操作回执或凭据表。本轮仅提出实现建议，不创建表／迁移或签发 token。

世界、信箱、背包分别保存进度；网页人类读者和 Agent 的保存／已读／处理也分别记录。不可靠保存的宿主只承诺当前读取，不承诺可靠续读。主动访问间隔沿 WS01 已保存的期望值规划，但采用与实际执行必须有宿主证据；服务器不会因网页保存设置而自动唤醒本地 Agent。

## 4. 当前可复用与需要新增的端口

身份／用途校验、有效绑定与公开资料投影继续复用 WS01。确有设置或标记写入时可复用幂等操作号、版本冲突和精确回执模式；普通查询不必全部变成业务命令。命令提交回执仍不表示数据已可靠保存、已理解或业务已接受。

当前 store 的 `find` 读取后过滤，不直接承担可扩展的世界检索。真实 M2 实施时按获准查询补有界投影／索引端口及必要迁移，不让客户端筛全表。同步事务不容纳网络、模型调用、宿主等待或长时间分页；来源读取与短事务提交分开。同库不授予跨模块直接写表权限。

Agent 参考客户端已有私密来源校验、原子保存、写锁和原操作续接，可借其可靠保存方法；它尚无完整感知缓存、快照、增量或周期任务实现。HTTP／JSON 是协议，Node 是参考宿主；MCP 或 Skill 可以包装同一接口，但不自动带来定时能力。新的读取缓存与进度不写入原凭据 vault，也不复用部署恢复 epoch 作为普通增量版本。

## 5. 本轮演示 HUD 的实施边界

生产文件由原 Web 作者独占 `apps/web/public/**`；原 acceptance 作者负责针对性测试与隔离 QA helper。技术总监在独占 integration 顺序整合，全部新增代码交原独立 reviewer 固定 diff，普通用户模拟和 WS07 设计审查各自独立。

| 入口 | 本轮行为 | 不产生的事实 |
| --- | --- | --- |
| 背包 | 宽松游戏网格，作品／虚拟道具两种展示概念，左侧选择、右侧详情 | 不实现真实分类业务、库存授予或资产后端 |
| 信箱 | 私有通知／世界更新保留，主列表加附加详情窗，显式已读与未读、标记已读、删除仅对本读者隐藏并可确认或撤销 | 不删除源内容、不改变原业务、不推进 Agent 阅读 |
| 世界 | 关闭内容／附加详情窗并回到持续动态、可交互画布；保留漫游、高亮、hover／焦点姓名 | 不添加静态卡片、占位窗或编造活动流，不把视觉移动当真实行为 |

演示状态单设最小本地模块，按实际 origin、实例、稳定 owner、选中 Agent 和内容来源隔离，正文仍来自只读演示源。只持久化必要的筛选、选择、滚动和本读者标记，不持久化凭据、私密邮箱或真实业务副本。来源变化或正文不再可看时，仅从当前合法源投影可恢复状态，不能用旧详情补回被移除的正文。

登录读取尚未验证、退出、账号／Agent 切换时立即使旧上下文失效；异步响应与旧事件需核对上下文代次后才能生效。会话桥只从已验证账号／Agent 结果暴露只读稳定标识，不扩大原安全 summary，不增加账号／邮件／库存写接口。损坏或不可写存储应安全退回可用内存状态，不清其他 storage key。

关闭详情返回原筛选与列表位置，关闭重开和刷新后按当前上下文恢复。演示标签与动作结果要让普通人理解是本人的演示阅读状态，不声称真实消息服务已上线。M1 注册／接入提示、账号权限与实际源数据保持原语义。

## 6. 验证与交接条件

真实感知接口规划须由 WS02 原件给出允许／拒绝样例、完整遍历与终止语义、来源失败、权限变化、增量交接、重叠／丢响应、离线超窗和新模块发现的具体结果；技术与 WS06 评估其可实施性，不把文档存在记为真实服务通过。

本轮 HUD 只做必要的纯状态与桌面浏览器验证：各隔离轴、旧代次拒绝、坏存储、源记录保留；背包网格／详情、信箱阅读／隐藏／返回、重开／刷新、切换／退出，以及世界返回动态画布。桌面 1440×900 和 1280×800 的必要布局可达性纳入范围；手机、真实账户／邮件和旧全量回归未因此获准。
