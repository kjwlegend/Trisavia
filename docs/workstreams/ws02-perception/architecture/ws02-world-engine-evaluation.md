# WS02 最小世界引擎评估

原评估：2026-10-16；本轮补充：2026-10-19。负责人：WS06，独立于技术总监。当前状态：**固定文档范围的规划R2修订复核通过，IR2-01／02均verified，根R3待进行；准确范围与指纹见[第11节](#r2-recheck-20261019)。**不表示真实接口、后端、代码或UI验收通过。第9节保留当时准备记录，第10节保留首次R2的两项发现及待修结论，不追改历史证据。WS02负责业务／完整感知接口规划，WS07负责M2设计，技术总监另写 `ws02-technical-evaluation.md` 并协调已授权UI实现，本文件不代改其原件。旧版下述D1—D4仅保留历史问题归属，当前决定以WS02固定稿为准。

## 1. 结论与依据

建议把最小世界引擎理解为：**保存有来源的世界资料，按当前权限提供能完整遍历的全域目录、详情和变化，让人和外部Agent读对同一件事。**附近／场所／类别是可选筛选，不能是唯一发现入口或用示例集冒充整个世界；完整遍历采用有界分页，不要求无限单包。先评估现有平台内的逻辑职责，不从动画推导实时世界服务器、物理或居民仿真。

这是事实支撑职责的评估名称，不是必须先造完的新系统。本轮后端只规划、不实现真实M2数据服务；规划必须交代全域覆盖，未来实施可按合法来源分片推进，不能以局部切片代替全域接口合同，也不等仿真或经济。

输入为 WS02 的[故事与四项待选](../discussion-brief.md)、[流程](../02-features-and-flows.md)、[技术边界](../03-technical-design.md)、[对象](../world-objects.md)及[信箱与感知](../mail-and-perception.md)。已交付基础的证据取[M1 MVP](../../ws01-registration/development/m1-mvp-delivery.md)、[主人体验修订](../../ws01-registration/development/m1-owner-experience.md)和[运行说明](../../ws01-registration/development/m1-mvp-runbook.md)；旧架构概览的规划状态不作为当前实现清单。这里没有新增运行验证或容量结论。

先服务两条故事：人能从可见入口查看有权内容，理解它是什么、现在怎样、接下来能做什么；Agent 隔一段时间回来，只补读相关变化和仍需处理事项，不补演离线期间的生活。用户主流程和技术接入分别表达，验收遵循[产品交付流程](../../../planning/product-delivery-workflow.md)。

## 2. 三个边界

| 部分 | 应负责 | 不能据此声称 |
| --- | --- | --- |
| 服务端世界数据 | 来源、稳定引用、当前版本／受众／权限、可遍历全域的有界查询、变化与读取记录；业务来源负责合法状态变更 | 一次响应不证明收全、保存、理解或行动；最近访问不等于在线握手 |
| 客户端地图与人类界面 | 在同一授权事实上组织场所、对象、列表、信箱与结果；展示演示、未知、失效和错误；把入口与故事接起来 | 动画人物、场所标签、展示位置不证明真实 Agent 移动、在场、聊天或工作；地图不授予物品/土地权利 |
| 外部 Agent 运行时 | 在本地主人许可及宿主能力下主动读取，可靠保存，决定是否理解、回馈或执行已授权动作；管理自己的触发频率 | 平台不远程唤醒、不替它运行模型，不要求所有电脑持续在线；网页看过不推进 Agent 进度 |

当前完整小镇合同和素材属于 M1 首页呈现，可使用明确标记的演示数据；它们不是已经存在的 M2 世界数据服务。相同权限/用途应取得相同来源事实，界面与 Agent 输出格式可以不同。

2026-10-19更正：世界始终动态，世界HUD关闭背包／信箱／详情等窗并返回可交互画布，保留动画、自有Agent视觉漫游／高亮／悬浮姓名；仅去掉编造演示动态列表，不新增静态世界卡片／占位窗。后续真实感知数据接入此世界，当前真实身份／资料、视觉动效与真实Agent活动分别表达，不能由动态图像推导后端或真实事件已存在。

## 3. 世界事实与合法来源

| 对象/内容 | 最低需要说清的事实 | 可复用或待交来源 / 边界 |
| --- | --- | --- |
| 人、Agent | 身份类型、稳定引用、允许公开的资料、资料版本与来源；位置声明另列来源/时间 | M1 Agent 身份及获准公开投影可作为接入起点。独立 human 公开存在需 WS01 合法来源；私密主人账户/绑定不因此公开，不从演示人物造真人 |
| 物品、作品 | 作品属于物品分支；标题/内容来源、作者声明、版本；登记、持有、版权与展示关系分开 | 先明确管理员或其它合法生产者。目录不等于背包，作品发表的真实生产不能由 M2 阅读旁路暗建 |
| 资产、背包 | 已获准的持有依据、读取主体、来源与适用范围 | D3 未定；缺来源写未启用，不能填虚假零余额。通用货币、转账、土地经济不继承 M1 注册或服务积分权限 |
| 空间 | 场所资料、展示位置、用途、管理权/所有权及各自来源 | D4 决定怎样建立真实场所/位置。地图坐标不是移动、签到、到访或占地记录 |
| 事件与状态变化 | 谁提供、何时声明、计划时间、实际结果/未知、状态与版本 | 计划时间已过不证明事件发生或完成；对象变更记录也不能替代原业务事实 |
| 原创消息、公告 | 自身正文、作者/来源、受众、版本和可读状态；外部对象引用可为空 | D2 未定；原创内容不必伪装成世界事件。M2 不提供任意私信、回复或接受诉求的生产旁路 |
| 派生提醒、当前事项 | 提醒追溯合法来源；当前事项按原业务当前状态枚举，各自说明范围/完整性 | 一场活动的公告/提醒不变成多场活动。已读、获取、保存、接受、业务完成分别记录；M3/M5 未启用时不伪造其待办 |

“世界引擎”不成为所有对象的万能写入口。资料登记、原创内容、互动接受和履约仍由对应领域决定与验证；当前只评估可读投影和变化如何消费。

## 4. 可见性、主动拉取与断续补读

最小可见性责任是按**当前主体、用途和范围**读取；主人管理、公开浏览、Agent 感知不共用一次宽泛授权。列表、摘要、正文、计数、地图聚合与信箱提示都要遵守同一边界，不能先给敏感标题/数量再在详情拒绝。

建议的最小读取闭环如下，字段名、API 与数据表由后续技术评估决定：

1. 重新验证当前身份／权限，允许不按距离截断的全域发现，也可显式选择空间、类别或关注范围。提供有界摘要、详情按需读；地图视口不决定Agent全部可发现范围，也不靠一次拉全再隐藏。
2. 初次阅读固定覆盖范围和一致截至点，分页给出完整性及结束依据；跨来源需说明各自水位／状态。换范围不能混用旧页，每页与详情复核当前权限，撤权优先于旧快照；范围失效时明确重建，不静默漏项后声称完整。
3. 之后读新增、更新与移出/失效；同一变化重复取得不变成重复消息，旧版本不覆盖新版本。对象不再匹配关注条件时也要移出该视图。
4. 消费端将本批实际取得的数据、去重依据与阅读进度一起可靠保存，再报告保存声明；失败保留原进度。同一消费视图协调重叠读取，网页和 Agent、不同用途各自维护进度。
5. 普通关机／休眠后先验权：窗口内补读，超窗则重建当前有权全域或所选过滤视图，说明历史缺口并另读当前事项；不会补跑错过的定时或执行过期提醒。

读取频率属于外部宿主能力和主人许可；先能正确处理手动及不规则间隔，再按实际宿主证据讨论可选周期。本轮不选定统一频率、不安装排程、不引入持续心跳。平台仅呈现最近请求/提供数据的事实和客户端有来源的声明；未更新原因不明时就保持未知。

频率评估看用户可接受的更新延迟、内容变化量、读取成本/限制及宿主可用时间。数据拉取、地图重绘和Agent决定是否行动分别处理，不能由画面每帧更新推导每帧读取世界，也不能把较频繁访问包装成真实在线。

到期、撤回、失权和取消关注必须区分：到期可关闭失效动作但按当前权限保留历史阅读；撤回/失权拒绝相应内容；取消关注只移出受影响视图，不宣布对象全局删除。重连先验权并处理缓存。普通断续读取不是灾备恢复；实例/恢复代次变化后的旧授权、旧进度按既有围栏处理，不能用全量重建复活旧权利。已被用户另行复制的内容不作可彻底收回承诺。

## 5. 状态怎样变成人能理解的结果

| 情况 | 世界数据应保留 | 人类界面应表达的结果 |
| --- | --- | --- |
| 资料更新或从视图移出 | 来源、版本及作用范围，区分筛选变化、撤回和失权 | 当前能看到什么；为什么这份列表已改变，能否重读/返回。没有依据时不猜对象被删 |
| 通知到期但仍有历史阅读权 | 原内容与到期状态、当前允许动作 | 可看历史、相关操作已结束；阅读不自动接受、报名或完成 |
| 一批读取尚未保存/结果未知 | 平台响应记录与客户端保存声明分开 | “尚未确认”“可继续读取/重试”；不把网页看过写成 Agent 已处理 |
| 活动计划时间已过、没有发生结果 | 计划时间与实际结果未知分开 | 明确结果尚未确认；不自动称活动已完成 |
| 演示人物移动或停留 | 演示来源与真实记录分开 | 就近用自然语言说明演示；不能生成真实居民经历、访问信息或收益 |

人类主流程无需阅读游标、协议字段、引擎内部评估或存储结构。技术接入说明可以表达必要续读约束，界面则给出对象、状态、结果与可行下一步。正文、作品和外链作为外部内容，不因系统投递而变成本地工具许可或系统指令。

## 6. 可复用能力与最低缺口

“可复用”指已有基础或模式适合评估接入，不表示 M2 可直接调用一个已经存在的接口。

| 已有基础 / 证据 | 复用方向 | 必须补足、不能继承为已通过的部分 |
| --- | --- | --- |
| M1 稳定身份、主人/运行访问分离、成员及限制轴、允许公开资料 | 提供真实 Agent 引用与当前权利来源，不重建一套平台身份 | 独立 human、世界对象及每种读取用途的可见性；公开投影不授权私有信箱 |
| 单服务、SQLite持久保存、事务／版本／精确回执模式 | 扩展目录和读取职责；合法写入尽量原子保存状态与变化依据 | 全域遍历／可选筛选、有界查询、稳定分页、变化保留／移出尚待实现验证；不依赖全表拉取作容量承诺 |
| 版本化 HTTP Markdown、独立 Node 客户端及私密本地保存/续接经验 | 复用接入、身份保存和失败恢复的约束与文档分层 | 世界数据与消费进度一起保存、重复/并行/超窗行为需要独立 M2 契约和测试；M1 回执不是 M2 阅读游标 |
| M1 页面与当前首页演示候选 | 复用可见入口、名单/详情、错误与返回的交互经验 | 地图展示不等于世界权威数据、实时在场或信箱后端；M2 设计由 WS07 负责 |

最少依赖是：全域发现及可选筛选的故事／PRD、合法生产者与当前权限来源、稳定引用／版本、有界读取／保存约束，以及真实、演示、空、不完整、失效、失败的表达。不能以未来架构未完阻塞评估，也不能把演示切片记为M2真实来源完成。

## 8. D1—D4 仍决定什么

| 待定项 | 对最小引擎的影响 | 评估时可以做 / 不能代定 |
| --- | --- | --- |

## 9. 本轮独立R2核对框架（待固定稿）

收到总指挥提供的WS02接口规划与技术总监技术评估后，再登记各自固定文件／版本／提交或内容指纹及准确审查范围。当前只准备下表，不评判尚未收到的稿件，也不预填PASS。以现有平台数据所有权、独立用途进度和模块合同边界为约束，不替作者选API字段或改其正文。

| 核对点 | 固定稿必须能回答／提供的场景证据 |
| --- | --- |
| 全域发现与有界读取 | 不依赖距离、视口或硬编码示例即可遍历全部有权对象／来源；说明分页／详情绑定和终止依据，限流／单页上限不等于永久截断总覆盖 |
| 完整性与快照一致 | 说明覆盖的类型／来源／范围、快照或各源水位、页间增删及目录变化；明确完整／部分／不可用，不能把某源失败或一页读完记为整个世界收全 |
| 当前权限变化 | 每页、详情、摘要／计数与缓存按当前权限；撤权优先旧快照，主体／用途／范围改变后旧游标拒绝或明确重建，不漏私有字段、不以重建复活旧权限 |
| 独立游标与可靠保存 | 区分分页位置和持久增量断点；人类／Agent、世界／信箱、不同用途／范围独立，保存失败／重叠读取不错误推进，网页已读不代Agent读完 |
| 增量更新与移出 | 新增／更新／撤回／失权／不再匹配筛选均有移出或明确重建语义；重复／乱序不复活旧对象，移出视图不伪称全局删除 |
| 长离线与恢复 | 保留窗口内续读，超窗明确历史缺口并重建当前有权视图／查询当前事项；实例或恢复代次变化使旧状态失效，不补执行过期事件 |
| 模块可发现 | 能发现当前允许的已启用模块及可解析的合同／schema／入口版本，不靠核心硬编码示例；发现查询与业务执行授权分开，模块停用／版本变化有明确结果 |
| 事件不是执行指令 | 事件／消息／作品及外链是来源数据，不自动变成工具调用、系统提示或M3／M5执行许可；平台不唤醒外部Agent，期望间隔不冒充宿主调度 |

### 10.2 具体问题与修正要求

#### WS02-IR2-01 · P2 · 人类状态缺少可调用的读取／冲突恢复合同

**位置：**[接口合同](../world-perception-api.md) §3 L33—41、§6 L171、§7 L177；关联[信箱业务](../mail-and-perception.md) L21—25、L31。唯一HTTP清单只定义 `PUT /reader-state`；`stateVersion/contentVersion/read/hidden` 仅在写入返回中列出，snapshot／detail未约定本人状态投影，也没有另一个读取方法。L177却要求发生 `409 reader_state_conflict` 后“重读本人状态再决定”，错误封套也没有当前状态。

**反例：**同一人类读者的两个页面最初均持有 `stateVersion:0`。页面A标记已读成功，服务端变为1；页面B以0请求隐藏，按合同得到409。B无法通过合同中的任一已定义请求取得最新的1及当前read／hidden，因而无法按约定重新判断再提交。重新打开没有本地状态的页面同样不能读取已经保存的真实已读／隐藏状态；把初始0当作现存状态会持续冲突，盲猜版本又违反不覆盖要求。本轮隔离演示的浏览器存储不能填补未来真实接口的缺口，设计也明确不把演示记录迁入真实信箱。

**修正要求／owner：**由WS02在唯一接口合同明确人类本人状态的读取方式，可选独立读取或明确挂到现有合法读取响应；给出输入、当前授权、返回状态／版本、未创建状态及隐藏项的读取语义，并让人类发现目录／schema能定位。串联“读取→条件写入→409→重读→重新决定”的实际请求响应，说明响应丢失后同operationId重试如何取得原结果，不能依赖猜测状态版本。保留当前权限检查、内容版本标记与Agent进度隔离；无须增加通用状态平台，也不要求本轮接入真实后端。TD仅在其技术建议受修订影响时同步。

**待复验：**两个页面的0→1冲突例、无本地状态重开后读取本人已读／隐藏、相同operationId丢响应续接，以及失权后不能借状态读接口泄漏对象存在。当前状态为open，未以示例UI通过抵消。

#### WS02-IR2-02 · P2 · page_expired的一律重建快照会跳过未提交增量，且不适用于独立读取面

**位置：**[接口合同](../world-perception-api.md) §3 L40／L45、§4 L53—56、§6 L165—166；[TD最新评估](ws02-technical-evaluation.md) L56—60按该错误合同续接。L165对所有读取会话的 `page_expired` 只给“重新快照”，没有按原操作恢复；合同同时要求未保存整批不能推进checkpoint，且current-items不能放入snapshot的三个通道。

**反例：**客户端已可靠保存C0，开始 `changes(C0)`，只暂存了本批第一页，续页会话过期，但C0及其之后的变化仍在日志保留期内。按L165改读当前快照并保存新C2，只能得到对象现状；例如仍获准交付的v2、v3两条变更会缩成快照v3，尚未提交的v2记录被越过，之后从C2也不会补回。这里失效的是分页会话，不是C0或变化保留窗口。另一个直接断链是 `current-items` 续页过期：该读取面不能调用 `snapshot(channel:current-items)`，而调用world快照又不能重获原域当前事项。

**修正要求／owner：**WS02按调用操作定义恢复：snapshot重新开始快照；changes废弃过期枚举的暂存，从最后可靠保存且仍有效的checkpoint重新发起同通道增量；只有该checkpoint也过期时才走cursor_expired的当前状态重建与历史缺口。discovery／current-items重新开始各自的稳定枚举，不混用world快照／断点。可沿用现有路径和字段，无须新增会话架构；TD核对其“旧引用过期按WS02合同重建”建议是否需随之明确。

**待复验：**C0仍有效但增量pageToken过期时保留连续覆盖；C0也过期时明确历史缺口；current-items／discovery过期后仍从原读取面重启且不推进world／inbox／inventory进度。当前状态为open。
