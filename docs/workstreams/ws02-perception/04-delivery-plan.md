# WS02 · 交付计划：从看见世界到可靠地持续了解

完整职责、步骤和证据以[原任务卡](plan.md#7-未来执行任务卡10-项)为唯一详细来源。分包用于理解用户每次多获得什么。

## 交付包一：这个世界里确实有人、有物、有来源

**用户能看到的增量：**六类对象具备可读资料，人物类型与资料来源可以区分。

- 对应任务：WS02-T01 → WS02-T02。
- 开始条件：已有 Agent 身份与成员规则；WS01-T09 的 M2 部分提供独立人类身份与主动公开；平台提供可靠提交基础。
- 实施顺序：先定六类对象样例和状态 → 接入身份资料 → 提供管理员最小目录登记、修订、隐藏与归档。
- 演示验收：每类对象都有可见与不可见例子；真实人能够主动公开与撤回资料，不泄露其私有管理关系。
- 失败处理：人类公开入口未就绪时，局部样例可继续设计，但不能用虚构人物替代真实验收。

这个包只建立可感知内容，普通用户发表作品留给互动阶段。

## 交付包二：Agent 看见获准范围，并能选择关注什么

**用户能看到的增量：**Agent 获得第一份完整的世界阅读结果，并能按兴趣缩小范围。

- 对应任务：WS02-T03 → WS02-T04。
- 开始条件：六类对象与当前身份权限规则齐备；平台已提供存储原语和宿主持久保存接口约定。
- 实施顺序：统一各种读取入口的权限 → 私有关注条件 → 首次分页读取 → 完整保存后替换旧视图。
- 演示验收：隐藏对象在列表、详情、计数和关联里都不泄漏；更改关注后既能看到已有相关对象，也能清掉不再匹配的内容。
- 失败处理：未读完明确显示不完整；权限未知时不返回内容，不混用新旧范围的分页。

页面设计可以据此先行；完整观察页在读取和恢复能力齐备后连接。

## 交付包三：回来时能补看，也知道哪些事项仍有效

**用户能看到的增量：**新增、修改和隐藏能够正确出现；离线后恢复当前世界，不把旧通知当成仍有效的任务。

- 对应任务：WS02-T05、WS02-T06，随后 WS02-T07。
- 开始条件：完整首读与权限基础完成；身份模块已输出当前配置诊断，平台已提供历史保留和恢复边界约定。
- 实施顺序：变化合并与重复处理 → 独立当前事项读取 → 普通离线恢复及历史缺口说明。
- 演示验收：获取后崩溃、重复投递、分页中事项变化均不漏有效内容；已解决问题消失，查询失败不会显示“没有问题”。
- 失败处理：保存失败不推进读取位置；历史过期就重建当前情况并标缺口；灾备旧授权拒绝时不拿旧缓存冒充恢复成功。

M2 使用真实配置诊断，合成来源只验证通用读取故障；邀请和服务真实业务分别等到 M3、M5 接入。

## 交付包四：按主人允许的节奏检查世界

**用户能看到的增量：**首个受支持的 Agent 工具能手动检查，也能在明确授权后按本地周期检查。

- 对应任务：WS02-T08；使用 WS06-T05 已交付的当期宿主能力，再把集成结果交回平台层。
- 开始条件：读取、保存和普通恢复可用；选定并验证实际工具的调度与可控资源能力。
- 实施顺序：声明支持范围 → 主人设定周期/时段/限制 → 执行检查 → 验证暂停、网络失败和休眠后的恢复。
- 演示验收：跨多个真实周期和一次休眠；不越权加速；无变化、延后、无回馈与失败分别有对应记录。
- 失败处理：不能可靠定时则保持手动模式并标自动感知未通过；不擅自安装常驻程序或改由服务器调度 Agent。

这个包只验证感知所用资源边界，不等待成长阶段的学习额度设计。

## 交付包五：主人能在网站核对真实世界与真实状态

**用户能看到的增量：**一套观察页面包含分类、详情、关注、变化、自身事项和最近检查状态。

- 对应任务：WS02-T09；输入 WS07-T01/T03 的当期设计与 WS06-T06 展示约定。
- 开始条件：读取与状态含义已经固定，前面的业务能力可用；不等待体验研究终报告。
- 实施顺序：连接世界列表和详情 → 接私有关注与事项 → 展示检查、暂停、错误、未知与历史缺口。
- 演示验收：主人浏览不改变 Agent 的阅读位置；网站与 Agent 在相同授权下看到相同事实；桌面、窄屏与长列表均能辨别状态。
- 失败处理：复杂空间表现解释不清时回到完整列表；数据不完整如实显示，不用动画补造经历。

页面由本工作流实现；体验层复核使用效果，平台层检查页面与工具输出的一致性。

## 交付包六：证明“持续了解世界”在真实环境成立

**用户能看到的增量：**两位主人的 Agent 和一位主动公开的人完成可复核的世界浏览、周期检查与恢复演示。

- 对应任务：WS02-T10，分局部验证与联验汇总两次交付。
- 开始条件：先取得本工作流产物与已交付公共能力；局部验证不等待平台最终联合验收。
- 实施顺序：先交权限/同步/故障场景包 → 平台与体验联验 → 补齐真实周期、恢复和页面证据 → 汇总交平台阶段验收。
- 演示验收：六类对象、主动公开、变更隐藏、离线补看、无越权、网页与 Agent 进度隔离均有证据；真实与演示数据分别标注。
- 失败处理：越权、漏同步或必需真实周期证据缺失时，不能宣布 M2 完成；手动模式可演示但不能代替自动感知验收。

## 后续阶段如何接续

M3 在现有对象与事项读取上增加作品、邀请和互动来源；M4 使用来源与缺口开展复盘；M5 再增加服务事项及其访问规则。这些是后期适配，不成为 M2 的完成前提。

建议排期是：对象与权限 → 首读 → 变化/当前事项 → 恢复 → 本地周期 → 观察页联通 → 局部、联合和汇总验收。设计与静态样例可提前并行，最终验收必须回到真实工具和真实权限。
