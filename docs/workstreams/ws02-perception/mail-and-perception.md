# WS02 · 信箱、世界动态与独立阅读进度

2026-10-19 · IR2-01／02 作者修订，待原 WS06 复核。接口规划与现有信箱交互改进已授权，真实信箱／整套感知后端待授权。全部线协议统一到[感知接口合同](world-perception-api.md)，不在本页另造 URL。

## 1. 原创、派生与当前事项

| 内容 | 自己拥有的事实 | 如何继续 |
| --- | --- | --- |
| 原创来信／公告 | 自身 ID、正文、作者／发布来源、合法接收方／受众、版本 | 无外部对象也成立；正文由其来源判断当前阅读权 |
| 派生提醒／投递 | 投递自身 ID、受众、提示、所引用业务 sourceRef／版本 | 回原对象读当前状态，提醒不成为第二个活动／订单 |
| 当前事项 | 原业务此刻仍有效的问题、请求或允许动作 | 独立查询／分页，未通知或历史提醒过期也不能漏项 |

系统代发不冒充原创作者。世界公告与活动结果可在 world 动态筛选中出现；只有合法定向内容进入 inbox，关注标签不授发送权、不泄露谁订阅。任意人机私信／邀请／接受属 WS03，服务属 WS05，首批真实来源 D2 仍待选。

## 2. 三条不同进度与人类状态

| 状态／进度 | 产生者 | 不改变什么 |
| --- | --- | --- |
| 来源处理／展示副本水位 | 平台来源处理器 | 不证明客户端拿到或已保存 |
| 数据页与消费 checkpoint | 服务端签发候选位置，Agent 保存后才推进自己的本地位置 | 不证明人类读过、理解或业务已完成 |
| 人类已读／未读 | 当前获准人类阅读者；关联实际内容版本及列表用途 | 不推进 Agent、其他人类或其他用途的进度 |
| 人类列表删除／隐藏 | 当前阅读者自己的 inbox 或 world-news 列表 | 不删源事件／正文，不从世界统一目录删除，不关闭当前事项 |
| 业务接受／拒绝／完成 | 原业务在当前授权及版本下提交 | 不由开详情、清未读或删除列表项代替 |

world、inventory、inbox 分别有消费进度；网页、Agent 运行时和不同用途也各自独立。当前主人只可看明确获准的管理内容，绑定不自动授权 Agent 私信；输入公开 Agent ID 或同一主人名下另一 Agent 也不能串收件范围。

未来真实本人状态按[合同 §7](world-perception-api.md#71-本人状态读取与内容版本)独立查询：无本地状态重开先取得当前获准 ref，再读本人已读／隐藏和版本，未知不当作默认态；源枚举不因人类隐藏而漏项。合法目标尚无标记才返回默认版本 0，隐藏项仍可查；不存在／失权统一拒绝，不从旧标记泄漏存在性。条件写冲突后重读并重新决定，用新操作键提交；响应丢失以相同键和原载荷取原结果，不猜版本或重复写入。当前正文版本不同于已读标记版本则呈现未读，隐藏仍保持；这套真实状态不迁入本轮演示，不触及 Agent 进度。

## 3. 本轮可见交互

信箱主窗保留“私人通知／世界动态”→选择列表项→打开附加详情窗口→关闭回同一列表。详情展示可读正文、作者／来源、时间、是否演示及仍有效入口；不要求每封原创信都显示“查看源事件”。

打开可读正文或显式标记可设已读，用户能再改未读；只看列表摘要不自动算正文已读。重要新内容版本可重新未读。列表删除立即对该阅读者的相应用途隐藏，源修订不自动复活隐藏项；本轮按 WS07 设计提供 10 秒撤销，恢复本组原标记与排序，过期仅结束撤销入口而非删除源。计数只计算当前阅读者能看且未隐藏的相关列表，不混入业务待办数。

真实信箱未接时，以上都在明确标识的演示会话中验证。正常关闭／重开／刷新保持演示记录，按 WS07 设计隔离 origin、实际实例、经验证主人、当前受权 Agent 与来源／示例收件主体；访客另域，验证未完成不预显旧状态。退出／切换先清可见旧上下文，重新验证相同范围后可恢复。仅保存示例标记与必要界面位置，不存秘密或真实正文；存储失败才退为本页并提示，不清其他存储，不冒称跨设备或服务端持久化。演示不发送任何真实消息，不调用拟议 reader-state 接口冒充真实已读。背包详情同样不产生真实持有变更。

## 4. 到期、撤回、删除与失权

| 条件 | 正文和继续入口 |
| --- | --- |
| 提醒／动作到期 | 移除无效动作；历史正文仍按当前权限／保留规则决定，不一律拒读 |
| 源内容撤回 | 不再显示被撤标题／正文；只有存在性／最小历史信息获准才显示不可用说明 |
| 原业务已解决 | 旧信可按权保留，但当前事项不再给待接受动作 |
| 读者失权 | 后续请求拒绝、客户端获知后清相关缓存／暂存／提示；不能借旧 ref／count 泄漏 |
| 人类列表删除 | 只隐藏本人的列表项；源仍按其规则存在，Agent 和其他读者不受此状态改变 |
| 公开资料撤回／屏蔽 | 分用途回源，不自动删独立私信或已获准保留的履约／案件材料 |

## 5. 第一次与长离线回来

Agent 默认先完整遍历全域 world；自己的 inbox／inventory 按独立通道从首次快照开始。按需读正文、可靠保存后推进；不会因为主人网页已读／隐藏而丢消息。摘要已全不等于正文已全。

恢复先核对当前权限、来源／规则版本及自己的断点。仅增量分页会话过期时丢弃本批暂存，从最后可靠保存且仍有效的 checkpoint 重读同通道变化；只有 checkpoint 也过期才重建当前可读视图并标历史缺口。快照、发现目录和当前事项的续页过期分别重启自身枚举，后两者不改世界／信箱／持有断点；另查原业务当前事项，不能用缺失提醒判无待办。到计划时间不证明活动发生，通知无回馈不自动说明客户端故障。平台只能说明最近请求／提供数据和客户端声明，不能证明准确在线、持久保存或理解。

世界 HUD 点击关闭信箱及附加详情并回到持续动态画布；不打开静态世界面板，也不保留编造的演示动态列表。内容数据与画布动画是不同事实。所有外部正文、通知和链接不授本地工具／Skill 权限；规则和模块说明仅从可信版本化目录读取。
