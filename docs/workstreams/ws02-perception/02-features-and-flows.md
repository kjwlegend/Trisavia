# WS02 · 范围、读取流程与本轮界面行为

2026-10-19 · R1 候选。全域为默认，过滤为可选。接口规划和现有前端改进已授权，真实感知后端待授权。先读[故事](01-user-stories.md)，全部对象／来源见[全清单](world-objects.md)，具体 HTTP／JSON 只见[接口合同](world-perception-api.md)。

## 1. 全部范围怎样确定

默认当前实例 default 世界的所有已启用且获准来源；覆盖世界介绍／规则、来源／类型／模块、全部获准对象目录及其详情，不依赖当前视口、地图位置、已知 ID 列表或固定示例数量。无 filters 就是全域；用户主动设置空间／类型／标签后，完整性才限定到该过滤范围。

world 负责可见世界；inventory 负责本人持有；inbox 负责本人定向内容。原业务当前事项独立读取。世界动态是 world 的公告／活动／发生记录筛选，与私人 inbox 不合成万能流。三通道及人类／Agent／用途的读取进度均独立，订阅只筛选不扩权。

## 2. 第一次读全世界

可信接入入口 → 当前身份／实例 → 分页读模块／类型／来源与规则目录 → 全域概览 → 全域快照首页固定来源集合及每源水位 → 连续续页 → 本地可靠保存后替换完整视图 → 按需读详情或开始增量。

概览是导航与覆盖状态，不代替对象枚举；未启用、失败、成功为空和未读完分别返回。快照完成只说明目录在固定切点已覆盖全部已启用获准来源，不说明未来领域已存在、正文全部读完或所有源同一瞬间最新。要全文遍历可逐个 ref 取完全部获准正文分段，期间撤回则说明不可读。

## 3. 后续变化及新内容发现

从已保存 checkpoint 开始 changes → 固定本批目标切点 → 处理 upsert／remove → 整批完整且可靠保存后推进。同一对象版本防旧页覆盖；重复变化不重复应用。移出过滤、撤回或不再获准的旧内容不能永久残留。

目录 revision 变化 → 取更新目录／规则／说明 → 原来源的新对象走增量，新来源或影响覆盖的类型／权限／筛选变化使来源集合变更 → 全域重建，包含新来源中已存在的对象。未知类型能按已懂封套保存安全摘要，但不能假称读懂正文；未知关键变更操作不能跳过后确认完整。

## 4. 离线、失败与并发

| 情境 | 可继续的结果 |
| --- | --- |
| 普通断网／休眠 | 先验权；有效断点补读，不补跑每次定时，不编造生活 |
| 仅分页会话过期 | 丢弃该次未提交暂存；changes 从最后可靠保存且仍有效的同通道 checkpoint 重读，保留连续变化；snapshot／discovery／current-items 重启各自枚举，后两者不改数据通道断点 |
| 增量 checkpoint 超窗 | 同通道当前快照重建（默认全域，保留主动过滤）、标历史缺口，再查原业务当前事项 |
| 读到半页或保存失败 | 保留上次可靠位置，允许重取；没保存不能前进 |
| 来源暂时失败 | 本视图不发新完成断点、不伪装为空；其他独立通道可继续 |
| 页间权限／来源／过滤变更 | 废弃受影响暂存与旧续页，按当前范围重建 |
| 同 Agent 重叠检查 | 同一消费视图串行或有可证明的原子进度合并；迟回页不覆盖新版本 |
| 无可靠本地存储 | 只承诺每次重读当前状态，不宣称可靠历史补看／去重 |
| 实例或恢复代次改变 | 旧证明／游标拒绝，按现有身份安全流程处理，不冒称普通恢复成功 |

## 5. 背包与信箱的本轮交互

| 功能 | 业务结果与验收边界 |
| --- | --- |
| 背包游戏网格 | 格子选择→物品详情→返回网格；可表现作品／虚拟道具概念，不增加真实分类或持有生产。真实源未接必须演示／未启用，不填余额或库存 |
| 信箱两类入口 | 私人通知对应 inbox，世界动态对应 world 公开内容；切换保留可理解的列表与返回路径 |
| 附加详情窗口 | 从列表打开一封内容的附加窗口，关闭回原列表；不跳转成业务接受／完成 |
| 已读／未读 | 打开正文或显式标记可设已读；可改回未读。仅当前人类阅读者、内容版本与列表用途生效，不写 Agent 断点；未来真实状态可独立查询，刷新恢复及写冲突重读不依赖本地演示标记，详见接口合同 §7 |
| 列表删除 | 从自己的列表隐藏；不删除源内容／事件、不消除当前事项、不向他人广播已读／删除。新版本不自动复活隐藏项，按 WS07 本轮设计提供 10 秒撤销，恢复本组原阅读态与排序而不恢复已撤回源正文 |
| 演示交互 | 无真实信箱／背包接入时就近持续标识演示；按 WS07 设计正常关闭／重开／刷新保持演示标记与上下文，按已验证主体／实例／Agent／来源隔离；存储失败才降级本页并提示，不调用待实现后端伪造真实记录 |

## 6. 世界 HUD 返回动态世界

点击世界→关闭背包、信箱及其附加详情→返回原动态、可交互画布。去除原编造演示动态列表，不开静态世界卡／占位面板，不暂停画布动画。已有地图／列表选择同步、自有 Agent 视觉漫游／光圈／高亮／hover 或焦点显名保留，不扩大地图／漫游修改。原缩放／全景／场所／接入与用户暂停／减少动态等有效操作保留，位置由所属设计确定；世界按钮不重置原用户偏好。

持续动画是展示效果，不产生世界事实、在线证明、真实到访或经历。未来真实来源接入当前动态世界；“世界永远动态”不等于平台此刻已有真实 M2 事件。

## 7. 内容与权限不从阅读推断

原创信／公告可以有自身正文／作者／受众，无外部引用也成立；派生提醒必须可追溯来源。消息到期只撤失效动作，历史正文按当前权限／保留规则；撤回或失权拒绝相应内容。当前事项回原业务读取，不靠通知历史、未读或列表删除判断。

主人绑定不自动授 Agent 私信权限，公开 human 不公开主人账号。摘要、详情、计数、关系和资源链接同样验权；外部正文／系统通知不成为工具指令、可执行代码或本地权限。服务器提供数据、客户端保存、人类读过、业务接受／完成分别记录。最近请求不推断准确上下线。

## 8. 依赖与下一步

WS01 提供真实主体／当前授权及公开资料来源，不把已知 ID 的公开查询当目录。WS02 拥有完整目录、来源适配、读取／恢复和阅读业务；WS06 供公共事务／持久化机制，不代写领域规则。WS03／WS04／WS05 的合法公开内容或事项按来源启用接入，不为规划提前实现互动、成长、服务或经济。

WS07 维护背包／信箱设计，原设计总监保有世界壳，技术总监评估和实施已授权前端；本流不编辑其 design／architecture。任务切片和可执行验收见 [04](04-delivery-plan.md)。
