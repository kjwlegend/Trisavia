# M5 真实需求：按用户可见结果交付

状态：规划提案，尚未实施；已完成[本次阅读层复核](../../planning/readability-review.md)。原任务卡内容保留，本文按可演示增量组织交付。

## 先后顺序

了解真实用途并缩小服务 → 展示服务和需求 → 申请、选择与确认 → 交付、验收及异常出口 → 接通页面和真实宿主 → 无偿价值试验。积分是最后的条件分支。

按五阶段顺序进入时，前面阶段的当期流程应已可用；不要求成长效果为正，也不要求服务方拥有成长证书。

## 增量一：请求方能解释自己为什么需要这项服务

**演示结果：** 有一类明确服务、一份输入示例、一份合格或不合格成果示例，以及双方都能理解的验收条目。

- 原任务：WS05-T01。
- 实际顺序：WS07-T11@预研 先给同意、退出和最小记录规则，WS07-T10 做获准前置访谈；T01 再定义服务，之后才冻结正式试用指标。
- 验收：请求方能逐条判断结果；没有发现问题也能合格；知道使用自己的 Agent 或已有工具能否解决相同问题。
- 失败时：缩小服务类型或保留研究，不建设通用市场。

## 增量二：有人愿意提供服务，也有人能发布需求

**演示结果：** 阿禾发布审阅服务，小林发布活动说明需求；双方能找到彼此并了解获准的信息。

- 原任务：WS05-T02。
- 实际前置：T01；WS01-T01/T04/T06/T09 的身份与权限、WS02-T03–T07 的读取和恢复、WS06-T03 基础，以及 WS07-T06-D 的设计输入。
- 验收：公开摘要不泄露正文；暂停服务只禁止新申请；没有成长证据也能发布服务；需求实质修改使旧申请失效。
- 失败时：先保留简单类别与状态筛选；材料权限不能成立就不开放真实试用。

## 增量三：双方明确同意，才产生一次服务

**演示结果：** 多位居民申请，小林选中阿禾，阿禾再确认；只有一份固定约定生效。

- 原任务：WS05-T03、WS05-T04。
- 实际前置：T02；身份继续由 WS01-T09 提供，当前事项复用 WS02-T06，屏蔽事实取 WS03-T05，保存与回执复用 WS06-T03。
- 验收：读取需求不占位；被选中仍可拒绝；同时选择和重复确认不会产生两份服务；服务条目暂停不会偷偷取消已有申请。
- 失败时：状态一致性不能证明就关闭承接，保留只读发现；不改成客户端抢单。

## 增量四：能交付，也能处理不满意和无法继续

**演示结果：** 阿禾提交成果，小林验收或提出一次返工；双方能理解离线、延期、取消、屏蔽与异议的出口。

- 原任务：WS05-T05、WS05-T06、WS05-T07。
- 实际前置：T04；WS02-T06/T07 的事项恢复、WS06-T05 的本地能力和 T11 的恢复规则；T06 使用 WS07-T06-D 设计，T07 需要先定保留与治理安排。
- 实际顺序：先固化期限与恢复，再接成果验收和案件；不等待平台服务终验才做领域规则。
- 验收：未验收不会自动成功；返工超时保留原成果；暂停本机不自动延期；屏蔽后普通联系停止，合法案件入口仍有限开放。
- 失败时：状态未知先查询，不能盲目重做外部任务；无有效异议处理安排时暂停新试用批次，已有未决事项按约定关闭。

## 增量五：网页和 Agent 都能完整参与

**演示结果：** 人—人、人—Agent、Agent—Agent 使用相同规则完成服务；至少有一条真实跨主人的流程。

- 原任务：WS05-T08。
- 实际顺序：先整合 T02–T07 的页面与领域场景，交 WS06-T09@M5-A 联验；之后再收 WS07-T06-V 可用性结果和平台证据，汇总给 WS06-T10。
- 验收：申请、被选、承接、运行声明、交付和验收不会被界面混为一谈；缺少周期能力的宿主明确标为手动。
- 失败时：只声明已验证的入口；可手动演示，不借平台托管执行扩大兼容性承诺。

## 增量六：判断别人提供的服务是否值得使用

**演示结果：** 一批真实无偿需求有采用、未采用、无人回应与失败记录，能比较现有替代方案。

- 原任务：WS05-T09。
- 实际前置：T08 的功能闭环；基于 T01 服务定义冻结的 WS07-T11-D 正式指标，以及 WS07-T10@M5 的获准试用参与者。共用同一批次和数据，不另开重复研究。
- 验收：使用自己 Agent 或已有工具的对照可重做；等待、沟通、返工和已知成本分别记录；未知费用不填零；没有采用的案例不被删去。
- 失败时：需求不足就调整类型或停止；不以演示、刷单或积分活动证明市场需求。

## 条件增量：有证据后才讨论积分

**可能的结果：** 在真实重复需求中，比较固定、不可兑换的试验积分是否改善互惠分配。

- 原任务：WS05-T10，默认不启动。
- 实际前置：T07 的争议处理、T09 的无偿证据、积分方式被明确选择；不阻塞前六个增量。
- 后续顺序：先验证积分业务，再由 WS06-T09@M5-B 集成、T11 演练恢复与对账，最终收集当期验收证据。
- 验收与失败：重试不多发、争议冻结可追踪；对账不平立即停用新结算，保留原服务记录。没有现金、兑换和自由转账。

## 阶段结论应分别回答什么

流程是否可靠？请求方有没有采用？相比自有 Agent 是否更值得？是否真的需要互惠分配？这四个问题分别给证据，不能用积分活跃回答真实需求问题。
