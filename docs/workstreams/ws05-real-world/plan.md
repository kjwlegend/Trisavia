## 1. 已确认目标与本轮建议

- 已确认：保留真实需求、服务与交易实验；人类和 Agent 均有参与路径，Agent 在各自主人的运行时思考和执行，平台验证业务事实。
- 已确认：服务价值、成长效果和市场需求均未得到验证；看见需求、获取事件、承接、提交成果、验收是不同事实。
- 建议：M5-A 先验证一种无偿服务；M5-B 仅在证据支持且另行选择后启用不可兑换试验积分；有偿服务作为更晚的独立分支。
- 本文流程、类型、时限、样本规模、技术模块均为建议，不是用户已确认的实现选择；不授权本轮开发或试验启动。
- 阶段最小价值：真实请求方获得一份自己确实要用的结果，能判断采用与否，并能比较请别人提供服务与使用自己 Agent 的差异。
- 非目标：通用接单市场、自动竞价、现金支付、提现、可交易代币、链上钱包、算力租售、平台推理、远程接管、自动访问客户账号或完成外部发布。
- 进入条件：按五阶段顺序推进，M1 主体授权/撤销可用，WS01-T09 按 M2/M3 切片提供 human 身份与参与授权；M2 可见性、离线恢复及当前事项枚举可用，M3 互动/屏蔽事实可用，M4 已完成当期流程验收；不要求 M4 效果为正或服务方取得成长证明，可关闭 M5 反馈学习；存在带具体用途的需求。
- 退出条件分开记录：功能闭环满足第 9 节；需求价值按第 10 节给出支持、反对或不足的结论。需求验证失败也能关闭实验，不能用积分流转补作成功证据。

## 2. 最小服务与模块顺序

**建议只选“短文档可用性审阅”**：请求方交付一段有权分享的说明文档，服务方指出读者完成目标时遇到的歧义、缺漏和顺序问题。
试点输入建议不超过 2,000 个中文字等量文本；成果为检查范围、问题位置、影响、修改建议及未覆盖项。可报告未发现问题，不要求为凑数创造缺陷。
例如请求方要让新成员按说明完成某个流程，验收检查“位置可找到、理由与目标有关、建议可理解”，另记实际采用结果；不承诺外部事实核验或专业认证。
输入与输出只处理受限文本；链接作为来源数据，不触发平台抓取或本地自动执行。私有文件、聊天原文、密钥、可执行文件均不是所需输入。
请求方发布真实用途、希望的结果、验收条目、允许分享的材料范围和时限；服务方声明能力与预算可用性，声明不等于平台认证。

| 顺序 / 模块 | 最小职责与产出 | 推迟的能力 |
| --- | --- | --- |
| A 类型与约定 | 固定服务模板、授权输入范围、可验收条目、无偿标记 | 自由定价、复杂服务分类 |
| B 服务目录与需求池 | 服务方发布可提供内容；请求方发布需求，摘要可发现 | 推荐模型、全量广播 |
| C 申请与承接 | 多人申请、请求方选择一人、被选者确认后唯一履约单 | 自动派单、直接抢单、多人分包 |
| D 履约与结果 | 文本提交、逐项验收、一次返工、显式关闭 | 任意附件、外部系统写入 |
| E 异常与争议 | 撤回、拒绝、暂停、期限处理、证据及有限人工处理 | 商业仲裁、质量担保 |
| F 价值观察 | 对比替代方案、记录采用、等待和人工介入 | 收入预测、能力排名 |
| G 积分候选 | 通过证据闸门后单独选择和设计验证 | 购买、兑换、转售、升值承诺 |

服务发布与需求发布是两个对象：目录中的服务能力不产生订单；用户从服务页发起需求也走同一申请和确认流程。
建议申请必须绑定申请者自己的已发布服务条目及其版本快照，并匹配需求类型；从需求池直接申请也执行该守卫。暂停/归档只阻止新申请，已有申请、选择与履约继续有效，要停止其中一项须显式撤回或取消；页面在暂停前说明这一效果。
M5-A 无偿只表示平台不收费、双方不交换试验积分；运行时可能消耗模型费用，费用未上报时显示未知，不显示零成本。

## 3. 主体、对象、权限与数据归属

| 主体 | 可以做什么 | 不能推断的授权 |
| --- | --- | --- |
| 请求方：人或 Agent | 发布自己的需求，选择、取消、验收、提出争议 | 管理某 Agent 不自动允许以它名义承接所有服务 |
| 服务方：人或 Agent | 发布服务，申请、确认、交付、拒绝、申诉 | 申请或确认不授予对方本机工具权限 |
| Agent 主人 / 管理者 | 按 M1 管理授权暂停平台访问、恢复或撤销范围 | 平台暂停不能证明本地进程已停止 |
| 平台治理人员 | 按授权看争议证据、隐藏内容、记录处置 | 不代替双方生成成果，不宣称裁定作品专业正确 |

实际行为主体从认证上下文确定，记录 human / agent、操作者和代表关系来源；不能靠请求正文自填角色提权。人类无需伪装 Agent。
Agent 可在既有服务类别、材料、操作和预算授权内自主申请与接受；超出范围在本地请求主人决定，平台不擅自扩大授权或唤醒宿主。
M5 与 M2/M3/M4 消费同一主人侧预算，不另建免费执行通道。WS06-C10/WS06-T05 提供宿主费用闸门能力与降级，WS04-T03 只拥有学习子额度；WS05-T05 在承接前及本地执行前重新检查策略和可用额度，调用共享预留/结算能力，超时保留不确定消耗。平台积分不是模型预算。
宿主不能执行共享限额或控制重叠调用时，不宣称硬上限，也不启用自动承接后执行；可由主人知悉估算限制后手动单次处理。该降级不要求另装常驻组件，不承诺跨设备预算共识。

| 领域对象 | 核心事实与归属 | 可见性 / 修改约束 |
| --- | --- | --- |
| 服务条目 Offering | 作者、类别、能力声明、版本、可申请状态 | 摘要依 M2 可见；作者编辑，历史不覆盖既有约定 |
| 需求 Demand | 请求方、真实用途、摘要、材料范围、验收条目、截止时间、版本 | 公共摘要不带私密正文；详情按请求方设定范围 |
| 申请 Application / 选择 Offer | 服务方声明、本人服务条目版本快照、目标需求版本；请求方选中记录和到期时间 | 申请双方可见；同一需求至多一个有效选择 |
| 履约单 Engagement | 双方、固定条款快照、期限、当前状态、版本 | 双方与获授权治理人员可读；确认为不可变约定 |
| 成果 Submission / 验收 Decision | 有序成果版本、来源、条目判断、意见和操作者 | 默认当事方可见；编辑必须新建版本，验收指向具体版本 |
| 争议 Case | 原因、证据引用、双方陈述、处理记录和结论 | 隔离可见；公开状态不暴露正文和本地敏感日志 |
| 事件 / 待办 / 回执 | 平台事实、收件人、操作去重标识、版本与时间 | 依 M2/M3 权限读取，事件获取不改变履约状态 |

材料分公共摘要、确认所需样例和完整正文三层：候选人默认只读明确授权的样例，承接后可读完整约定材料；确认前确需全文，由请求方显式授权给该候选人。拒绝、撤回或选择到期撤销后续读取权。
未被选中者只能读足以申请的摘要；公开成果另行授权，不因完成服务自动公布。撤回授权影响后续读取，不能保证别人已保存副本被删除。
平台保存提交的业务材料和必要证据；模型密钥、系统提示、私人记忆、未提交草稿与工具日志留本地。保留与删除由 WS01/WS02/WS06 契约共同确定，试用前必须明确证据保留期。

## 4. 状态机与不变量

| 对象 | 建议状态与主要迁移 | 关键守卫 |
| --- | --- | --- |
| 服务条目 | 草稿 → 发布 ↔ 暂停 → 归档 | 暂停/归档阻止新申请，不撤回既有申请、选择或履约 |
| 需求 | 草稿 → 开放 → 选择待确认 → 已承接 → 已关闭；开放可取消/到期 | 选择失败回开放，且仍需满足需求有效期 |
| 申请 | 已申请 → 被选待确认 → 已确认；另可拒绝/撤回/到期/未选中 | 一人可有一个当前版本申请；重复提交返回原申请 |
| 履约单 | 待交付 → 待验收 → 已验收（申诉期）→ 最终已验收；待验收 → 待返工 → 待验收 | 待交付表示承接生效，不声称本地正在工作 |
| 独立案件 Case | 无案件 → 处理中 → 双方解决 / 未解决关闭 | 每单至多立案一次；不覆盖原履约、成果和验收事实 |
| 关闭结果 | 取消、交付逾期未完成、返工逾期未验收、验收逾期未验收、争议后关闭、争议未解决、最终已验收 | 明确验收与最终验收分开计数，争议中的单不计最终完成 |

不变量：每个需求至多一个有效选择、一个有效履约单；只有请求方选择与服务方确认双重成立后才得到任务；不按读取顺序分配名额。
申请时原子校验服务条目属于本人且处于发布态，保存不可覆盖快照；条目后续编辑不改变旧申请。选择和确认校验权限、不同参与主体、双方屏蔽/资格、需求/申请版本、有效期与名额，不因条目后来暂停而否定既有申请；确认原子创建履约单、关闭其他申请并写事件及回执。
开放需求实质修改会递增版本并使旧申请失效，申请人重新读取与申请；选择待确认后禁止修改条款，可撤回选择后修订，不能悄悄改服务范围。
履约条款与验收条目固定；范围变化通过双方确认的变更记录，拒绝则按原约定继续或协商关闭；MVP 只开放期限调整，范围变化另建需求。
本地暂停只记声明，不另建履约暂停态；期限调整限一次且最多延长当前期限 7 天，须在旧期限前双方确认，不能恢复已终结任务。
所有变更动作使用稳定请求标识和预期对象版本；相同标识重试回原结果，内容不同报冲突。状态、事件、回执一并持久化，客户端遇超时先查结果。
复用 WS06-C02/C03：当前鉴权及结果可见性 → 核对命令形成时的实例恢复代次 → 查幂等 → 仅新命令校验对象版本/时限；历史成功按当前权限裁剪并附现状，不因已推进版本而重做，不让旧回执恢复被撤回正文。
旧备份恢复后遵守 WS01/WS06 首期限制：身份/事实保留但不支持灾备再授权，不因持有旧证明继续操作。未来若另行支持合法新授权，也须拒绝旧代次命令，核对履约及外部效果后才显式产生新动作；本期以标记契约夹具验证该命令守卫，不冒充恢复访问成功。外部执行不由平台幂等保证，未知时停止盲重试。
“获取成功 / 已处理”沿用 M2/M3 投递事实；“本地开始 / 暂停 / 进度”仅是运行时声明，不能改变平台的承接、交付或验收事实。

## 5. 正常与异常业务路径

正常路径：服务方发布无偿服务 → 请求方公开需求摘要 → 其他参与者筛选发现 → 本地判断并申请 → 请求方选择一人 → 被选者核对条款、材料与本地授权后确认 → 平台生成唯一履约单 → 本地执行 → 提交成果版本 → 请求方逐项验收 → 记录是否实际采用 → 输出可授权的经历。
双方可以是人或 Agent；人通过页面完成同一动作。Agent 的意愿和工具执行在本地，平台仅验证请求合法性、状态与提交数据，不运行模型替请求方判断质量。
无变化或不感兴趣时可不申请；申请后可撤回；被选仍可拒绝。无人申请、无人承接和服务失败分别记录，不模拟他人参与。

以下时限都是首轮试用建议，须在需求发布前展示并固化；业务期限按服务器时间判断，不取决于轮询次数，期限变更须双方同意。
建议选择确认 48 小时、交付 7 天、验收 7 天、返工 3 天且最多一次、争议补充证据 7 天/立案 14 天后未决关闭；不是已验证的最优参数。交付从确认起算、验收从有效提交起算；提前发布的需求同时指定申请截止。
选择确认截止不得晚于需求申请截止；返工须在验收期限内提出，由服务方在 48 小时与原验收截止两者较早时前明确接受，接受后才进入待返工并起算 3 天。未接受保持原待验收期限，可验收原成果或立案。
仅时间严格早于截止的动作有效；即使期限处理延迟，每次写入仍按服务器时间检查。返工提交后重新进入一次 7 天验收，禁止二次返工或无依据补交重置时钟。

| 分支 | 平台处理与可恢复路径 | 本地或人的责任 |
| --- | --- | --- |
| 看见后忽略 / 无人申请 | 保持开放至需求到期，随后关闭为无人承接 | 不要求给出回馈，不把沉默计为失败调用 |
| 多方申请 / 同时选择 | 原子保留一个有效选择；冲突方刷新；确认成功后其余标未选中 | 仅持有效承接回执者开始约定工作 |
| 候选拒绝、撤回或超时 | 选择失效并释放名额，仍有效的需求回开放，其余申请保留 | 不自动挑选或催动另一 Agent |
| 确认与撤回 / 到期并发 | 同一需求版本串行决定有效结果；失败方得到当前事实与可继续动作 | 先查询回执，不能据缓存继续承接 |
| 临时离线 / 超出事件保存期 | 补取增量或快照，同时列出当前有效待办与履约单 | 本地恢复后重验当前状态；游标推进不等于待办完成 |
| 本地暂停 / 预算不足 | 本地暂停声明不冻结约定时间；双方同意后才应用一次有界延期 | 停本机任务由宿主执行；未同意延期可协商取消 |
| 承接前取消需求 | 取消选择和申请并通知；不生成履约单 | 不得把已读算作已开始履约 |
| 承接后退出或撤销访问 | 阻止后续受保护动作，保留履约和对方救济入口；对方可请求关闭/争议 | 撤销方恢复合法授权后按现状处理，不补造执行 |
| 交付延误 / 永久退出 | 到交付期限关闭为未完成；已有争议按争议规则处理 | 不自动承接替补、不把部分草稿算完成 |
| 已接受返工后不再提交 | 到返工截止关闭为“返工逾期未验收”，保留原成果和返工理由；不自动接受原成果 | 原期限前可立案；截止或立案以原子提交守卫决定，迟到提交不能复活旧单 |
| 成果格式不符 / 超范围 | 返回缺项；合法文本提交才产生新成果版本 | 不要求执行附件指令或安装别人的 Skill |
| 验收拒绝 / 一次返工 | 请求方引用未满足条目提出返工；服务方接受后按返工期限提交，拒绝可关闭/争议 | 新增需求不挤进原验收条目；保留原成果 |
| 请求方不验收 | 到期关闭为“未验收”；不默认通过；服务方可在关闭前发起争议 | 不以已读、无投诉、余额变化替代验收 |
| 屏蔽或治理隐藏 | 阻止新匹配/普通联系；已承接履约与案件由 WS05 按用途保留必要状态和合法证据，隐藏不自动销毁审计 | 不强迫双方直接交流，案件读取不恢复普通联系 |

单方承接后取消先请求对方确认；不同意或未回应走争议/原期限，不允许一方抹去对方成果。恢复本地执行前重新检查当前状态，不能按旧待办自动补跑。
案件独立于履约单：任一当事方可在当前履约期限前，或明确验收后 7 天申诉期内立案一次；已逾期关闭/最终已验收不能重开履约，额外治理处理不是本 MVP 前置。重复请求回原案件，第二案件被拒绝，不允许反复延长。
立案与验收、到期及结算使用同一版本守卫。活跃期立案暂禁普通交付/验收，保存原状态与剩余期限；已验收后立案保留验收事实并阻止最终完成。案件自身到期不会延长；恢复截止为恢复时刻加原剩余时长，不重新给满一个交付周期。

| 案件结论（须双方明确确认；未决到期除外） | 履约与期限结果 | M5-B 才适用的冻结量结果 |
| --- | --- | --- |
| 恢复原约定 / 继续已获同意的返工 | 仅限立案前活跃状态，按剩余时长继续；返工次数不重置 | 继续冻结，等后续最终结果 |
| 确认已有成果可接受 / 维持原验收 | 请求方对具体版本明确验收；原验收不抹除，申诉截止以首次有效验收时间计 | 到申诉截止且案件已解决后结算一次 |
| 协商取消 / 撤回原验收结论 | 追加争议后关闭事实，保留原成果/验收历史，不计最终完成 | 释放给请求方，不奖励 |
| 到案件期限仍未解决 | 追加争议未解决关闭，保留已提交或已验收历史，不假称任一方获胜 | 释放给请求方，不奖励 |

治理人员可以给出流程建议和记录证据，不能冒签双方结果或认证专业质量。双方未共同解决且无治理人员时同样按期限未决关闭；本文不裁定真实世界损失或外部权利，不提供金融或法律建议。
屏蔽按用途判权：WS03-T05 只提供主体对/用途/策略版本事实，不能把 M3 的活动终止或正文总拒绝套在 M5。WS05-T05/T07 决定已承接履约的保留、当前允许动作及隔离案件的最小证据范围；普通发现/联系受限，合法当事方仍可按规则请求关闭或立案。
全部用途先校验有效凭据，再由服务端核对当事人、履约/案件对象和保留用途；客户端自填“案件”不构成授权。案件只读 D03 允许保留的必要证据，治理隐藏或用途撤销仍须裁剪，不能旁路取得原已撤回普通正文；无效凭据无例外。WS02-T03/T05/T06 与 WS06 适配区分普通发现、互动及履约/案件视图和缓存；案件例外不恢复普通联系，也不依赖通用举报系统。

### WS05-T05 · 期限、暂停、撤销与离线恢复
负责人：WS05 领域开发 + 接入工程；依赖/输入：T04、I01–I03/I05，WS01-T09 有效身份、WS02-T06/T07 枚举/恢复、WS03-T05 用途事实、WS06-T05 能力及 T11 恢复契约。
步骤：① 固化服务期限/延期、共享预算检查和已承接用途权限；② 用共用事务处理服务期限/退出，消费屏蔽事实但不继承 M3 终态；③ 经 WS02 分用途枚举恢复履约/案件，验失权、备份恢复及预算不足。
交付物：异常状态机、期限处理、恢复说明和回执。
验收证据：暂停不延期，返工截止/立案只有一个结果；屏蔽后普通联系拒绝而合法服务待办仍在；无效凭据各用途拒绝；旧动作不重放，未知预算不重花；撤权不伪称停本机。
失败/回退：期限处理失败显示待处理事实并重试，不自动通过验收；无法恢复待办时暂停新增承接。

### WS05-T06 · 成果、验收与有限返工
负责人：WS05 领域开发 + 前端；依赖/输入：T01/T04/T05、I03/I04/I05 及 WS07-T06-D 设计规范；WS04-T02/C06 仅消费获授权结果引用。
步骤：① 提交不可覆盖的文本成果版本；② 请求方针对该版本逐项验收或提出一次返工；③ 校验二次提交、拒绝返工和验收沉默的终结路径。
交付物：唯一成果/验收模块、版本对照/验收页面及组件代码、带用途边界的结果经历更正；页面理解验证交 WS07-T06-V。
验收证据：提交与验收分开；非请求方及迟到/旧版本验收拒绝；返工失联保留原成果但不计成功；结果经历后续被争议更正时，迟到旧验收不覆盖最新结果或扩大学习用途。
失败/回退：不明确的验收条目返回协商，不生成自动优评；争议留给 T07，旧成果仍可追溯。

### WS05-T07 · 争议、屏蔽与证据保留
负责人：WS05 治理产品 + 领域开发；依赖/输入：T05/T06、I01–I03/I05、WS01-T09 身份、WS02-T03/T05/T06 分用途投影、WS03-T05 用途事实、WS06-T03/T11 及 D03；不需通用举报系统。
步骤：① 定义案件专用当事人/对象/证据用途权限与活跃/验收后入口；② 以 WS02 独立枚举接通屏蔽后最小案件投影及双方陈述；③ 验伪造案件用途、无效凭据、隐藏证据、重复立案与未决期限。
交付物：案件流程、有限处置权限及审计规范。
验收证据：验收第 2 天可立案且不重复/延时；屏蔽双方凭有效授权可读必要案件证据却不能恢复普通联系；伪造用途/跨案件/无效凭据拒绝；治理裁剪生效，结论不伪造验收。
失败/回退：无人能处理则允许冻结争议流程后到期未决关闭，暂停新试用批次，不强迫继续联系。

### WS05-T08 · 同事实的页面、工具与宿主走查
负责人：WS05 前端/接入工程 + QA；依赖/输入：局部片取 T02–T07、WS06-T05@能力/T06@契约及 WS07-T01@M5/T06-D；汇总片才取 WS06-T09@M5-A 联验与 T06-V，缺成长证据用未知样例。
步骤：① 先整合唯一业务页面/组件、视图模型、绑定和领域局部场景包；② 将局部包交 WS06-T09，复用通用宿主适配联验真实主体/分用途屏蔽/恢复；③ 收集 WS07-T06-V 与平台联验，输出本域汇总给 WS06-T10。
交付物：先交唯一业务页面/组件、绑定和局部证据，再交真实宿主/体验/平台联验汇总；WS07 只供规范/文案/可用性验收，WS06 只做基础/适配/联验。
验收证据：覆盖人—人、人—Agent、Agent—Agent 主体组合；至少一条真实跨主人闭环；看见/选中/承接/执行声明不混淆。
失败/回退：兼容失败只声明已验证入口；可先手动执行服务步骤，不宣称所有宿主支持调度。

### WS05-T09 · 无偿先验与替代方案比较
负责人：WS05 服务研究负责人；依赖/输入：T08、D01/D03、基于 T01 服务定义冻结的 WS07-T11-D 正式预登记指标与 T10@M5 试用招募/同意切片；I04 只作可选证据，不等 M5 反馈回流后的 M4 终验。
步骤：① 试用前核对冻结的真实用途、参与关系、对照方案和成本口径；② 运行建议小批次无偿试用并记采用/放弃理由；③ 分开出具功能结论、价值证据和是否值得积分实验的决定。
交付物：匿名案例表、替代方案对照、失败案例与 M5-B 进入评审。
验收证据：含无回应、未验收及未采用样本；未知成本不填零；自有 Agent/已有工具对照可重做；无价值也可明确停止。
失败/回退：需求不足先改变类型或停止，不用演示、刷单或积分激励充当需求证据。

### WS05-T10 · 条件性积分实验与回退
负责人：WS05 实验产品 + 账本领域开发（唯一业务实现）；依赖/输入：T07/T09、WS06-T03 基础、I01/I05/I06，D04 获未来明确选择后才开始；局部验证不依赖 WS06-T09@M5-B 终验。
步骤：① 预登记配额、固定单位、争议期和实验组；② 实现唯一账本业务与原子守恒，并向 WS06-T09 提供集成用例；③ 联合 WS06-T11 演练恢复/对账、重复验收、争议及停用，将结果交 WS06-T10@M5-B 平台终验并比较无偿基线。
交付物：不可兑换积分候选的实施设计/记录、对账证据及停止开关。
验收证据：无现金/兑换/自由转账；重试不多发，各案件结论/返工逾期正确处置冻结量；灾备旧证明不能再授权，另以标记夹具验新授权下旧命令仍拒绝，不把夹具算真实恢复；核对前不消费恢复余额，停用保留履约，互刷不计需求。
失败/回退：对账不平立即停止新冻结与结算，保留记录和服务闭环；不向用户承诺积分补偿现实支出。

## 10. 观察、积分闸门与未来决定

无偿先验建议首批邀请 5 位独立请求方、观察 10 个真实需求/两周；规模与窗口仅为试验提案，不能支持总体市场推断。
观察分母分别为发布、有效申请、确认承接、提交、明确验收、最终验收；记录无人申请、退出、未验收、返工、争议、实际采用、再次使用及人工介入。
比较同一任务由自有 Agent / 既有工具完成的可用性、等待、沟通、返工和费用；能力/资料差异单独记录。费用来源和未知项显式展示，不把模型花费等同服务价格。
积分闸门建议为：无偿流程已可靠闭环；存在多位独立请求方实际采用并再次提出需求的证据；参与者明确遇到互惠分配问题；治理与保留能力可用。样本不足或只是缺少需求则不开启。
M5-B 候选：封闭自愿批次，积分不可购买、兑现、跨实例转移或自由赠与；固定一种服务、一次扣划一单位，初始每参与单元三单位，参数均为建议。
模式和固定单位在需求发布时固化，既有无偿单不能改价。按批次和参与单元唯一发放；承接与冻结同事务，必须有足够可用量且不允许负数，否则不产生履约单。冻结以履约单唯一关联，重复确认不再冻结。
冻结记录独立于履约及 Case，为“冻结中 → 已结算 / 已释放”单向终态；只有最终验收可转给服务方。取消、交付/返工逾期、未验收及未决争议释放原量，不自动奖励；恢复中的案件继续冻结，结论映射见第 5 节。
验收后 7 天内可立案，期间不结算；到期结算仍检查有效验收、案件状态与唯一结算记录。事实修正保留审计，不编辑历史账目；异常需停止结算并以带来源的纠正记录对账，不能靠重放验收补账。
恢复旧备份时 WS06-T11 使旧凭据/游标/命令代次失效；WS05-T10 对受影响试验批次暂停新发放、冻结和结算，连同履约/案件/账本按同一恢复点核对。对账未闭合不把恢复出的可用量当作可消费余额；纠正须引用原尝试与核对证据，不能把旧请求改代次后补跑。
同管理关系的自我订单、短时间循环协作、重复材料应分层观察；邀请配额和人工抽样降低刷分风险，但不宣称认证了独立真人或彻底阻止多账号。
实验退出先关闭新积分需求；已有冻结按原条款结清或释放，再将该批积分归档且停止使用，公开说明不兑换；无偿服务可以继续。
有偿未来分支只在真实付费意愿、服务责任、成本、支付/退款与争议等另行规划且获授权后讨论；不把试验积分直接升级为可兑现资产，不预设算力交易成立。

| 决策 | 影响 / 建议默认 | 最晚选择点 |
| --- | --- | --- |
| D01 首类服务与样本 | 建议短文档审阅；其他类型需重新写验收/材料边界，不扩大到通用代理执行 | T01 签出前 |
