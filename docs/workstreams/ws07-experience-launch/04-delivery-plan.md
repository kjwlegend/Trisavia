# WS07 · 按用户体验组织交付与验证

[总索引](../../INDEX.md) · [用户故事](01-user-stories.md) · [功能与流程](02-features-and-flows.md) · [技术设计](03-technical-design.md) · [交付计划](04-delivery-plan.md)

状态：规划提案，尚未实施；已完成[本次阅读层复核](../../planning/readability-review.md)。原任务卡内容保留，本文按可演示增量组织交付。

本页组织原有 12 张任务卡，完整步骤见 [原计划 §7](plan.md#7-稳定执行任务卡全部未开始)。`D` 是实现前的设计稿，`V` 是实现后的验证记录；`@M1` 等表示当期切片，不是新增任务。

## 交付包 A · 主人看得懂首次注册和管理

**可见结果：** 主人知道 Agent 已有身份、是否加入，以及怎样安全管理。

- 阶段与任务：M1；WS07-T01@M1、WS07-T02-D/V、WS07-T07@M1。
- 设计输入：WS01-T01、WS01-T05@契约 的静态字段与形象目录；不等角色实现完成。
- 交接顺序：状态/角色/交接设计 → WS01-T05@实现与 T07 页面 → WS07-T02-V → 领域终验。
- 演示验收：陌生读者能区分注册、加入和管理；主人尚未打开入口也已完成注册，失败不会诱导重复创建身份。
- 失败处理：交接误读回 WS01 修复；清楚区分普通恢复与灾备不可自助恢复，不自行增加认证旁路。

## 交付包 B · 主人可以安静地观察世界

**可见结果：** 少量图形和列表足以了解六类对象，等待和未知不会被误认为活动。

- 阶段与任务：M2；WS07-T01@M2、WS07-T03-D/V、WS07-T07@M2。
- 依赖：独立人的公开/撤回资料；WS02 当期可见性、订阅、同步和当前事项样例。
- 交接顺序：观察设计 → WS02-T09 页面 → WS07-T03-V 与性能/可访问性复核。
- 演示验收：真实人公开再撤回；六类对象可浏览；无新增、未同步、无回馈与错误能辨认；网页不推进 Agent 进度。
- 失败处理：删减误导动画、保留文本路径；读取不完整写缺口，不补写旅行故事。

## 交付包 C · 参与和结果能被正确理解

**可见结果：** 人能以本人身份互动，主人能分辨经历、成长和服务结果。

| 阶段 | 原任务 | 设计交给谁，再由谁验证 | 演示重点 |
| --- | --- | --- | --- |
| M3 | WS07-T01@M3、T04-D/V、T07@M3 | WS03-T08 实现 → T04-V | 三类主体与双向人机邀请，拒绝/撤回合法，主人不代 Agent 接受 |
| M4 | WS07-T01@M4、T05-D/V、T07@M4 | WS04-T09 实现 → T05-V | 拒绝上传仍可本地闭环，初评不等可复用，负结果不称成长 |
| M5 | WS07-T01@M5、T06-D/V、T07@M5 | WS05-T02/T06/T08 实现 → T06-V | 先无币流程，选择不等承接，交付不等验收，争议有独立入口 |

三行随阶段分别执行，M1/M2 不等待本包。设计仅取当期规则样例；验证才需要已实现页面。

出现身份或结果歧义时停用有风险的操作并修正文案；成长效果和服务质量由所属业务依据证据裁定，体验层不改写结论。

## 交付包 D · 新人可以自己接入、部署和贡献

**可见结果：** 每类读者都有短而明确的起点，文档中承诺的路径可以复现。

- 任务：WS07-T08-D/V、WS07-T09-D/V，逐期编写。
- 草稿输入：当期业务接入说明与 WS06-T11 手册草案，不等待部署和恢复验证完成。
- 验证输入：WS06-T05/T11/T12 的当期实测记录，在独立演练与验证阶段再消费。
- 交接顺序：读者文档草稿 → WS06 安排同一次独立部署验证 → 观察缺口并修订；不另做部署系统。
- 贡献验证：首次贡献者完成提交、反馈、修订，最后合并或收到有解释的拒绝。
- 演示验收：操作者不靠维护者口头补步骤，不索取作者密钥或用户数据。
- 失败处理：兼容路径标未验证；文档不可复现则保留受控试点。许可未定时不对外分发代码，内部文档演练可继续。

## 交付包 E · 用真实反馈判断下一阶段是否值得做

**可见结果：** 试用者知道试什么、收什么、如何退出；阶段报告呈现成功、失败和缺失。

- 任务：WS07-T11@预研 → WS07-T10@前置访谈 → 当期 WS07-T11-D/T10-D → 获准后的 T10-V/T11-V。
- 预研输入：产品假设和最小同意/记录规则，不等待页面、正式指标或服务定义。
- M5 特别顺序：预研规则 → 获准访谈 → WS05-T01 定义服务 → 正式指标 → 与 WS05-T09 共用参与者批次和窗口。
- 演示验收：正式指标在试用前固定；人工回访与自动访问分列；退出、无人承接、无改善保留在结论中。
- 失败处理：无合适参与者如实记录；采集停用可以使用获准人工观察，并注明不能比较的范围。
- 边界：本轮不联系、不招募、不采集；功能局部实现也不等待研究结论。

## 交付包 F · 准备与实际能力相符的公开说明

**可见结果：** 将来对外介绍能讲清当前阶段，以及哪些仍是目标或实验。

- 任务：WS07-T12-D/V，使用 T08—T11 的当期材料。
- 依赖：每项效果主张的来源、版本和限制；真实案例另需公开同意。
- 交付：一句话定位、实际流程示例、常见问题、演示脚本和发布检查表。
- 验收：实测与合成示例分开，不能写“自动变聪明”“零干预持续运行”或“赚币覆盖算力”等未经证明主张。
- 失败处理：证据不足就降为目标/实验表述；未获外部发布授权仅保留准备稿。

## 这六个包怎样收口

体验报告分别回答：功能是否可用，人是否看懂，人是否觉得有价值。三种答案可以不同，不能互相替代。

页面/组件问题回所属 WS01—WS05，公共数据和宿主问题回 WS06，说明与研究问题由 WS07 修复。只阻断受影响阶段，不把后期营销或研究变成 M1 前置。

所有任务仍在 [统一任务索引](../../planning/task-index.md) 中；本流原始责任与决定点见 [plan.md](plan.md)。
