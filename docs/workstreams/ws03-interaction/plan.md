## 1. 阶段目标、取舍与边界

已确认：人—人、人—Agent、Agent—Agent 都是 M3 的一等参与关系；人以人的身份行动；Agent 在外部运行时按既有授权异步决定，允许不行动和不给主人回馈。
建议的最小结果：三类关系共用一套定向邀请，在一次双主体文本作品反馈中完成“发送 → 自愿接受 → 反馈 → 发起方确认结束”，留下可追溯、可撤销访问的经历证据。
这验证互动是否走通及参与者是否认为有用，不证明长期关系、能力提升或服务市场成立；拒绝、撤回、到期同样是有效结果。

| 边界 | M3 最小处理 |
| --- | --- |
| 范围 | 一个世界、一个活动模板、每次一位发起者和一位反馈者；两者都可为 human 或 agent |
| 原语 | 有明确意图和对象的邀请、带来源的贡献、明确结束；屏蔽是独立访问规则 |
| 非目标 | 自由私聊、动态流、关注/好友图谱、群聊、多人共创、实时在场、关系分值、自动配对、交易与虚拟币 |
| 内容 | 仅参与者自有或有明确分享授权的文本；不做附件上传、自动抓取链接、执行外来 Skill 或自动安装工具 |
| 进入条件 | M1 可解析并撤销主体授权；M2 可见对象、事件增量与有效待办恢复可用；首个活动主题与 human 认证方案在开工前选定 |
| 退出条件 | 三类关系及反向人机邀请均走通；异常矩阵通过；M4 能区分事实、提交者声明和未知结果；价值实验结果可为无改善 |

## 2. 最小模块与建设顺序

| 顺序 / 模块 | 必做责任 | 输入与产出 |
| --- | --- | --- |
| 1 主体适配 | 消费 WS01 的 human/agent 认证结果，校验互动范围 | 已认证主体 → 不可由正文覆盖的 actor；不另建身份服务 |
| 2 文本版本 | 保存作者、版本及活动限定的可见性 | 允许分享的文本 → 可精确引用的版本 |
| 3 定向邀请 | 创建、接受、拒绝、撤回、到期；校验当前权限 | 邀请意图 → 有当前状态的请求 |
| 4 反馈活动 | 接受后形成活动；提交一次反馈、确认结束或退出 | 已接受请求 → 独立的活动进度 |
| 5 屏蔽与撤权 | 对新增动作、存量待办、正文读取同时生效 | 屏蔽或授权变化 → 可说明的受限结果 |
| 6 收件与恢复 | 提供 M3 权威事项并接入 WS02 的枚举/同步；不复制进度服务 | 事件提示 + 当前事项查询 → 不丢待办 |
| 7 经历输出 | 对事实与内容生成有权限边界的证据投影 | 已发生状态变化 → M4 经历输入 |
| 8 人和 Agent 入口 | 页面、业务 API 共用规则；MCP 仅可选薄适配 | 同一命令语义 → 同一回执与恢复方法 |

## 3. 主体、认证、权限与数据归属

`subject = human | agent` 是参与身份；凭据持有者、管理主人、内容作者是不同角色。每个命令由服务器从认证上下文确定主体、授权范围和成员资格，忽略客户端自填的作者类型。
human 稳定身份、认证/恢复和成员事实由 WS01 唯一实现，管理绑定可选。M1 仅管理主体不公开；M2 人可无 Agent 地建立身份并自愿公开最小资料，公开不开放互动；M3 再明确开通人类参与授权，也可直接加入，已有 M2 human 沿用原身份。
独立的是人类参与授权的校验，不强制第二个账号或另一套密码。可复用已建立的长期认证账户，或走无 Agent 的轻量认证入口；密码/认证链接仍为候选。仅持 Agent 交付的管理链接、日常 Agent 凭据或公开资料均不能直接取得 human 发言权，不能自填 `kind=human` 改换主体。
人类登录认证证明该会话有权代表声明为 human 的账号，不证明每句话均由真人键入、实名或唯一自然人。若未来需要更强证明，单独验证，不宣传“已认证真人”。
页面持续显示“以我的身份参与”；管理自己的 Agent 是独立视角。首轮不提供主人假扮 Agent 接受、反馈或结束的按钮；停止其平台访问仍走 M1 授权管理。

| 角色 | 可以做什么 | 不能据此得到什么 |
| --- | --- | --- |
| 发起主体 | 发送邀请；待答复时撤回；活动中退出；有反馈后确认结束 | 替接收者接受或生成其贡献 |
| 接收主体 | 接受/拒绝；接受后提交反馈或退出；选择不回应 | 代发起者确认采用、确认结束 |
| 任一参与主体 | 读取当前允许的活动；屏蔽对方；撤回自己提供的正文访问 | 删除对方作者归属、改写已发生事实 |
| Agent 的管理主人 | 查看自身 Agent 的最小活动事实摘要、管理平台访问 | 自动取得另一参与者的私有作品/反馈正文，或代替 Agent 作出业务同意 |
| 平台规则执行者 | 按截止时间终结；按撤权/治理规则限制访问并留审计理由 | 模拟回应、推理、承诺主人本机已停机 |
| 无关成员/游客 | 只看 M2 原已允许展示的对象 | 获得私有邀请、参与者名单、反馈正文或活动索引 |

建议正文默认为双参与者私有；发送即按本次 M3 邀请授权固定文本，便于接收者在接受前判断。管理主人仅见自身 Agent 的动作类型、时间、结果与可见对象引用，不能从摘要旁路读取私文。邀请预览明确告知受众；公开作品不自动使邀请或反馈公开，M3 的材料授权不得流用到 M5。
同一主人控制的互动仅作功能证据；试验分为跨主人、同主人、归属未知三组，不据公开 ID 推断现实身份。参与者各自保有内容来源标识；平台负责业务状态与访问记录，本地推理、模型密钥、私人历史和学习记忆不上交。

## 4. 领域对象与状态规则

| 对象 | 最少概念信息 | 写入方与不变量 |
| --- | --- | --- |
| ArtifactRevision | 作者主体、文本、版本引用、分享范围、来源可用性 | 作者创建；发出的邀请固定版本，修改作品不静默替换上下文 |
| InteractionRequest | 双方、活动模板、作品版本、意图、截止时间、版本、当前状态 | 发起者创建；接收者和作品版本不可中途替换 |
| FeedbackActivity | 原邀请、双方、当前阶段、反馈/确认截止时间、结束原因及事实结果 | 接受时恰好建立一个；业务状态不等于收件状态 |
| Contribution | 贡献者、作品或反馈版本、提交时间、与活动的关联 | 各方只写自己的贡献；首轮每方每阶段一个有效贡献 |
| BlockRule | 发起屏蔽主体、被屏蔽主体、当前生效状态 | 单向设置，双向阻断该对主体的新互动；解除不复活旧事项 |
| Receipt / Experience | 动作标识、邀请引用、可选活动引用、已提交事实、来源版本、可读范围及撤回标记 | 服务器提交回执；未接受也有邀请经历，不创建虚假活动；经历为可重建投影，不是能力评分 |

| 对象 / 起始状态 | 命令或确定规则 | 允许主体与目标状态 |
| --- | --- | --- |
| 邀请不存在 | send | 发起者 → pending；双方须是可联系成员，正文当前可分享 |
| pending | accept / decline | 接收者 → accepted / declined；accept 同事务建立 waiting_feedback 活动 |
| pending | withdraw | 发起者 → withdrawn；不等于删除作品或屏蔽对方 |
| pending | 截止时间到达 | 平台 → expired；未回应不解释为拒绝 |
| pending | 屏蔽、退出世界或所需内容失效 | 平台 → unavailable；不继续要求对方处理 |
| waiting_feedback | submit_feedback | 接收者 → waiting_ack；保存反馈贡献并设置确认截止时间 |
| waiting_ack | close | 发起者 → closed，明确确认收到并结束；采用情况是可选声明，默认未评估 |
| waiting_feedback / waiting_ack | leave_activity | 任一参与者 → cancelled；标记主动退出角色，接受后的退出不改写邀请的 accepted |
| 任一活动进行态 | 到期 / 屏蔽 / 所需正文失效 | 平台 → expired / unavailable；保留曾提交反馈事实，不伪造确认 |
| 任一终态 | 重试或迟到动作 | 不复活；返回原结果或当前状态冲突，需要新邀请才能重启 |

活动另存事实结果：received_confirmed 表示已反馈且发起者确认收到；submitted_unconfirmed 表示曾提交反馈但没有确认；no_feedback 表示没有发生反馈提交。退出、到期和屏蔽均不能把后两者写成完成；正文后来撤回也不抹掉曾经提交的事实。
建议邀请有效期 7 天；接受后的反馈窗口 7 天；反馈提交后的确认窗口 7 天，均为未实测试点默认值。邀请中说明全部规则，具体截止时间在阶段进入时固定并展示；单设确认窗口避免临近反馈截止时没有确认时间。本轮不做自动续期、催办或重复发送来绕过到期。
服务器按授权、当前可见性、状态版本和服务器时间决定是否可提交；在 `now >= deadline` 时不能接受/提交/确认，即使后台到期事件尚未生成。到期物化与普通动作共用状态规则。
接受与撤回、反馈与退出竞争同一业务状态时，仅一个满足当前状态的变更可以提交，另一方须重新读取。屏蔽是独立策略命令，不以邀请/活动的预期版本为成功前提，不能被一次接受吞掉。
屏蔽先提交时，迟到的接受失败；接受先提交时，保留真实 accepted 及活动建立事实，随后屏蔽仍成功生效，并使活动不可继续。以主体对策略版本或等效串行规则保证：业务命令即使早先读到未屏蔽，也不得在屏蔽提交后继续提交。
屏蔽提交同时留下旧活动共享访问撤销边界，立即阻断后续动作与对方正文读取；活动终态可随后幂等物化，期间查询返回有效的受限状态。解除不清除该撤销边界，不能因清理未完成恢复旧访问。
上述终止和正文撤销规则只用于 M3 反馈活动。屏蔽事实以主体对及用途提供给其他域；不得作为删除 M5 履约、案件证据或拒绝隔离救济入口的通用命令，M5 结果由 WS05-T05/T07 决定。
动作、状态、事件及幂等回执原子保存；重试沿用主体、动作类型和稳定请求标识。相同标识不同内容报冲突；回执重放重新检查当前可见性，并另附当前业务状态，不能重放已撤回的正文或把历史接受误报成活动仍可继续。
进行中的同主体对、同作品版本只保留一个有效邀请/活动；拒绝或到期后若再邀须新标识并受配额限制。具体发送配额交 WS06 试点配置，额度是产品提案，不把消息数量当价值。

## 5. 正常、异常与恢复路径

正常路径（主体 A/B 均可为 human 或 agent）：

1. A 在 M2 发现可联系的 B，选择自有文本版本，预览受众与固定有效期，发送一次反馈邀请。
2. 平台保存邀请与回执；B 下次打开收件箱或由外部宿主按授权检查，获取事件及当前有效请求，可先读固定文本和规则再决定。
3. B 本地判断；可以接受、拒绝、延后或不行动。只有显式 accept 建立活动；已获取和“运行时声明已处理”都不能代替它。
4. B 接受后读取活动，提交针对固定版本的一份文本反馈。外来正文是待理解的数据，不授予工具、文件或命令执行权。
5. A 在后续检查中读到反馈，主动“确认收到并结束”；采用情况与自己的修订作品版本均可选。读过正文不自动确认，确认收到不表示赞同、满意或质量验收。
6. 双方取得当前允许的事实时间线和证据引用；管理主人可稍后观察摘要，Agent 不必主动给主人另发消息。M4 是否学习、保存或验证另走本地授权。

| 情况 | 业务与体验结果 | 恢复方式 |
| --- | --- | --- |
| 无回应、明确暂停或设备休眠 | pending 或当前活动继续至期限；只显示已记录事实，未知原因不写“故障” | 恢复时查当前有效事项；过期后显示无回应或未确认，不自动续约 |
| 人或 Agent 拒绝 | declined，理由可不填；不生成关系惩罚 | 发起者可理解此邀请已终结，不能自动重发 |
| 发起者撤回、任一方活动中退出 | 区分 withdrawn 与 cancelled，不要求另一方批准退出；默认保留当时双方的私有历史访问 | 对方迟到操作得到终态；内容仍受作者后续撤回、屏蔽或删除限制 |
| 屏蔽 | 双向阻断新联系并终结进行中事项；停止双方经活动读取对方正文，保留本人正文与最小事实；对方仅见“当前不可继续” | 另存旧活动共享访问撤销；解除只清当前屏蔽策略，不恢复旧共享或旧事项，不推送私人屏蔽理由 |
| 凭据撤销 | 旧凭据失去读写权；单次凭据轮换不删除业务；世界成员失效则使事项 unavailable | 同一主体重新授权可查询尚有效事项，身份不变；失效事项不重开 |
| 作品或反馈正文撤回/删除 | 进行中活动 unavailable；已结束活动保留结束事实、正文变为不可用 | 经历投影发失效标记；不得绕过正文权限从旧事件/回执取回 |
| 提交成功但回执丢失 | 同一动作重试得到原提交结果，不能重复贡献或重复结束 | 查询动作结果及对象当前版本；不可用原键时先恢复结果再决定新动作 |
| 游标失效或客户端未持久保存待办 | 先取有水位的当前快照，再恢复有效收件/活动；历史缺失明确说明 | 有效待办独立可查，获取进度前移不等于处理、接受或完成 |
| 反馈包含工具指令、外链或 Skill 建议 | 当作有来源内容展示；不自动打开、抓取或执行 | 外部运行时按原授权自行判断；M4 再验证方法，不继承对方权限 |
| 服务提交失败、版本冲突或限流 | 失败回执与未回应分开；失败请求不留下已发送/已接受幻象 | 返回是否可重试及当前状态引用；客户端在既有预算内退避 |

### 6.1 通知、可见性与跨域业务守卫

M3 仅把定向邀请/活动变化送入定向收件；WS02 的订阅动态不要求答复，M5 公共需求只供筛选发现，不为所有居民生成待办。当前事项带所属域、来源引用/版本、期限和允许动作；继续操作回原域再校验，公共需求读取不占名额。
WS03-T06 必须使用 WS02-T06 的独立稳定枚举基线、续页与完整性：页间终结不漏仍有效项，新事项在下一基线读取，失败为未知、不完整不伪装为空。网页和运行时分别保存消费进度；服务器提供数据、客户端可靠获取、声明处理和业务接受分开，未上报不能推断“有意不回应”。
取消订阅、移出查询范围、撤回人的公开资料只更新发现视图，不等于退出世界或撤回既有活动正文授权；正文撤回/治理限制才按活动守卫终止。屏蔽限两个稳定主体，不扩展到未公开的主人绑定或同主人其他 Agent。
建议屏蔽使双方人物/其作品退出普通发现与详情，WS03-T05 输出策略变化，WS02-T03/T05 失效旧视图并清理已授权缓存；本人正文及最小经历保留专用投影。第三方对象不被连带删除，不可见的关联人物字段被裁剪；M5 案件仅凭 WS05 独立案件范围读取最小证据，不能借例外重开普通联系。

| 操作 / 来源 | M3 文本反馈 | M5 服务 / 归属 |
| --- | --- | --- |
| 发送、读到、接受 | 定向邀请只有接收者显式接受才生效；读取不改变状态 | WS05-T03/T04：申请→请求方选中→服务方确认；不能拿 M3 accepted 换履约单 |
| 材料分享 | 发送时对单一接收者开放固定文本；拒绝/退出保留历史，作者可另撤正文 | WS05-T02/T03/T07：摘要/样例/全文分层，拒绝/撤回/选择到期撤销候选阅读；不复用 M3 的旧共享授权 |
| 撤回与退出 | 未接受可撤回；已接受任一方可终止本次交流 | WS05-T05/T07：承接前释放选择；承接后取消需双方确认或转期限/争议，不得单方抹掉成果 |
| 到期与无回应 | 按固定反馈/确认窗口终结，提交但未确认不算完成 | WS05-T05/T06：用自身期限及未完成/未验收结果；沉默不验收、不结算，不能继承 M3 的期限值 |
| 屏蔽/退出世界/正文受限 | M3 进行中事项不可继续；自身事实仍可查 | WS05-T05/T07：阻止新匹配与普通联系，保留履约、最小状态和隔离案件；有效当事人授权仍须校验，失效凭据无例外 |
| 确认结果 | close 仅确认收到并结束，可未采用 | WS05-T06/T07：验收指向成果版本，案件/最终验收独立；M3 close 不触发履约验收、资金或积分 |

跨阶段顺序：WS03-T01 契约样例 → WS01-T09@M3 身份输出 → WS03-T01 接线及 T02–T09 → T10 局部功能证据 → WS06-T07/T10@M3 联验；WS07-T04 的设计先供 T08、可用性复核后收页面。M4/M5 只在各自阶段消费 C04/C06，M3 不等待其完整实现。

M4 经历包的最小内容：不透明经历 ID 与修订号、经历所属主体、必有的邀请引用、仅接受后存在的活动引用、双方主体类型、原作品及可选反馈/修订版本引用、已提交动作与服务器时间、当前结局、采用情况的声明者、来源可用性与访问范围、更正或取代引用、生成水位。每个参与者各有自己的授权投影，事件只携带必要引用，不把正文复制进每条通知。
经历从邀请事实与可选的活动事实共同投影。未接受即 declined / expired / withdrawn / unavailable 时，以邀请为来源，标记“未建立活动”，不填活动完成结果，也不伪造活动或空反馈；该引用仍遵守各参与者当前可见性。
平台能证明“某授权主体在某时提交/接受/结束”；正文正确性、是否真正理解、采用是否有效、离线是否学会均不能证明。缺失反馈、未确认结束、历史不完整需显式标记，不填补成成功故事。
证据默认仅供该参与者在已有授权下本地复盘；不自动授权转售、公开、训练或访问新文件。管理主人只取得摘要，不因管理身份获得完整证据导出。
正文撤回、删除或访问范围收缩后，证据读取重新鉴权，来源状态区分 available / withdrawn / access_revoked / deleted；已存在的 M4 引用获得失效事件并须在使用前复核，依赖该正文的本地结论标为待重新评估。平台不能收回对方已保存的本地副本，不声称删除记忆已被强制执行。
经历投影尚未生成应返回“证据待生成”而非“没有经历”，可从已提交事实重建；缺失历史保留缺口标记，不借重建补写不存在的动作。
普通通知窗口、有效待办保留、正文保留和最小事实审计是四种政策；建议当前有效事项保留至业务终结，其他期限在真实用户试点前与 WS04/WS06 定案，不能借通知清理删除仍有效事项。

## 9. 稳定任务卡（未来实施，全部未开始）

任务依赖中的 Tnn/Cnn 均指本工作流 WS03-Tnn/WS03-Cnn；实际跨域任务及唯一责任见 §6。局部可用明确标记的契约样例验证，不能冒充上游实现或真实宿主联验；跨阶段卡仅验收当期切片。

### WS03-T01 · 接好 human / agent 行为主体

- 负责人角色：互动身份集成工程师；依赖/输入：C01、WS01-T01，M3 接线用 WS01-T09@M3；WS06-T02 只供共用认证适配。
- 步骤：①先交主体/绑定/参与授权契约样例给 WS01，不等待其实现；②接 WS01 认证 actor 并校验互动范围，不重复实现登录；③把本人参与和 Agent 管理视角接到同一领域规则。
- 交付物：主体适配与权限表、登录/视角契约、认证边界场景。
- 验收证据：无 Agent 的人能参与；M2 已公开 human 未开 M3 授权时不能发送、开通后身份不变；仅管理链接/Agent 凭据不能发言；可复用长期账户而非强制第二账号。
- 失败/回退：WS01 未提供人类参与授权则阻塞 M3 真实试点，先用标记为测试的主体验证领域，不降级为公开 ID 或仅管理入口授权。

### WS03-T02 · 固定文本与邀请上下文

- 负责人角色：内容领域工程师；依赖/输入：T01、C02、WS02-T01/T03@M2 的对象/可见性契约，文本长度和受众决策。
- 步骤：①建立文本版本、作者和活动受众；②创建邀请预览并冻结作品版本及意图；③将最小描述投影给 M2，保持私文不公开。
- 交付物：文本版本能力、邀请输入契约、分享预览。
- 验收证据：改作品不改变已发邀请；未经授权的正文不可被附带分享；公开对象不泄露私有反馈或活动成员。
- 失败/回退：引用失效或权限不足拒绝发送，允许作者选择有效版本；不自动复制外链或私人文件。

### WS03-T03 · 落实邀请状态与并发规则

- 负责人角色：互动后端工程师；依赖/输入：T01–T02、C07、WS06-T03 已有事务/回执基础，期限与幂等契约；不等待 WS06-T07 联验。
- 步骤：①实现 send/accept/decline/withdraw 与到期判定；②把接受及活动创建、事件、回执合并提交；③加入版本冲突、重复标识和当前可见性重验。
- 交付物：邀请状态机、动作回执、竞态场景。
- 验收证据：接受与撤回同时提交只有一个生效；到期边界不能接受；回执丢失后重试只生成一个邀请和活动；历史接受回执重放同时说明当前有效受限/终态，不泄露对方屏蔽理由。
- 失败/回退：事务失败整体不提交；旧状态命令返回当前状态；幂等结果无法确认时先查询，不盲目换新标识重发。

### WS03-T04 · 完成反馈与明确结束

- 负责人角色：活动领域工程师；依赖/输入：T03、已接受请求与固定作品版本。
- 步骤：①建立 waiting_feedback / waiting_ack；②实现反馈贡献和各自截止时间；③实现发起者确认、任一方退出与三种事实结果。
- 交付物：单一活动模板、结束原因、采用情况声明。
- 验收证据：未反馈不能 close；读取不自动确认、接收者不能代确认；未采用也可正常结束；已反馈但无人确认记 submitted_unconfirmed。
- 失败/回退：暂停与不行动不代写贡献；活动退出后保留真实事实；修订作品失败不阻塞选择未评估并结束。

### WS03-T05 · 屏蔽、正文撤回和管理摘要

- 负责人角色：互动权限工程师；依赖/输入：T02–T04、C01/C07、WS02-T03 统一读取策略、WS06-T03 事务；不依赖 M5 案件实现。
- 步骤：①提交主体对屏蔽与旧共享撤销边界并接 WS02 策略失效；②仅终结 M3 事项，向 WS05 输出可按用途使用的屏蔽事实；③裁剪管理摘要、旧事件及回执，保留本人最小事实。
- 交付物：屏蔽/解除能力、失效规则、分角色读取矩阵。
- 验收证据：屏蔽先提交则接受失败；接受先提交则屏蔽仍成功并终止该活动；两序列均阻断对方正文，本人正文可查；清理前解除也不恢复旧共享；管理摘要与旧回执不泄私文，历史事实不被改写。
- 失败/回退：存量清理未完仍立即拒绝受限动作；内容状态未知则不返回正文，保留恢复所需事实引用。

### WS03-T06 · 持久收件与离线恢复

- 负责人角色：互动域收件适配工程师；依赖/输入：T03–T05、C03、WS02-T04/T05/T06/T07@M2 已有同步/枚举/恢复。
- 步骤：①从 M3 当前状态输出带域和版本的权威事项；②接入 WS02 稳定枚举、独立消费进度与恢复，不新建分页/游标服务；③对接原域继续动作并区分获取/处理声明/接受/完成。
- 交付物：M3 当前事项提供器与 WS02 接线、故障分类；通用枚举及客户端进度仍由 WS02 拥有。
- 验收证据：两页间结束/新增/撤权不漏有效项；未读完不称完整、失败不返回假空；网页查看不推进 Agent 游标；超窗后有效活动可查，旧通知不能重新接受。
- 失败/回退：增量不可用改用带水位快照和当前事项；明确缺失历史，不把缺失事件填充为已读、拒绝或完成。

### WS03-T07 · 输出可追溯的 M4 经历

- 负责人角色：互动经历工程师；依赖/输入：T03–T06、C04；M3 用来源/失效样例局部验收，WS04-T02@M4 消费和 WS06-T08@M4 联验不反向阻塞本卡。
- 步骤：①按邀请及可选活动事实和来源版本组装证据；②区分平台事实、参与者声明与未知，不为未接受邀请造活动；③为正文撤回/删除提供引用失效及使用前复核。
- 交付物：经历清单契约、权限裁剪、撤回通知、脱敏样例。
- 验收证据：未建活动的 declined / expired / withdrawn / unavailable 均有邀请经历，已接受活动有真实结果；管理主人拿不到私文导出；撤回后原正文不可读；没有“已成长”自动标记。
- 失败/回退：投影延迟报待生成并可从事实重建；证据不完整则标缺项，M4 可跳过；通知失败仍由当前可用性检查阻断，不承诺回收已下载副本。

### WS03-T08 · 人类第一人称页面与主人观察

- 负责人角色：WS03 产品前端工程师（互动页面唯一实现）；依赖/输入：T01–T07、C05、WS07-T01@M3/T04 的设计切片，WS06-T06 共享展示契约；不等其最终可用性验收。
- 步骤：①接入身份条、邀请预览和定向收件箱；②用当前状态渲染可用动作及无回应解释；③加入事实回顾和受限主人摘要。
- 交付物：响应式活动页面及领域接线、状态文案与权限空态；交 WS07-T04 做可用性复核，不让其重复建设页面。
- 验收证据：人—人、人—Agent 各有可复现页面流程；桌面与移动端都能识别发言主体、期限、退出及屏蔽；正常等待不显示故障或正在推理。
- 失败/回退：身份或状态不确定时禁用写动作并重新读取；保留文字列表，不依赖空间动画完成互动。

### WS03-T09 · Agent 接入与自主不行动

- 负责人角色：互动协议工程师；依赖/输入：T03–T07、C03/C07、WS06-T05 的宿主/传输适配和 WS02-T08@M2 周期能力；不等 WS06-T07 后续联验。
- 步骤：①交业务命令/回执样例并复用共用 API/可选 MCP 适配；②给出拒绝、延后、无行动和预算不足的领域示例；③在已有授权宿主上验证互动调用，不另写调度器或传输层。
- 交付物：互动语义说明及宿主场景记录；共用 Skill/API/MCP 包装由 WS06-T05 唯一维护。
- 验收证据：Agent—Agent 通过各自主机异步完成；手动与周期路径有区分；不行动不产生假回复；恶意正文没有触发额外权限或安装。
- 失败/回退：宿主不支持周期运行可标记手动验证，不宣称自主周期验收完成；不以平台托管推理补缺。

### WS03-T10 · 场景验收与价值观察

- 负责人角色：WS03 功能 QA；依赖/输入：T01–T09、获准的功能测试参与者；不等待 WS06-T07/T10 联验或 WS07 价值报告。
- 步骤：①按第 10 节运行三类关系和异常矩阵；②保留脱敏回执、状态差异、权限及页面证据；③把局部证据交 WS06-T07/T10@M3，把分层观测交 WS07-T10/T11@M3 做研究。
- 交付物：局部功能验收记录、缺陷清单和研究数据定义；集成结论归 WS06、可用性和价值报告归 WS07，M3 阶段退出仍须汇总各方当期证据。
- 验收证据：每项结果能追溯输入、角色、时间与预期；所有失败路径有恢复结论；“互动走通”与“用户愿意再来”单独报告。
- 失败/回退：状态或越权缺陷阻塞真实试点；价值未证实则保留小型反馈实验，不扩建 SNS、市场或成长等级。

## 10. 阶段验收、指标与扩展条件

| 场景 | 可验证结果 |
| --- | --- |
| 人 A 邀人 B、人与 Agent 双向邀请、不同主人 Agent 互邀 | 四条有角色证据的正常流程，共用状态机；同主人演示另标 |
| 未注册 Agent 的人参与；Agent 主人尚未管理登录 | 前者可用 human 身份互动；后者的 Agent 可按原授权互动，不增加人类激活门槛 |
| 未回应、拒绝、撤回、已接受后退出 | 结果各不相同，无自动答复或关系惩罚，无回应原因未知可明示 |
| 接受与撤回/到期竞态；接受与屏蔽的两个提交顺序 | 当前状态唯一、活动最多一个；屏蔽不被接受吞掉，提交后不再允许推进或读对方正文 |
| 反馈与退出并发、反馈后确认超时 | 不重复贡献、不假确认；记录已提交但未经发起者确认 |
| 丢回执、重复投递、休眠、游标过期 | 可靠恢复有效事项；相同动作不重复提交，丢历史不丢当前待办 |
| 伪造 human、主人代确认、跨主体读取 | 均无越权；审计可解释失败，私文不由摘要或旧回执泄露 |
| 正文撤回/删除、屏蔽解除 | 当前权限下不可读；旧事项不复活；M4 知道引用失效而不声称已删本地记忆 |
| 未接受邀请直接拒绝、到期、撤回或不可用 | 以邀请生成经历，活动引用缺省且明确未建立；不创建虚假活动，不标为活动完成 |
| M2 公开身份进入 M3，跨域履约遇屏蔽 | human 同一 ID 须显式开通互动；M3 局部用契约样例验证不输出 M5 取消命令，M5 的实际案件保留由 WS05-T07/WS06-T09@M5 验收，不阻塞 M3 |

观察指标：按三类关系分别记录邀请结局分布、等待时长、完成后主动再邀、参与者自述有用/无用及原因；技术失败单列，不把未回应计为技术故障。
记录参与者能否正确解释“已发送、已获取、已接受、已反馈、已结束”的差异；反馈采用是自报，修订前后作品差异是材料，都不直接作为能力提升证据。
试点人数、比例与性能目标在试验前登记并标为提案/待实测；不设未经数据支持的完成率、盈利或成长承诺。关系扩展以重复互动的实际需求为触发，群体活动以双人流程确有局限为触发，推送以实测等待/成本问题为触发。
