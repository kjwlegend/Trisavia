# M3 互动：按用户可见结果交付

[总索引](../../INDEX.md) · [用户故事](01-user-stories.md) · [功能与流程](02-features-and-flows.md) · [技术设计](03-technical-design.md) · **交付规划**

状态：规划提案，尚未实施；已完成[本次阅读层复核](../../planning/readability-review.md)。原任务卡内容保留，本文按可演示增量组织交付。

## 先后顺序

先准备参与身份和文字 → 再做邀请及反馈 → 补齐退出、隐私和恢复 → 接通经历、页面与真实 Agent → 最后验证功能与参与价值。

设计样例可以先于实现提供；集成和可用性复核必须等相应实现可用，不能反过来堵住开发。成长和服务的完整实现都不是本阶段前置。

## 增量一：我知道自己以谁的身份、分享什么

**演示结果：** 人以自己的身份进入，小岚以 Agent 身份进入；各自可准备发给阿禾的一版文字，预览受众。

- 原任务：WS03-T01、WS03-T02。
- 实际前置：WS01-T01 的身份边界、WS02-T01/T03 的对象与读取规则；T01 先交静态身份样例，再接 WS01-T09@M3 的参与授权。人类公开资料不等于已获互动权。
- 先决定：首个文字主题、长度和分享说明；人类认证方案与注册工作流统一。
- 验收：无 Agent 的人能参与；管理 Agent 的入口不能冒充本人发言；修改原文不会改掉已经选定的版本。
- 失败时：权限或版本不能确认就停止发送，保留草稿；上游未完成时仅做明确标为测试的演示。

## 增量二：我们能自愿完成一次文字交流

**演示结果：** 小岚发邀请，阿禾接受并提交反馈，小岚确认收到并结束；另演示拒绝和无人回应。

- 原任务：WS03-T03、WS03-T04。
- 实际前置：增量一，以及 WS06-T03 已提供的共同保存与回执能力；无需等待平台互动终验。
- 验收：重复提交只有一次邀请；接受与撤回同时发生时结果唯一；没有反馈不能确认结束；反馈已提交但未被确认时如实显示。
- 失败时：查询原操作及当前状态；不盲目换新标识重发，不用模型补造缺失的回复。

## 增量三：可以放心退出，也能隔天回来继续

**演示结果：** 双方能退出、屏蔽或撤回正文；设备离线后再次进入，仍能找到有效事项，也不会继续已终止活动。

- 原任务：WS03-T05、WS03-T06。
- 实际前置：邀请及活动流程；WS02-T03 的读取规则、T04–T07 的同步、当前事项与恢复能力；复用 WS06-T03，不另建一套收件服务。
- 验收：屏蔽与接受无论谁先提交，屏蔽最终都生效；解除不恢复旧共享；网页查看不吞掉 Agent 尚未处理的事项；列表读取不完整会明确说明。
- 失败时：先拒绝受限动作和正文读取；同步有缺口时改查当前事项，不把缺失历史写成成功或拒绝。

## 增量四：人、Agent 和主人都能看懂发生了什么

**演示结果：** 人在网页完成交流，两个不同主人的 Agent 异步完成交流，主人之后能看到获准的经历摘要。

- 原任务：WS03-T07、WS03-T08、WS03-T09。
- 实际前置：前面增量；WS07-T01@M3/T04 先交页面设计，WS06-T06 交共同展示约定；Agent 接入复用 WS06-T05 与 WS02-T08，不另建调度器。
- 并行安排：T07 可先以来源与撤回样例核对经历输出，不等待 M4 成长实现；T08、T09 在各自输入齐备后分别推进。
- 验收：拒绝邀请也有真实经历且没有虚构活动；主人摘要不泄露对方私文；Agent 可以不行动；不支持周期运行的宿主明确标为手动演示。
- 失败时：保留文字列表和手动路径；来源不完整时标明缺口；不以平台代跑 Agent 补齐演示。

## 增量五：确认流程可靠，再判断交流有没有价值

**演示结果：** 分别重走人—人、人—Agent 的两个方向及 Agent—Agent，再解释无回应、退出和屏蔽结果。

- 原任务：WS03-T10 汇总前九项；完整场景见[原方案 §10](plan.md)。
- 实际顺序：T10 先完成本领域检查，交 WS06-T07/T10@M3 集成验证；WS07-T04 做页面可用性复核，WS07-T10/T11@M3 负责获准的体验研究与价值报告。
- 验收：能从角色、输入、时间、提交结果和页面重走各条路径；技术失败与正常不回应分开；“交流完成”与“愿意再次参加”分别报告。
- 失败时：越权或状态错误阻止真实试点；交流价值不明确时保留小范围实验，不据此扩建好友、市场或成长等级。

## 当期完成标准

交付范围是完整的双人文字反馈流程、异常恢复、三类主体入口和真实经历。不得为了画面热闹，伪造对方在线或自主活动。

真实宿主、集成、页面理解与领域证据需要汇总后才形成阶段结论。规划文字和静态示例本身不算通过实际验收。
