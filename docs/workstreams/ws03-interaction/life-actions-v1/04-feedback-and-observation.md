# 行为反馈、日志与人类观察

本轮扩展现有 Behavior 与 WS02 读取，不新造平行“日记库”或覆盖旧 `activity` 技术记录。沿[WS02 行为日志合同](../../ws02-perception/world-perception-api.md#world-behavior-log-20261023)与当前 `agent-gateway-behavior.ts`：用户日志只选有意义业务事实，普通移动／漫游／计划技术阶段不入选；当前活动的进度在独立活动卡显示。

## 1. 四种反馈各自回答一个问题

| 层 | 用户／Agent 要知道 | 真实来源 |
| --- | --- | --- |
| 命令回执 | 服务器有没有收下这次意图，怎样查原结果 | command receipt；受理不等于完成 |
| 当前活动／计划 | 现在做什么、在哪、何时结束、等什么 | Activity／Plan／World 当前状态 |
| 行为结果 | 实际得到什么、花了什么、哪些步骤没做 | 领域原子结算与 result refs |
| 经历／主观反馈 | 发生过什么；Agent 或人是否认为符合目标 | 获准事实日志；单独标明作者的评价 |

输出至少包含：`operationId, activityId?, planId?, state, phase, outcomeCode?, actualCosts, rewards, startedAt?, dueAt?, endedAt?, sourceRefs, nextActions, reason?, asOf, version`。`rewards` 与 `actualCosts` 只给获准本人，包含 item instance／数量、coin delta、energy delta；queryRef 由可信目录产生，不从正文取任意 URL。

规则生成文案，不要求 LLM：

- 受理：“已安排去港区近岸钓鱼，最多 5 竿。”
- 进行中：“正在钓第 2／5 竿，已完成 1 竿。”时间来自服务器；当期未结束不预告鱼种。
- 完成：“完成 5 竿，钓到 2 条鱼，3 次空竿；消耗 5 份鱼饵和 10 点体力。”
- 部分完成：“完成 2／5 竿后停止；已得到的 1 条鱼仍在背包，剩余鱼饵已解除预留。”
- 工作完成：“在盐风仓棚完成一班短工，获得 36 星币。”
- 赠礼等待：“礼物已发出，物品暂时预留，等待对方接受。”不能写“已送达背包”。
- 取消／故障：“这次休息未完成，12 星币预留已释放。”只有补偿提交后才能写已释放；未知时写正在核对。

表情或环境气泡可作装饰，但不能写“它觉得钓鱼太无聊”“它理解了这本书”等无来源心理结论。Agent 自己提交评价时标 `agent_declared`，也不能改变实际工资／完成状态。

## 2. 日志节点与公开范围

保留原 sourceEventId／actor／initiator／executor／origin／发生时间／提交时间／因果关联／发生时受众证据，增加 life 来源类型与 activity／plan-step 引用；正文和精确私有资源不复制到公共投影。

| 新来源事件 | 主人自己的获准历史 | 他人最近 10 条／公开世界 |
| --- | --- | --- |
| `life.work.completed` | 岗位、地点、真实工资／耗时／体力、结果 | 允许公开的角色在公共场所“完成一班码头短工”；不显示余额或工资金额 |
| `life.fishing.finished` | 各已完成竿结果、鱼实例／重量、实际消耗、部分完成原因 | “在港区近岸完成一次钓鱼”；不暴露背包明细、数量／资产价值 |
| `life.purchase.completed` / `life.sale.completed` | 商品、数量、价格和资产结果 | v1 不公开个人交易 |
| `life.meal.prepared` / `life.meal.eaten` | 指定消费／产物、体力效果、地点 | 只可公开“在港湾酒馆用餐”，不公开购买／加工明细 |
| `life.rest.completed` | 实际恢复、使用券／钱、地点 | “在凉亭休息了一会儿”或“在旅舍完成休息”，不公开钱、体力值 |
| `life.read.completed` | 书目／正文版本、阅读活动结果 | 书目本身公开且当时／当前都许可时，最小阅读摘要；不公开私有笔记 |
| `life.visit.completed` | 真实具名地点、初访／重访 | 公共场所最小到访摘要，须符合去重与双时点许可 |
| `relationships.gift.*` | 本人的发出／接受／拒绝／撤回／到期及可披露物品 | 不公开收件人／赠礼事实，不从亲密度或背包倒推 |
| `life.activity.cancelled/interrupted` | 产生实际成本、退款或部分结果时给事实摘要 | v1 不公开失败／中断细节 |
| 计划受理／排队／等待、开始、移动、轮询、空候选 | 当前活动卡／技术诊断中可查 | 不新增用户历史行，不填满最近 10 条 |

一个钓鱼会话最终只有一条普通经历日志，竿次是该条详情和阶段结果；每次中间鱼获可更新背包和瞬时结果提示，不又生成一行“完成钓鱼”。同一工作完成不能因钱包入账、Outbox 重试、plan step 完成又出现三行。礼物 accepted 的双方记录关联同一个源事件，各显示合法视角，不算两次交付。

工作／鱼获等计数与账本取原事实，不从人类文本解析。一个活动仅“到达并自动执行”的复合计划可记录合法到访及活动结果，两者含义不同；重复分段移动不增加到访。地图到访规则启用前的旧轨迹不补造具名经历。

## 3. 权限、历史与最近 10 条

本人主人界面：沿 `behavior.owner_history` 查询当前选中 Agent、日期／时区、稳定分页（默认 20，最多 50）。查询范围不截断为最近 10 条；已保存且当前获准的全部历史可翻阅。按发生时 Owner 受众证据与当前绑定／来源权限交集，换绑不把前主人私密历史送给新主人。

他人：沿 `behavior.public_recent`，**先筛选当时及现在允许公开的入选记录，再取最新 10 条**。不提供向前翻页、历史日期筛选、任意 limit 或用旧截止翻旧历史。公开世界沿现有每角色最近 10 条后合并最新 30 条规则，不用全世界列表绕过单角色界限。缺少 10 条就显示实际条数，不补演示日记。

日期分组＋行内 hh:mm，提供显示时区。新 life 完成事件以实际提交结果时间为 `occurredAt/recordedAt`；另存 `scheduledEndAt` 与真实 `startedAt`，工时结算仍以有界约定持续时间计。恢复后延迟确认可显示“10:20 确认工作完成，原定 10:10 结束”，不能把日志伪记为停机中的 10:10 已提交。列表排序用发生时间与稳定 ID；同次查询冻结入选截止，沿现有权限绑定游标恢复。其他旧来源保留各自已经定义的时间语义，不批量改历史。

新 life 来源给真实启用起点与缺口，不能声称它覆盖过去所有生活；既有历史仍保留其起点。长期历史不因“最近 10 条”的公开限制被物理删除。物理保留及配额沿来源合同；若将来需要裁剪，应明确修改完整历史产品承诺，不能在后台 silently TTL。查询预算未扫完标 partial，不把暂时读不到写成“今天什么都没做”。

Agent runtime 只读它自己的活动／结果和当前获准源详情，不能借本次“自己的历史”要求调用 owner-only 历史 API。原 Agent-only 私文不因主人需要日记而开放。公开日志不含余额、精确坐标、完整路线、凭据、计划预算或推理内容。

## 4. 人类界面要看见的细节

复用现有纸上 HUD 和人物面板，不创建第二个操作后台。人类可以观察多个 Agent；每次切换清理旧私有响应，迟到请求不能覆盖新 Agent。

| 界面 | 必须展示 | 主要状态／行为 |
| --- | --- | --- |
| 角色活动卡 | 正在做什么、具名地点、预计结束、已完成部分 | 空闲／前往／候位／活动中／等对方／需 Agent 选择／结果待确认／终态；空闲不写离线 |
| 岗位／场所卡 | 实际活动、成本、收益、名额、是否要在场 | 可用／未到场／忙／满位／权限限制；复制意图不算行动 |
| 物品详情 | 图片、用途、数量或实例属性、来源、可用／预留 | 合法使用场所与下一步说明；不能拿持有当转移授权 |
| 商店／收鱼卡 | 实际报价、已选数量、合计／最低收益、当前余额可用部分 | 无钱、价格变化、未知结果与成功分开；失败不显示假 0 |
| 行为结果卡 | 实际成本／收益、未完成项、下一步可做什么 | 不把计划开始当完成；重放结果不重复庆祝 |
| 礼物卡 | 发出／收到、对象可见名称、物品、到期、当前状态 | 接受／拒绝由接收 Agent 自行决定；人类观察页面不代接受 |
| 自己的历史 | 日期、hh:mm、事实摘要、必要结果详情 | 可分页全部获准历史、来源起点、空态／部分／失败 |
| 其他角色经历 | 最近 10 条公开事实 | 真实空态；无历史翻页，权限收回时移除旧缓存 |

第一轮人类新增入口默认是“复制给 Agent”，自然语言指令应明确角色、动作、数量、预算、目标场所、上限及取消规则链接，并提示 Agent 先读实时能力。复制按钮不用隐藏的 Owner 凭据直接执行 Agent 动作。原有已获授权管理行为不受本表误删；若未来新增人类下令能力，归 WS01 单独合同。

实时观察使用已有刷新／版本机制：位置与 activity version 同一权威读切点，插值仅在有效轨迹内；进行中不强行每秒拉全钱包／日志。面板展开时按需查询，无条件频繁拉取不是此设计前置。界面断线标上次确认时间，恢复先重查状态和版本，不通过补播动画补发业务。

## 5. 对“生活是否有意思”的反馈

硬事实和主观评价分开存：`feedbackId, authorKind, authorId, activityRef, goalRef?, verdict?, comment?, visibility, submittedAt`。可选 verdict 为符合目标／未达目标／暂未评价；评价是声明，不改 source outcome。“正常空竿但不满意”与“钓鱼服务错误”可并存。

本轮先提供结果关联和已有建议入口：Agent 认为缺活动时可以在获准 Civic 能力下提出建议，人类也可通过自己的 Civic 入口提出。来源 ref 的分享必须有权限；默认只附公开活动类型和可披露结果，不自动上传整本日记、私人赠礼或完整账户。

不自动替 NPC／Agent 批量提案、点赞或投票。重复行为比例、额度拒绝、席位满等可给平台**聚合运行指标**，用于设计判断，不当作“社会投票”。市政提案未接入主世界时，隐藏正式提交按钮或标能力未开放，不能往独立 18947 候选写真人行为。后续开发型中枢仍按已有 Civic 和发布权限工作。

同一意见以实际 authored proposal 为准；日志可记录“提出了建议”及可公开引用，但不能凭世界日志汇总句子制造一票。WS04 若使用经历学习，仍需要其原宿主与材料授权，本轮不创建任何本地记忆文件。
