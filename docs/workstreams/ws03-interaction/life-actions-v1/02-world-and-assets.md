# NPC、场所、物品图片与活动表现

本章是交原设计总监及 WS07 的**制作规格**，不是已制作素材包。行为、地图几何和美术资源通过稳定 ID 关联；名称或图片变化不改变业务身份。所有正式资源须沿项目已有素材授权记录，现有 Sunnyside 素材先查可复用部分，缺少时再制作，不能从网络随意取版权不明图片。

## 1. 空间层级与场所合同

沿总指挥既有世界地图任务：世界 → 板块 → 清昼小镇场景 → 场所 → 服务站／活动区。日落海、逐鹿原等规划板块不因本包开放。钓鱼发生在出生小镇港区的海岸。当前画面上的建筑没有室内，本轮第一版活动区布置在可见外场、亭廊、栈桥和门前明确休憩区；不能把角色站在街道称为已经进房间睡觉。

| 场所 ID／名称 | 对齐现有建筑或新区域 | 必须可见的内容 | 有效交互／占用 |
| --- | --- | --- | --- |
| `town_hall` 市政厅 | `p-hall` 山台会馆 | 迎新服务牌、镇长位置、现有 Civic 入口 | 旧迎新／公告；不重复新人奖励 |
| `harbor_work` 码头工作区 | `h-warehouse` 盐风仓棚外侧 | 岗位牌、4 个工作点、箱件表现区 | 4 个作业名额；物件是场景道具，不自动成为可拾取背包物 |
| `harbor_tavern` 港湾酒馆 | `h-tavern` | 3 个帮工点、4 个餐位、2 个厨房服务点、外卖窗口 | 工作／用餐／加工的席位分别计算；买东西不占餐位 |
| `stone_inn` 石岸旅舍 | `e-inn` | 4 个有遮蔽且看得见的休憩位、价目与用券说明 | 旧券和新付费休息共用容量；不重复占两套床位 |
| `fisher_shop` 渔人小铺 | `e-stall` | 鱼具柜、收鱼篮、清楚的自助交易标识 | 瞬时买卖，无持续身体席位；仍需到达服务区 |
| `blue_library` 蓝檐书屋 | `n-blue` | 馆藏架、4 个外廊阅读位、售书点 | 阅读席位与购书分开；不提前开启“所有建筑室内” |
| `garden_bench` 花径凉亭 | `g-pavilion` 附近 | 6 个长椅／桌边休息位、植被遮挡层 | 用餐与休息共享 6 位；到访只在公共区域停留 |
| `harbor_shore` 港区近岸 | 新语义区域，设计总监在港区落点 | 4 个面水钓位、岸线、不可通行水面 | 钓位必须在陆地；观景访客走专用旁路 |
| `harbor_pier` 外侧栈桥 | 复用／扩展港区 docks，由地图作者定 | 3 个面水钓位、连续步道、防遮挡边缘 | 不能把钓位设在桥梁必经格导致堵路 |
| `lookout` 穹顶观测台 | `p-observatory` 外侧 | 观景区域和场所铭牌 | 到访，不发币；不暗开望远镜等新动作 |

表中容量唯一数值来源为 `catalog.json`；不是同时可站立的像素人数。角色可在公共走道经过，但必须预约活动点才可开始耗时活动。

设计交付包含一个语义 manifest：`placeId, parentSceneId, anchorBuildingId?, name, polygon/cells, entrances, approachCells, stations[{id, actionIds, capacity, cells, facing}], walkableVersion, visualAnchor, occlusionLayer, assetRefs`。一个 station 的活动格不得与墙／水／未开放区重叠；入口有到达生成点的连通路径；工作、钓鱼、餐饮、休息的必要站位不能复用同一格。公共到访区域可容纳经过者，不消耗钓位。

现有坐标只作建筑锚点：不在本业务文档凭空填未经验证的钓位坐标。**生成最终 cells、可达路径与可视样稿是地图制作任务的必交付物**，不是留给 API 作者临时决定。若只增加语义区，发新语义版本并绑定原几何 digest；若新增栈桥可走格，必须发新地图／拓扑版本，不修改已发布 `pixel-town-v2` 的固定文件或 SHA。

新旧几何切换：作者提供活动格与路径的映射；TD 在切换前排空或按系统中断结算受影响活动。原角色可走位置不删；确实需要重定位时用显式维护规则和事实记录，不能静默传送后继续计工时。未经生产合同校验的预览 JSON 不装入生产。

## 2. NPC 的角色，不是每天的剧本

NPC 是服务端管理的居民实体，明确 `actorKind=npc`；不注册成外部 Agent，不占用用户 Agent 数量，也不出现在“真实外部 Agent 参与”的验收计数里。现有 3 位保留 `npc-mayor/npc-tavern/npc-innkeeper` 稳定 ID；新增 4 位为本轮设计 ID，正式显示名由文案作者统一命名。

| NPC | 职责与约束 | 可选择的生活行为 | 个性偏好（选择权重，非台词日程） |
| --- | --- | --- | --- |
| 镇长 | 迎新／市政介绍；已有 Civic 范围保持 | 值守、去凉亭休息、书屋阅读、观测台到访 | 公共事务／阅读高，钓鱼低 |
| 酒保 | 酒馆介绍与迎新招待 | 值守、购买餐食、吃饭、近岸钓鱼、休息 | 饮食／社交高，偏好近岸 |
| 旅社老板 | 休憩服务介绍 | 值守、阅读、凉亭休息、到访 | 阅读／宁静高，工作兴趣低 |
| `npc-harbor-hand` 码头熟手 | 介绍岗位，但不替系统发薪 | 码头短工、吃饭、栈桥钓鱼、休息 | 工作／钓鱼高 |
| `npc-fishing-clerk` 鱼具店员 | 介绍鱼具、收鱼规则 | 值守、买饵、两处钓鱼、卖鱼、休息 | 钓鱼高，近期重复同点会换点 |
| `npc-librarian` 书屋管理员 | 馆藏介绍，不声称理解居民私文 | 值守、阅读、观景、喝茶、休息 | 阅读／探索高 |
| `npc-neighbor` 自由镇民 | 无固定服务职责 | 两种工作、购买、钓鱼、用餐、阅读、到访、休息 | 多种兴趣均衡，承担选择多样性的观察样本 |

每位 NPC 保存 `preferences, energy, wallet, holdings, recentActivityIds, currentGoal, nextDecisionAt, planRef, policyVersion`；同类偏好可以不同，禁止以当前文案或名字作逻辑分支。偏好不等于推理记录，不给它编造长篇内心独白。

各 NPC 的数值偏好与启用切片见 `catalog.json/npcProfiles`；没有列出的自主目标不入选。动作尚未随切片上线时暂不入选，不用假成功补齐它的生活。没有职责地点的居民不生成 duty 候选。

### 2.1 第一版主动选择器

在活动结束、必要条件失效、到期检查时生成候选，最多每 60 秒做一次新选择；空闲角色也有有限 dueAt，所以不依赖有人打开页面。已开始的有效活动继续执行，最低 120 秒目标驻留用于抑制频繁改主意，不能拖延已经终结的活动或覆盖高优先级取消。

选择器先硬过滤：能力启用、当前权限、可达、体力／物品／余额、当日额度、场所容量、无前景占用。之后按同一策略评分：

过滤对象是**有界生活目标及其所需步骤**，不能因刚出生没鱼竿就永久排除钓鱼。目标模板如下；它们定义做事方法而非按时刻播放的日程，资源不满足时目标不可选，不能借机自动补钱：

| 目标 | 明确的有限展开 |
| --- | --- |
| work_harbor／work_tavern | 前往对应岗位 → 一班工作 |
| fish_shore／fish_pier | 缺竿则去小铺购买 1 根；鱼饵不足则只补足 2 竿所需 → 前往选定钓点 → 钓 2 竿；必须能负担整个购买上限 |
| sell | 选自己至多 3 条可用鱼，按捕获时间／稳定 ID 取最早 → 前往小铺 → 按最低收入保护出售；不卖被预留鱼 |
| eat／tea | 已有对应餐食则使用，否则去酒馆只购买 1 份便餐／茶 → 到可用餐位消费；体力满时不选 |
| rest | 前往免费凉亭 → 一次休息；NPC v1 不为恢复自动选择付费旅舍 |
| read | 前往书屋 → 免费馆藏阅读；不自动购书 |
| visit | 从已启用地点中选近 24 小时未完成到访者 → 前往 → 完成到访；全部近期去过则候选为空 |
| duty | 前往职责点 → 一段有限值守 |

没有钱买鱼具的 NPC 仍可在其 profile 支持的岗位挣钱或选择免费活动；服务 NPC 可以耗尽最初预算而转向免费生活，不无限补贴或偷走商店收款。每个模板也走同一 Plans／领域接口，消费预算由 NPC policy 明确给出，不获得人类运行身份。

`score = need + duty + preference + novelty - travelCost - recentRepeat`

- `need`：体力 <30 时免费休息 +80；30–59 时休息／饮食 +35；已满时恢复类被过滤。
- `duty`：当值守窗口不足时值守 +45，否则 +10。值守只在设施点进行，不凭“有顾客”预读居民私人任务。
- `preference`：profile 中各活动 0–30；各 NPC 不同。
- `novelty`：最近 6 次已完成活动未做过该活动 +15；新场所 +10。
- `travelCost`：`min(20, estimatedTravelSeconds/10)`；没有路线的候选已排除。
- `recentRepeat`：最近 2 次每次同活动扣 20；有其他可行活动时，连续 3 次同活动暂停入选一次。

平分用 `npcId + decisionSequence + policyVersion` 的稳定种子选择，使重试不重选，又不让所有居民同步转身。候选为空时原地空闲 60 秒再检查；体力低优先寻找免费椅，不能凭空补钱／体力。现有闲逛是最低优先级、有界空闲活动，不抢当前目标。

值守作为 NPC 专用有界行为 `npc.duty`：在服务站停留 180 秒，体力花费 0，不自动发币、不对居民发消息，结束后再选；不暴露给外部 Agent。一个职责 NPC 在滚动 30 分钟内累计值守低于 6 分钟则启用上面的高 duty 权重。仍可休息、钓鱼，不按固定小时表循环。

每个场所 NPC 最多占 1 个活动席位，且至少留 1 个总容量席位给外部 Agent；若不满足，NPC 不候位抢位。NPC 不抢占已开始的居民活动，也不通过“系统身份”绕过成本。

经济初始化单独具名：这批 NPC 首次启用各 80 星币／100 体力，无自动补发，稳定初始化 ID 防重；鱼竿／饵从商店购买，后续可工作挣钱。NPC 收支单独归类，但用相同价格、额度、库存结算规则。商店系统服务不是店员私人钱包；不靠其余额决定是否收鱼。该有限 NPC 初始化不修改真人余额／欢迎权益。

### 2.2 服务连续性与历史接口

设施的常备交易、岗位牌、休憩预约可自助；NPC 当前不在场时写“店员外出，可使用自助交易点”，不能说“酒保递给了你鱼竿”。现有 `town_services` 欢迎／招待／休息入口、券和唯一权益不直接删除；升级须为原动作提供兼容适配与精确新指南。

具体 NPC 的问候须根据**当前位置**求合法接近格，角色离开后不在原坐标产生问候。设施迎新领取可在原服务点由明确的迎新柜台执行；旧接口名可保留，但完成记录区分 `executor=facility` 和实际在场 NPC 接待，不把不在场镇长写进交互事实。固定“酒保说……”话题需要酒保值守才能执行，否则返回 `provider_away` 与下一次可检查时间，不扣券；不伪造人际对话。旅舍原券规则为设施服务，不受老板外出阻断。

以上是旧固定 NPC 合同的明确扩展，由 WS02／WS03 与 TD 接管；不能仅移动精灵而不改服务校验。浏览器展示 NPC 的真实当前位置／动作，初始 map NPC 位置只是生成点，不继续当运行真源。

**WS03接管补充（2026-10-25）：**设施自助完成不能被记成与缺席NPC交往；新开始的facility路径不新增该NPC熟悉度或伪造问候，实际NPC在场接待才沿原关系计分来源处理。升级前已经开始／完成的操作保留原规则和事实，不重算旧熟悉度；新版指南须区分服务效果与关系效果。既有新人活动ID、已领卡／100星币／双券权益及去重来源不变，不能以服务改由柜台执行为由重新发放。尚未领取者仍须真实到达原迎新服务区，不能把自助适配改成远程领取。

### 2.3 未来替换为服务端 Agent

模型只可从相同候选动作中给出有界 plan 提议，不能直接写位置、余额、物品或关系。必须保留费用上限、超时、当前授权、结构校验及规则选择器回退；模型输出不通过时继续可解释规则策略。这是预留接口，不在本轮安装模型／后台推理／新密钥，不把外部 Agent 托管进来。

## 3. 物品与图片清单

本轮新增 9 个物品类型；加原 3 类物品共 12 类。星币、体力、岗位、鱼获经历、席位和书屋馆藏都不伪装成背包物品。鱼实例共享品种图片，重量是文字属性，不为每个克重生成 PNG。

| ID／物品 | 图片必须可辨的轮廓 | 实际功能／详情字段 |
| --- | --- | --- |
| `basic_rod` 木柄鱼竿 | 木柄长竿、线轮、收拢鱼线，不画成武器 | 工具；可重复用；持有／使用预留／来源 |
| `bait` 通用鱼饵 | 小纸包打开露出饵粒，区别于食品 | 数量、每竿耗 1、预留数 |
| `sardine` 银纹沙丁鱼 | 细长银身、深色背线 | 品种、克重、钓点、捕获时间、收购价 |
| `mackerel` 青背鲭鱼 | 更厚鱼身、青背条纹 | 同上；不能只给沙丁鱼换色 |
| `sea_bass` 花斑海鲈 | 宽体、背鳍与明显斑点 | 同上；大小轮廓与前两者明显不同 |
| `bread_meal` 麦香便餐 | 面包＋小碟，单份餐形态 | 数量、用餐时长、恢复体力、来源 |
| `herbal_tea` 草本茶 | 小杯、叶片、少量蒸汽 | 饮用时长、恢复值，与迎新招待券图不同 |
| `grilled_fish` 香煎鱼餐 | 餐盘、熟鱼、配菜 | 已加工食物，不能误认成可再次收购的生鱼 |
| `harbor_handbook` 港湾生活手册 | 小册子、封面海浪／书签，无细小正文 | 书目、正文版本、阅读入口、可转赠 |

居民卡／招待券／休息券沿原素材与 item identity；如现有没有正式图，补 3 张图片属于设计任务，不重发物品。馆藏指南另有书封／场景书脊，可复用书本图形但不进背包。

图片交付规范：

- 32×32 透明 PNG 逻辑像素，四周至少 2px 安全边距；背包 32／64px 整数倍 nearest-neighbor 呈现，详情最高 128px 同源放大，不模糊拉伸。
- 与当前像素世界及纸上 HUD 配色、描边对齐，白／浅纸／暗地图底都可辨；物品本身不写价格、数量或长文字，徽标由 UI 渲染。
- 同套资产包含 atlas 与 manifest（逻辑大小、frame、pivot、assetId、itemId、版本、sha256、来源／授权、alt 文本）；图集边缘留 padding 避免串图。
- 每张图配 32px 原尺寸和 2 倍背包预览；9 个新增物品同屏检查“只看轮廓能否区分”；不依赖颜色区分鱼种。
- 第一轮提供制作原件及实际导出，不以链接占位或 emoji 交付正式背包。运行可用占位图降级，但未完成图不能记美术验收完成。

物品详情必须区分 `available/reserved/consumed/transferred`，当前背包只列仍持有；历史详情引用来源按当前许可读取，不能把别人的现有持有泄漏给原主人。

## 4. 人物与活动动画

复用现有人物骨架／sprite 标准，保持脚底 pivot、步幅、遮挡与方向。新增 NPC 以外观组合和职业小配件区分，不能把所有 NPC 换成同一个外观。7 位需要角色清单与 standing／walk；新增动作可共享骨架与物件叠层，不要求每位重画完整套。

| 状态 | 最少视觉反馈 | 不得据此产生的业务事实 |
| --- | --- | --- |
| 工作 | 原地搬箱／端盘 4–6 帧循环，岗位标识 | 每循环一遍不计一次工资 |
| 钓鱼 | 抛竿开始、等待 2–4 帧、收竿结果；鱼竿朝水 | 由服务端结果决定空竿／鱼获，不能动画先抽奖 |
| 用餐 | 坐姿／杯盘叠层 2–4 帧 | 碰到餐位不自动吃掉物品 |
| 休息 | 坐／半躺低频 2 帧 | 闭眼不等于活动完成或外部模型睡眠 |
| 阅读 | 持书、低频翻页 2–4 帧 | 不宣称 Agent 理解了正文 |
| 观景／值守 | 朝向与活动图标，静态也清楚 | 站立不自动问候任何人 |

减少动态模式用静态代表帧＋文字／进度；无声音也能知道结果。音效复用音频负责人已有接口，只在真实本地可见结果播一次：开始工作、买卖、鱼获／空竿、完成恢复。音频资源未就绪不阻塞实际业务，不能每次读取旧回执重复播放。

“正在做什么”文字来自 activityRef 和服务器时间；失联后冻结到上次确认并标记，不能继续播放不断获鱼／得钱动画。地图停留标签不遮住姓名与选中高亮。

## 5. 设计验收与输出文件

原设计总监拥有正式视觉包，建议放在 `docs/design/life-actions-v1/`，实际路径由其交付确认。本规格不创建空图片或假 manifest。必交：

1. 1 份场所／station manifest 与地图 overlay 样稿，明确可走／水／墙／活动点／公共旁路、面向和遮挡；两个钓点真实可达。
2. 9 张新增物品图及必要的原 3 类补图，atlas、映射清单、来源记录和非空背包／详情样稿。
3. 7 位 NPC 的角色与造型清单、新增 4 位外观、共享动作动画及各状态代表帧。
4. 岗位／钓点／商店／恢复／阅读／礼物／当前计划／结果／历史的 UI 状态稿，使用同一真实参数表。
5. 1440×900 与 390×844 的代表界面，至少一次非空物品详情、名额满、执行中、部分完成、断线、等待对方状态；长文字不盖地图必要操作。

设计可先交切片 A 的岗位／椅子／状态卡，再补 B、C；总指挥不能把“后续可由 AI 补图”当成已经完成全部美术。本章允许沿用已有建筑以加快第一轮，但后续新活动可以新增场所，不能把所有玩法永远塞在这几个门口。
