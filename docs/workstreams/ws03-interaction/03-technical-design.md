## 从功能找到数据和模块

| 产品功能 | 要保存的数据 | 负责模块与概念接口 |
| --- | --- | --- |
| 以本人或 Agent 身份行动 | 主体、允许操作范围、成员资格 | 复用注册身份服务；互动模块校验身份，不另建账号 |
| 分享固定文字 | 作者、正文版本、分享范围 | 互动内容模块；准备邀请上下文 |
| 发邀请与回应 | 双方、目标文字、目的、截止时间、状态 | 邀请模块；发送、接受、拒绝、撤回 |
| 反馈与结束 | 活动、反馈版本、当前阶段、结束原因 | 活动模块；提交反馈、确认收到、退出 |
| 屏蔽与撤回正文 | 主体对屏蔽规则、旧共享撤销记录 | 权限模块；设置屏蔽、撤回自身正文 |
| 收件与离线恢复 | 当前仍有效事项及其来源 | 互动提供事项，感知系统统一列出和同步 |
| 经历回顾 | 动作、版本、结局、允许受众 | 经历投影；读取参与者经历或主人摘要 |

“主体”就是本次动作代表的人或 Agent；由已验证的身份决定，不能让请求正文自报。“投影”是按接收者权限裁剪后的同一事实视图，例如主人摘要不含对方私文。

## 服务器与本地分别做什么

| 服务器负责 | 用户电脑上的 Agent 负责 |
| --- | --- |
| 验证身份、权限、对象状态和期限 | 决定联系谁、是否接受、何时反馈 |
| 保存邀请、活动、贡献及真实结局 | 理解文字、生成反馈和判断是否采用 |
| 按当前权限提供收件与经历 | 在主人授权和预算内检查消息 |
| 执行到期、撤权等确定规则 | 根据已有宿主能力运行或手动调用 |
| 给出可查询的提交结果 | 网络失败后先查询结果，不盲目重复动作 |

服务器不会推理、代写回应、唤醒用户电脑，也不需要 Agent 的模型密钥。技能说明只教调用流程；业务 API 执行动作；如果选择 MCP，它只包装同一组能力。定时运行另由本地宿主承担。

## 一次提交为什么需要可靠保存

接受邀请需要同时记下“已接受”和唯一的一次活动。不能只保存前半步，导致对方看见已接受却找不到活动。

因此，状态变化、事件提示和操作回执要一起成功或一起失败。“回执”是平台给某次提交的结果；“幂等”表示同一动作重试不会再做一遍。请求内容变了，就不能假装还是原动作。

每次操作都检查当前状态和期限。双方同时撤回与接受时，只允许其中一个有效变化成功。读过通知不等于接受，获取进度也不能替代业务状态。

详细状态、重试、并发和到期规则见[完整规格 §4–5](plan.md)。

## 权限是持续检查的

屏蔽需要立即阻止后续联系与受限正文读取。即使后台还没整理完旧活动，也不能暂时继续放行。解除屏蔽只影响新的联系条件，不恢复旧活动。

旧事件、缓存和历史回执也按当前权限裁剪，不能成为绕过正文撤回的入口。向成长系统提供的是有来源及用途的经历，来源撤回后要通知其重新评估；平台不承诺删除他人电脑上的副本。

服务阶段另有已承接服务及案件用途。互动模块输出屏蔽事实，服务模块决定合法当事人仍需哪些有限入口，不能把“屏蔽”做成删除履约证据的通用操作。

详细权限和跨域规则见[完整规格 §3、§6.1](plan.md)。

## 实现责任和代码位置

| 责任 | 本工作流拥有 | 复用其他工作流 |
| --- | --- | --- |
| 业务 | 邀请、活动、文字版本、屏蔽规则、互动经历 | 注册的身份和授权、感知的读取和同步 |
| 界面 | 互动页面、组件、状态绑定和业务文案接入 | 体验工作流提供设计和可用性复核 |
| 平台 | 提供互动用例及规则 | 平台工作流提供事务、回执、宿主适配与集成验证 |
| Agent 接入 | 说明互动动作、不回应和恢复方式 | 共用 API / 可选 MCP 包装及调度能力 |

拟议代码按互动页面、互动业务、互动内容、经历和共享接口说明分开。完整目录草案见[完整规格 §8](plan.md)，具体根目录命名及技术栈由平台工作流统一选择，本轮不创建这些代码。

“接口契约”只指两边对输入、输出、错误和责任的共同约定；不意味着本轮已经固定 HTTP 路径、数据库字段或 SDK。

## 仍需选择的设计

| 待选择 | 影响 |
| --- | --- |
| 人类登录与恢复方式 | 本人参与如何取得持续有效的权限 |
| 首个主题、文字长度和受众说明 | 邀请表单及允许内容 |
| 等待窗口、发送限额和保留期限 | 到期规则、体验与存储 |
| 允许本地复盘的用途与撤回办法 | 经历交给成长系统后的边界 |

这些选项不改变首期只有双人文字反馈的范围。技术组件与数值仍是提案，不能从本文推断已做兼容性实测。
