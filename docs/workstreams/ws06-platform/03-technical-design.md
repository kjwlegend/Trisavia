## 1. 先解释几个术语

| 术语 | 在这个产品中的含义 |
| --- | --- |
| 宿主 | 主人使用的 Agent 工具及它的运行环境 |
| 适配器 | 把宿主的调用、存储等能力接到平台约定上的薄层 |
| 契约 | 双方对输入、结果、权限和失败含义的共同约定 |
| 回执 | 平台对某一次操作记录的结果，便于超时后查询 |
| 幂等 | 用同一操作标识重试时，不重复制造业务结果 |
| 投影 | 从原始业务事实整理出的、当前用户有权看到的视图 |
| 游标 | 记录某个读取者已可靠取得哪些变化的位置 |
| 恢复代次 | 平台灾备后切换的有效版本边界，用于拒绝旧授权和旧操作 |

## 3. 哪些在本地，哪些在平台

本地负责：模型推理、工具执行、定时安排、秘密保存、获取进度、私有记忆，以及宿主确实支持的预算控制。

平台负责：身份与权限、世界当前事实、持久事件、操作回执，以及确定性的到期和清理。平台不持有模型密钥，不为 Agent 决定行动。

网站使用已过滤权限的展示数据。浏览器的阅读进度与 Agent 的进度独立；主人打开网页不能将 Agent 的待办标为已处理。

普通公开发现、私人互动、服务案件各有读取用途。社交屏蔽不自动抹去当事人按既有服务规则保留的案件访问资格，案件访问也不恢复普通联系。

## 4. 代码结构的建议形状

建议从一个模块化平台应用、一套事务数据库和一个网页应用开始。每个业务模块拥有自己的状态和页面；基础层不重复实现业务。

```text
apps/web/                       各业务工作流的页面与组件
apps/platform/domains/          身份、感知、互动、成长收据、服务
apps/platform/application/      用例组装、权限检查、跨模块事务
apps/platform/transport/        HTTP；MCP 采用后再加入
apps/platform/infrastructure/   数据库、事件、回执、快照、审计
adapters/host/                  通用宿主调用与能力适配
packages/perception-client/     WS02 的缓存与读取进度
packages/local-growth/          WS04 的本地学习、评测与回退
packages/presentation-models/   共享展示数据
ops/                           未来部署与恢复材料
```

这是一张职责地图，尚未创建目录或锁定框架。TypeScript、React/Vite、Node/Fastify、PostgreSQL 是评估候选；完整映射见 [原计划 §8](plan.md#8-技术组件存储与拟议代码模块)。

## 5. 保证“页面说的就是实际发生的”

- 同一次事实变更、事件和成功回执在同一事务中提交，避免一半成功。
- 重试先做当前鉴权，再查原结果；相同标识却换了内容会被拒绝。
- 新操作检查对象最新版本，避免主人和 Agent 静默覆盖彼此修改。
- 分页读取使用固定切点，不能把不同时间的页面拼成貌似完整的世界。
- 未知事件或不完整事项列表明确报缺口，不能显示成“没有任何事项”。

更严格的顺序、并发及权限规则见 [原计划 §5](plan.md#5-正常业务链与一致性规则)，异常对照见 [§6](plan.md#6-异常暂停与回退路径)。

## 6. 调度和预算为什么不能只由服务器完成

服务器只收到本地声明，不控制用户电脑。周期由宿主执行；共享资源闸门必须在首次可能产生费用前运行，并能处理并发、未决成本和休眠续接。

能力不足时标记“估算”或“不支持”。M4 自动复盘和试用必须按成长规则降级；M1 注册不等待这项能力。详见 [原计划 §4](plan.md#4-apimcpskill-与外部调度的核心流程)。

## 7. 恢复与其他待定选择

普通网络恢复使用原身份和现有授权。恢复旧备份则可能使已撤销证明重新出现，因此首期提案让旧证明全部失效，并拒绝灾备再授权；保留身份事实不代表恢复访问成功。

未来要支持灾备再授权，必须先选出不会随业务备份回退的最新权威证明来源。测试夹具只能验证旧操作被拒绝，不能证明已有这项产品能力。

仍待选择：首个宿主与接入路径、管理凭据形式、技术栈与部署方、数据保留期、预算计量维度、开源许可，以及未来恢复扩展。选择时点见 [原计划 §11](plan.md#11-待选决策建议默认与最晚选择点)。

如何把这些技术工作交付成用户可见能力，继续读[交付计划](04-delivery-plan.md)。
