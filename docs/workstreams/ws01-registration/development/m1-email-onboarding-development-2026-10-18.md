## 用户能完成的路径

| 路径 | 本轮实现要求 |
| --- | --- |
| 人先注册 | 填写用户名、邮箱、密码，收码并验码后建立账号；没有 Agent 时进入真实空态 |
| Agent 先加入 | Agent 独立取得身份及运行凭据；人从私密入口验邮箱，账号建立、目标关联及交接消费一次提交 |
| 已有账号 | 正常登录后明确确认关联新 Agent，原账号、其他 Agent 及恢复材料保持 |
| 密码和备份都丢失 | 当前绑定 Agent 发起协助，服务端向原存邮箱发码；网页独立验码后只获得本次重设权限，完成后引导用新密码登录 |
| 可选备份 | 普通注册与邮件恢复不要求下载 JSON；人仍可明确选择保存备用恢复材料，既有有效备份路径保留 |
| 响应丢失 | 页面自动保存同次浏览器证明、原操作号及必要后继材料；不保存明文密码，不把 A 的结果用于 B |

完整 HTTP 请求、响应、状态及 Node 参考客户端说明见 [公开 HTTP 合同](../../../access/v1/http-api.md)与[接入入口](../../../access/v1/entry.md)。Node 客户端为可选参考；主人验证码只在可信网页提交。

## 配置与数据交接

邮件渠道固定为 Resend，薄适配器使用原发送键和固定正文续接未知结果。发送受理不代表收信或邮箱验证，账户验证事实由主人的独立验码及最终提交建立。参见 [Resend 发送接口](https://resend.com/docs/api-reference/emails/send-email)及[幂等规则](https://resend.com/docs/dashboard/emails/idempotency-keys)。

配置模板为根目录 `.env.example`，仅说明变量，不自动加载。服务器从私有环境读取 `RESEND_API_KEY`、`M1_EMAIL_FROM`、`M1_PUBLIC_ORIGIN`、`M1_EMAIL_CODE_SECRET`；校验密钥须稳定且至少 32 字节，不能复用为网页或 Agent 证明。缺少或无效配置只关闭邮件能力，明确显示邮件服务暂不可用，保留已有登录、关联和独立备份恢复。已验证发件域名和真实投递尚未确认，本轮不索取密钥或发送邮件。

迁移 4 新增 `email_attempts` 与 `mail_jobs`，原迁移 1—3 保持；本轮仅交付迁移源码，未打开或迁移用户库。验证码验证保存 HMAC，投递正文加密保存在服务端，网络发送在数据库事务外执行。用户 `data/m1-account-v2.sqlite`、配对 identity、实例、旧分支及源码／回退快照继续保留。
