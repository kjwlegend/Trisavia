## 2. 最小可用素材与姿态

固定字节、来源、尺寸、pivot 和 recipe 见 `asset-manifest.json`。本批包含真实 PNG / SVG 文件，无空占位。

- 7 张 DOING PNG：base + 六种现有发型，均为本地已采用 Sunnyside V2.1 原字节复制，768×64，8 帧、每帧 96×64。工作取原帧 `[0,1,2,4,5,7]`，180ms/帧；帧不插值、不跨站走动。六发型齐全，避免既有 Agent 选择掉帧。
- 工作：原地手部动作 + `crate.svg`（14×12）或 `tray.svg`（16×10）；站位固定。道具不是新增可交易背包物品。
- 休息：原有 IDLE 的 0 / 4 帧上身与头发，1600ms/帧；原 PNG 不改。渲染时取帧内 `(0,0,96,36)`，相对 feet anchor 放到 `(-48,-38)`，再叠 `seated-legs.svg` 到 `(-4,-3)`。这是一套可运行的坐姿组合 recipe，**不是原包自带的 SIT 图集**。
- 长椅：`bench-back.svg`（28×14）到 `(-14,-13)`；`bench-front.svg`（28×8）到 `(-14,-2)`。先长椅后人物 / 弯腿，保留前缘与腿部可读性；所有层作为同一个座位组排序。
- 值守：原有 IDLE 第 0 帧 + 状态文字即可。NPC 策略决定何时值守，动画不决定服务是否可用。

沿原 96×64 frame、feet pivot `[48,39]`、工程 origin `[48,64]`，world source point=`[520+16*x,520+16*y]`。左右朝向翻转完整人物与道具组；不要只翻头发。坐姿含长椅外沿约 28×30 source px，地面落点相对 logical anchor 最低 +6 px；这只是外观越界，不扩大碰撞。人物与静物依脚底 y 排序，座位组以 ground y+5 为参考；既有命中区不因透明 frame 扩大。

## 3. 卡片元素与信息层级

沿已批准纸上 HUD：paper `#F7F3E8`、ink `#263F36`、muted `#68746E`、sage `#DFE5D4`、accent `#BE6346`。标题 20/28，主文 14/23，辅助 12/20；卡片 340 px、内边距 24、行组 16–20、按钮至少 36 px。窄宽卡片 310 px / 内边距 18。关键收益不用小于 16 px，状态不只靠颜色。

| 模块 | 必要元素 | 延后或删除 |
| --- | --- | --- |
| 场所卡 | 名称 / 场所图标、简短用途、实际空位与总容量、时长、完成收益或费用、体力、当前可用原因、活动说明 | 不加重复货币余额、重复地图层级、装饰编号和常驻长篇教程 |
| 当前活动 | 活动名、权威状态、实际主体、dueAt/剩余时间、预留和已结算区别、取消后的实际结果、最后同步状态 | 不把“到点”写成“已完成”；Owner 没有代 Agent 开工 / 取消按钮 |
| 满员 / 候位 | 无空位、候位上限 2、等待上限 120s、改选 / 以后再来说明 | 不默认代排队，不把候位者当正在工作 |
| NPC | 稳定 ID 与系统 shortId、原有外观、职责、当前位置、在岗 / 离岗说明 | 不造新的 N004，不留固定服务点分身，不在缺席时播放本人对白 |
| 完成 / 取消 | 来源确认的终态、实际收益 / 消耗、已完成步骤保留、释放资源 | 不从前端按时钟推算最终账本 |

预览有三个场所 × 六种代表状态（可用 / 进行中 / 满员 / 离线 / 取消 / 完成），审核切换器和下方姿态样例不进入产品 HUD。可用容量、活动记录与进度均为布局样本。真实数据缺失时显示未知，不填样本数字。

业务数值只源自 WS03 `life-actions-v1/01-behaviors.md` 与 catalog（规则交付 c473e5f）：码头 600s / 36币 / 24体力；酒馆 480s / 24币 / 16体力；长椅 300s / 免费 / 最多恢复30至100。工作开始预留体力；取消无工资，体力按实际 elapsed 比例向上取整结算，余量释放，主动取消仍占当日班次。UI直接显示服务端结算，不复制账本运算。系统强制中断按来源原因与实际释放结果显示。

可用/说明中揭示完整时长与最多成本；实际进度应附服务端下一次 UTC 日重置时刻的本地显示。近满体力预览显示实际可恢复量。新增恢复活动满体力不可开始，不为演示扣体力。旧券休息沿当前来源合同，不让新长椅卡改掉旧券的预留 / 消耗规则。
