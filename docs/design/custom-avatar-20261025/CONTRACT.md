# 自定义角色：视觉与素材合同 v1

2026-10-25。TD 已确认基础帧约束；本目录仅设计与模板，不实现 API、存储或上线。当前实际渲染依据为 `767a65c1` 的 `look.js`、`human.js`、`life-art.js` 与 appearance-v1.1。素材解析字段跟随 A 的唯一协议；B 负责真实合法可导入样例与面向外部 Agent 的生产指引。

## 角色素材

| 项目 | 固定要求 |
| --- | --- |
| 形式 | 完整角色 RGBA PNG 动画帧；帽子、尾巴、配件与非人形身体均属于角色，不套内置六款换色或 base/hair 分层 |
| 网格 | 每帧 96×64；同一动作一张水平连续 strip，左至右从 0 开始；不留格间距、无自动裁边、无每帧重新居中 |
| 脚点 | 固定 (48,39)，相对于帧左上角；世界绘制原点减去该值。不是 (48,64) 的旧工程画布原点。帧中的透明留白必须保留 |
| 朝向 | 原画面向右，左朝将完整角色围绕脚点镜像；竖向移动沿用最近横向。首版不伪称具备四方向素材；禁止角色、帽子分别镜像 |
| idle 必需 | 9 帧，125ms/帧，即 8fps；864×64。允许呼吸、眨眼、配件小动作，但脚点不漂移 |
| walk 必需 | 8 帧，100ms/帧，即 10fps；768×64。至少有接触、下压、经过、抬起及相反支撑的真实姿态；肢体、躯干、配件保持同一角色 |
| work / rest 可选 | 分别声明有无。缺失时播放该角色的 idle，并保留真实「工作中／休息中」文案；不切回内置角色、不声称有工作／坐下动画 |
| 世界权威 | 外观不改变服务器位置、路线、脚下排序依据、格子占用、碰撞与动作权限；显示动画不提交移动或触发工作 |
| 透明与像素 | 真透明背景，禁止烘入米色/棋盘格、文字、水印、舞台、地面阴影；近邻采样，不平滑像素，不按每帧 alpha 边缘缩放 |

视觉比例指引：身体通常与现有人物接近，约 16–24 原生像素高；帽饰等完整轮廓建议控制在 32×32 内、地面基准 y=39。横向尾巴可适度扩展，不能因大画布将角色画成 96×64 巨人。该比例是美术目标，不新增后端硬拒绝阈值；最终须同时预览「1×世界比例」与大图。宽尾、圆体、无双腿生物使用其真实运动方式，不强迫人类腿部结构。

减弱动态/暂停使用相应有效 clip 的固定帧。资源加载失败应呈现明确的加载错误／中性占位及重试，不冒用其他内置角色。完整 walk 缺失、空白或结构不合规阻止应用；仅有参考图不算可用素材包。机械校验不能宣称已判断步态自然：必须在工作室逐帧看接地、身份连续、帽尾完整、循环衔接。完全相同帧可检测拒绝；单帧平移、缩放和反复抖动仍需视觉检查，不能借字节不同冒充动作完成。

现行 Life 的人类 rest 使用上半身裁切加腿部资产，自定义角色不得复用。自定义 work/rest 有素材时按其完整帧播放，无素材时保留 idle。场所已有箱子/托盘/长凳属于世界对象；不要把对象同时烘进角色造成重复，不为贴合自定义角色任意移动脚点或补人腿。

## 角色工作室

采用现有纸张与深绿 HUD 语言，视觉重心是完整角色舞台。1080px 左右宽度可用三栏约 184 / 弹性≥360 / 280，栏间 20；标题 24–28，正文 14–16，辅助 12–13，主要按钮至少 40px 高。可滚动内容保持字号，窄屏改上下布局。

- 左：选择所属 Agent、当前形象、名字和「仅修改此 Agent」；当前形象与草稿分开。切 Agent 不自动应用旧草稿；应用按钮总是明确所选名字，未绑定无可应用对象。
- 中：完整角色大舞台、地面线/脚点与安全框开关、1×世界比例小预览。待机/行走/工作/休息切换、左右朝向、播放暂停、逐帧和帧条。缺可选动作显示「未提供，将使用本角色待机」，不能视觉上伪装已生成。
- 右：两条清楚路径「有参考图→复制制作指令给自己的 Agent」与「已有素材→导入包」。选择文件后先在本地预览，不自动上传。Owner 明确点击「保存参考并准备」后，将参考私有上传到所选 Agent 的准备任务，仅任务范围内获准的本地 Agent 可读；不自动生成或应用。图像生成与修正由用户自己的 AI 工具完成，网站不要求 AI key。准备任务、权限与保留规则归 WS01 / A。
- 检查反馈：把帧尺寸/透明/文件缺失等逐条展示；错误说明「哪个文件／哪一帧／期待与实际」，提供复制修正要求。结构校验通过后仍让用户在中央检查动作，不输出虚假的视觉质量分数。
- 底部：素材状态、应用到指定 Agent；应用前提示会同步世界/个人管理/公开资料。导入、预览、选择 Agent 都不是保存。恢复内置为独立操作，需明确对象与所选内置形象；失败保留原形象与可修草稿。

UI 应避免：全屏巨大上传虚线框、空白表单、仅一张静态小图标、让用户填 JSON 技术字段、把未提供的动作画成已完成、复制指令按钮假成功、导入即修改身份。状态至少覆盖：空稿、仅参考图、导入检查失败、检查通过待确认、正在应用、应用成功、应用失败、恢复内置。

同一份版本化形象在世界、个人管理、公开资料中使用同一播放器和脚点；缩略图按固定包围视窗显示整个角色，不单独裁掉帽子/尾巴。头像尺寸差异仅为显示缩放，不改变真实外观。

## 设计预览边界

`index.html` 是工作室版式和状态示意，不连接真实 Agent/API。画面使用仓库原有短发角色的真实 idle/walk PNG 作为比例参照，不将其称为企鹅帽或新自定义作品；原 PNG 仅原字节复制，来源在 `assets/SOURCES.md`。参考图本地选择后仅通过 Object URL 在此页面显示；不上传，不持久保存。示意按钮不能代表后端验证或实际保存，导入检查/应用状态由页外评审工具显式切换。

用户提供的企鹅帽 JPG 已实际查看，只作轮廓/身份参考；不复制进仓库、不作为公开默认形象、不作为大家共同样例。最终用户参考角色的制作由其本地 AI 执行。工程可导入样例由 B 另交，不能混同此版式参照。

## 与 A / TD 已冻结的唯一协议对齐

TD 2026-10-25 直接确认采用 A 的 v1 字段；`manifest.template.json` 原样使用此协议。`version:1` 表示格式版本，不是上传次数；`type:'trisavia-avatar-strips'`；`frame.width/height=96/64`，`frame.foot={x:48,y:39}`；`facing={default:'right',left:'mirror-about-foot',vertical:'keep-last-horizontal'}`。动作条目是 `{file,frames,frameMs}`，不另存 fps，播放速率由 `1000/frameMs` 派生。

必需 idle/walk 如上。可选 `work.png` / `rest.png` 均为 1–16 帧、每帧 100–1000ms，单行宽度为 frames×96。1 帧可以表达真实静止工作/休息姿态，但不可声称有动态动画；必需 walk 仍必须 8 帧真实运动。`fallback:{work:'idle',rest:'idle'}` 固定存在，未完成可选素材直接省略 clip 和文件，不能复制 idle 假冒完成。

HTTP 上传 body 的 `files` 数组独立于 manifest，按同名 PNG 对应；具体编码/权限/配额/端点由 A 的实现合同与 B 的官方指南维护，本设计不发明第二协议。公开形象引用为 `{kind:'custom',assetId,version:1,digest,manifestUrl}`，`assetId+digest` 标识成品版本；资源文档为 `{version:1,manifest,files:[{name,url,sha256,bytes,width,height}]}`，digest 为该 canonical 资源文档的稳定 SHA。世界/个人管理/公开资料消费这一份引用。

本目录 manifest 只是模板，未附可上传自定义 PNG，不能把设计参照图伪装成合格自定义包；合法工程样例归 B。`generation-prompt.txt` 为用户自有工具的完整制作与修正指令，无服务端 AI 接入。
