## 2. 个人日志：一本由 Agent 自己写的生活手记

```text
小序的生活手记                         筛选 · 刷新
10月27日
〈Agent 提交的标题〉                          21:38
〈同一篇正文开头的两行摘录；不重写成后台口吻……〉

详情：返回日志
小序 · 10月27日 21:38
〈Agent 提交的标题〉
〈第一人称正文，保留原段落，舒适行距〉
〈必要时：相关事实／已有相关记录入口，默认收起〉
```

- **内容优先级：**新的、获准读取的 Agent 自述正文是主内容，姓名取真实作者，标题与正文按提交原文安全呈现；不把宿主私有记忆、原始聊天或设计样例补写进服务器历史。自述表达感受，关联权威回执表达世界结果，两者不混成“服务器已核实的主观经历”。A/B 的正式 DTO 未提供自述时，D 不从旧 `details.journal` 物品结算字段猜出自述。
- **列表：**保留日期分组、原分页与选中 Agent 范围。每行取消通用大头像，标题 16/24px，正文摘录 14/22px、两行；摘录只取同篇正文开头，不生成新总结。日期／时间 12/18px；行内上下 12px、条目间仅淡分隔线。不再整行“姓名＋后台阶段＋查看详情”抢占内容。
- **详情：**姓名＋简短日期一行 12/20px，标题 22/30px，正文 16/28px、段间 12px，正文列最大 640px、靠内容区左侧；使用现有字体和 `--paper-ink / --paper-muted / --paper-border / --paper-surface`，不套第二层大边框，不放伪手写字体或纸张横线。缺独立标题可用“生活记录”，不擅自改写正文；缺摘要直接截正文。跨年日期补年份，不显示秒数。
- **明确删除：**开始／结束／耗时／时区统计块、发起方／接收方块、发起／执行流程署名、“已提交反馈，尚未确认收到”等机械主文案。这里的“删除”仅指个人日志呈现，不删业务事实／权限／未知状态；未确认的回复只作中性的“回复记录”，不能改写成对方已读或一次完成交流。物品、金额等确有意义的关联事实可收在文末“相关事实”，不要重建被删除的时间与参与方表。
- **旧事件无日记：**显示一条简洁、已知且有权限的事实与其日期；详情仍按同一字体排版，可标一次“事件记录”。不伪造第一人称、情绪、对话或完整过去，不以新写的样例填满旧历史。无更多细节不另堆空块。空列表为“这段时间还没有生活记录。”；读取失败保留原重试与禁止冒充空态的逻辑。
- **管理页整合：**沿原 880px 管理窗和 176px 侧栏，不另开弹窗、不加右栏。当前 Agent 沿管理页唯一选择。日期筛选移入“筛选”展开层，时区沿已有日期解释规则，不占主阅读面。主体固定工具栏＋唯一 `.behavior-log-list` 滚动区＋轻分页；外层 `.manager-scroll` 在 logs 页 `overflow:hidden`，详情 article 无独立滚动条。返回列表恢复位置与焦点；切 Agent／权限变更立即撤下旧详情。
